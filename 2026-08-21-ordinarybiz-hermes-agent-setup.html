Oh My Hermes 사용법: Hermes Agent 메모리·스킬·모델 라우팅 전부 딸깍!

01핵심 개요

항목내용
형식평범한 사업가 채널의 대담(2부 중 관련 회차). 진행자와 사이오닉 AI(Psyonic AI)의 김희망(닉네임 K Hope, 직함 '울트라띵크 엔지니어')이 오픈소스 프로젝트 '오마이 에르메스(Oh My Hermes)'를 주제로 대화한다.
화자김희망(K Hope, 사이오닉 AI 개발자, 오마이 에르메스 제작자), 평범한 사업가 진행자
핵심 문제의식헬메스(에르메스) 에이전트는 셀프 이볼빙(self-evolving) 철학의 퍼스널 AI 에이전트이지만 메모리 훼손·리콜 재현율 저하 등 장기 기억 관리에 약점이 있고, 스킬·플러그인이 난립해 사용자가 무엇을 써야 할지 판단하기 어렵다는 진단에서 출발.
핵심 내용'오마이 에르메스'는 에르메스 에이전트를 설치만 하면 메모리 시스템 강화, 스킬 자동 라우팅, 도메인 스페셜리스트 지식, 코딩 오케스트레이션/모델 라우팅 추천을 한 번에 제공하는 래퍼(플러그인)다. 철학은 "Anyone can use Hermes agent professionally".
실증 지표대담 시점(8월 3일 기준) 저장소 스타 약 470개. 첫 접촉 당시 스타 약 30개에서 4~5일 만에 하루 100개씩 증가해 급성장.
개발 배경제작자는 오마이 코덱스·오마이 클로드 코드·오마이 오픈 에이전트(레이지 코덱스 제작자 '연규'와 사무실 옆자리) 등 '오마이(OM) 시리즈'의 철학(설치만 하면 알아서 똑똑해짐)과 울트라워크·딥 인터뷰 같은 코딩 오케스트레이션 개념을 참고해 에르메스 전용으로 확장했다.

02핵심 기능/내용 구조

  1. 오마이 에르메스의 철학과 포지셔닝: "누구든 에르메스 에이전트를 프로페셔널하게 쓸 수 있게 한다"는 문장으로 요약. 코딩 오케스트레이션, MoE(Mixture of Experts) 방식 활용, 루프 엔지니어링 지원 등 기능이 방대해 "그냥 깔면 좋아진다(파워 인텔리전스)"로 설명된다. 오마이 코덱스·오마이 클로드 코드 같은 코딩 에이전트용 하네스와 달리, 에르메스는 코딩 특화가 아닌 퍼스널 에이전트라는 점에서 결이 다르다.
  2. 메모리 계층 구조(L0~L3): 에르메스 에이전트 자체는 L0~L2까지 지원하며, 오마이 에르메스는 특히 L2의 '품질'을 강화하는 데 집중한다.

- L0: soul.md 파일 — 에르메스의 말투·정체성·역할을 정의하는 자기 정체성 레이어. - L1: memory.md 파일 — 프로젝트 스펙 등 기본 기조 정보를 담는 간단한 기억 창구. - L2: SQLite·파일시스템(마크다운)에 라벨링된 데이터를 별도 저장해두고, 세션이 전체를 항상 로딩하지 않고 필요할 때만 찾아가 조회하는 연속성 저장소. - L3: 세션 단위를 넘어선 에르메스의 전체 생명주기 관리 레이어. 다른 세션도 침범(공유)할 수 있는 더 큰 단위.

  1. 메모리 라벨링 4유형: 리콜(recall) 재현율을 높이기 위해 기억을 유형별로 라벨링하고 블록 단위로 관리·서치 가능하게 한다.

- 팩트·디시전(Fact & Decision): 변하지 않는 사실과 결정+이유. 예 — "레포지토리는 파이썬 3.11+ 대상", "인증 방식은 세션 쿠키로 가고 JWT는 폐기". - 리즌(Reason, 교훈): 실패에서 얻은 교훈. 예 — "마이그레이션은 인덱스를 먼저 만들어야 안 죽는다". - 프로시저(Procedure): 재현 가능한 절차. 예 — 워크플로우/스킬 계약이 변경됐을 때 어떤 기준으로 유닛 테스트를 통과시킬지. - 에피소드(Episode): 특정 사건의 인과관계. 예 — "8월 1일 배포 후 롤백해 오류가 발생했다"는 사건 맥락. - 여기에 TTL(Time To Live) 개념도 적용해, 계약이 끝나 더 이상 유효하지 않은 협력사 관련 기억 등을 자동 만료시킬 수 있다.

  1. 메모리 관리 스킬 — 드리밍(Dreaming)·프루닝(Pruning)·싱크(Sync): 드리밍은 컴팩션 발생, 세션 종료, 또는 N번의 대화 완료 시점마다 주기적으로 기억을 정리해주는 스킬(사람이 자는 동안 정보가 정리되는 것에 비유). 프루닝은 에이전트가 현재 기억하고 있는 내용(예: "이 프로젝트는 파이썬으로 개발 중이고 유저도 파이썬을 선호하는 것으로 기억합니다, 맞습니까?")을 사용자에게 되물어 확인·수정·삭제하게 하는 스킬. 셀프 이볼빙은 유저의 인지 부하를 줄이지만 잘못된 데이터를 기억하면 생산성에 큰 타격을 줄 수 있어, 이런 확인 질문 루프가 필수라고 강조.
  2. 스킬 생태계와의 공생 전략: 오마이 에르메스는 에르메스 에이전트 자체 내장 스킬을 대체하지 않고, 필요할 때만 오마이 에르메스가 정의한 확장 스킬로 넘어가는 '어댑티브' 구조를 지향한다. 또한 오마이 클로드 코드·오마이 오픈 에이전트 사용자를 위해, 에르메스가 그쪽 스킬셋을 인지한 프롬프트를 만들어 코딩 위임 시 활용하도록 설계했다. 스킬은 캐퍼빌리티 스킬(기술적, 모델이 강해지면 유효기간이 짧아짐)과 프리퍼런스 스킬(조직·개인 맥락 결합, 유효기간이 김) 두 종류로 구분되며, 제작자는 에르메스의 강점이 프리퍼런스 스킬의 유연성에 있다고 본다.
  3. 모델 라우팅과 믹스처 오브 에이전트(MoA): 오마이 오픈 에이전트의 믹스처 오브 모델 개념에서 영감을 받았다. 설치 시 자동 구축되는 게 아니라, 인터뷰 프로세스에서 사용자가 쓰는 모델을 파악해 세팅을 추천한다(헤비 유저는 GPT-5.1이나 페이블을 메인 브레인으로, 라이트 유저는 소넷/하이쿠 등 하위 모델도 활용). 각 모델의 강점(클로드=비주얼/프론트엔드, GLM=단순 코드, GPT-5.1=고난도 추론)을 라벨링해두고 AI가 스스로 라우팅 판단을 내리게 한다. 여러 모델을 동시에 돌려 최고 결과를 선출하는 방식은 비용 낭비로 보고 채택하지 않았으며, 실험을 통해 검증된 '리더' 모델을 미리 선출해 프롬프팅으로 고정하는 방식을 쓴다.
  4. 코딩 위임 방식(ACP 유사): 에르메스 에이전트 세션 내에서 모델(뇌)을 바꿔 끼우는 것이 아니라, 클로드 코드·코덱스 등 완전히 별도의 외부 세션을 파괴(생성)한 뒤 프롬프트를 주입(프롬프트 피드, prompt feed)해 작업을 위임하는 방식이다. 제작자는 오마이 클로드 코드의 스킬셋을 읽은 뒤 서브 에이전트에게 웹서치·기능A·기능B·기능C 등을 병렬 분할해 울트라워크로 처리하도록 프롬프팅한다. 이 방식의 단점은 옵저버빌리티(observability) 저하이며, 이를 보완하기 위해 브리핑 스킬셋과 로컬 대시보드를 별도로 세팅해둔다고 설명한다.
  5. 무한 루프 방지 설계: 추론을 깊게 하는 모델(예: GPT-5.1)이 검증 루프에 반복 진입해 5분이면 끝날 작업이 30~40분 걸리는 문제가 있어, 오케스트레이션을 맡는 메인 브레인이 "루프를 끝내는 명확한 기준점"을 미리 설정하도록 설계했다고 밝힌다.

03기술적 맥락

오마이 에르메스는 헬메스(Hermes) 에이전트 위에 얹는 오픈소스 플러그인/래퍼로, 제작자가 이미 만든 오마이 코덱스·오마이 클로드 코드·오마이 오픈 에이전트('OM 시리즈')의 철학(설치만 하면 자동으로 지능이 강화됨)을 계승했다. 코딩 에이전트(클로드 코드·코덱스)와 퍼스널 에이전트(에르메스)는 사용 맥락이 다르다는 전제 하에, 코딩 오케스트레이션·모델 라우팅 개념만 차용하고 메모리 시스템은 별도로 설계했다. 모델 라우팅은 YAML 파일 기반 설정(에르메스 에이전트 자체 기능)과, 오마이 에르메스가 제공하는 '추천 스킬'(어떤 작업에 어떤 모델을 쓸지 컨피그 파일에 권장안을 제시) 두 층위로 나뉜다. 대시보드/데스크탑 앱 등 GUI는 에르메스 본체가 이미 잘 만들고 있어 오마이 에르메스가 손대지 않는 영역으로 구분한다.

04전략적 의미

첫째, 정보 과잉 시대에 "AI를 잘 쓰는 법을 사람에게 배우기보다 AI에게 세팅을 맡기는" 흐름(제작자 표현으로 '대딸깍 시대')이 하네스 엔지니어링의 다음 트렌드로 제시된다. 툴이 매일 업데이트되는 상황에서 사용자는 도구 학습이 아니라 자신의 도메인에 어떻게 활용할지에 집중해야 한다는 주장이다. 둘째, 캐퍼빌리티 스킬(기술적)은 모델이 강해지면 자동 소멸하지만 프리퍼런스 스킬(조직·개인 맥락)은 유효기간이 길다는 구분은, AI 에이전트 도구 투자 우선순위를 정하는 데 실질적 기준이 된다 — 조직 워크플로우를 스캔해 스킬로 변환하는 기능이 장기적으로 더 방어력 있는 자산이라는 뜻. 셋째, 플러그인 생태계를 대체하지 않고 "단일 진입점(single point)"으로 흡수해 공생하는 전략은, 오픈소스 확장성이 큰 생태계에서 개인/소규모 팀이 취할 수 있는 현실적인 포지셔닝 모델을 보여준다. 넷째, 메모리 셀프 이볼빙의 양날의 검(잘못된 기억이 누적되면 생산성에 타격) 문제를 프루닝 질문 루프로 해결하려는 접근은, 자율 학습형 에이전트를 실무에 도입할 때 반드시 갖춰야 할 안전장치로 시사하는 바가 크다.

05핵심 워크플로우 또는 비교표

코딩 위임세션 내 모델(뇌) 교체 아님클로드/코덱스 등 별도 외부 세션을 생성해 프롬프트 주입(ACP 유사)
최종 결정사용자가 직접 YAML 수정유저 인터뷰로 헤비/라이트 유저 파악 후 세팅 추천만 제공

06활용 시나리오

  1. 에르메스 에이전트를 이미 쓰고 있지만 메모리 관리가 번거로운 사용자: 잘못 기억된 선호도나 오래된 프로젝트 맥락을 방치해 생산성이 떨어지는 경우, 오마이 에르메스의 드리밍·프루닝 스킬을 설치해 주기적으로 기억을 재확인·정리하는 루틴을 자동화할 수 있다.
  2. 여러 LLM(클로드, GPT, GLM, 키미 등)을 병행 사용하는 개발자: 작업 성격(비주얼=클로드, 단순 코드=GLM, 고난도 추론=GPT-5.1)에 따라 어떤 모델에 위임할지 매번 판단하기 번거로울 때, 오마이 에르메스의 모델별 라벨링·추천 스킬을 참고해 라우팅 기준을 세울 수 있다.
  3. 비개발자·바이브 코더가 스페셜리스트 수준의 워크플로우를 구축하고 싶을 때: 도메인 스페셜리스트(재무·마케팅·세일즈 등) 배경지식이 내장돼 있어, 코딩 맥락이 없는 사용자도 회사 워크플로우를 빠르게 학습시킨 에이전트를 구성할 수 있다.
  4. 다수의 서브 에이전트를 병렬로 오케스트레이션해야 하는 대규모 작업: 기능 A/B/C를 독립적인 코덱스·클로드 세션으로 나눠 울트라워크로 병렬 처리하고 싶을 때, 오마이 에르메스가 제공하는 브리핑 스킬셋과 로컬 대시보드로 옵저버빌리티를 확보하며 위임할 수 있다.

07현황 및 전망

대담 시점 기준 오마이 에르메스 저장소는 8월 3일 기준 스타 약 470개로, 첫 접촉 당시(약 30개)에서 4~5일 만에 하루 100개씩 증가하는 급성장세를 보였다고 언급된다. 제작자는 프로젝트가 오마이 오픈 에이전트·오마이 클로드 코드 대비 상대적으로 신생이라 아직 완성도가 100%는 아니라고 인정하며, 향후 로드맵으로 (1) 자동 업데이트 기능 추가(현재는 ohm update 명령으로 커밋 단위 수동 업데이트만 지원), (2) 헤비/라이트 유저를 4단계로 세분화해 맞춤 추천 패키지를 제공하는 기능, (3) 에르메스 에이전트 생태계의 '대표 플러그인'이 되는 것을 목표로 제시한다. 장기적으로는 사이오닉 AI가 다루는 AI 활용 문제 전반으로 확장할 계획이며, 채용도 열려 있다고 밝힌다. 제작자는 모델이 충분히 강력해지면 하네스 엔지니어링 자체의 의미가 옅어질 수 있다는 견해도 덧붙이며, 그 경우에도 프리퍼런스 스킬(조직·개인 맥락)의 가치는 유지될 것으로 전망한다.

08용어 사전

용어한줄설명비유/예시
오마이 에르메스(Oh My Hermes)헬메스(Hermes) AI 에이전트에 메모리·스킬·모델 라우팅 기능을 강화해주는 오픈소스 플러그인설치만 하면 에르메스가 더 똑똑해지는 '파워 인텔리전스' 패키지
셀프 이볼빙(Self-Evolving)에이전트가 스스로 학습·기억을 개선해 나가는 방식에르메스 에이전트의 핵심 모토
메모리 레이어 L0~L3기억을 정체성(L0)→기본정보(L1)→라벨링 저장소(L2)→세션 생명주기(L3) 순으로 계층화한 구조soul.md(L0), memory.md(L1), SQLite/md(L2), 세션 관리(L3)
드리밍(Dreaming)세션 종료·컴팩션·N회 대화 후 주기적으로 기억을 자동 정리하는 스킬사람이 잠들며 기억을 정리하는 것에 비유
프루닝(Pruning)에이전트가 기억 내용을 사용자에게 되물어 확인·수정·삭제하는 스킬"이 프로젝트는 파이썬 기반으로 기억하고 있습니다, 맞습니까?"
팩트·디시전(Fact & Decision)변하지 않는 사실과, 그 사실에 근거한 결정+이유를 기록하는 메모리 유형"인증 방식은 세션 쿠키, JWT는 폐기"
에피소드(Episode)특정 사건의 인과관계를 기록하는 메모리 유형"8월 1일 배포 후 롤백으로 오류 발생"
TTL(Time To Live)특정 시점 이후 자동 만료되는 기억의 유효기간 설정계약 종료일이 지나면 협력사 관련 맥락을 자동 삭제
캐퍼빌리티 스킬 vs 프리퍼런스 스킬전자는 기술적 스킬(모델 발전 시 유효기간 짧음), 후자는 조직·개인 맥락 스킬(유효기간 김)리액트 기능 사용법(캐퍼빌리티) vs 사내 코드리뷰 워크플로우(프리퍼런스)
믹스처 오브 에이전트(MoA) / 믹스처 오브 모델여러 LLM을 역할별로 나눠 오케스트레이션하는 방식메인 오케스트레이터는 페이블, 세부 작업은 GPT/그록에 위임
ACP(Agent Control Protocol) 방식한 에이전트가 다른 CLI 도구(클로드 코드, 코덱스 등)를 외부에서 제어·위임하는 방식에르메스가 클로드 코드 세션을 생성해 프롬프트를 주입
옵저버빌리티(Observability)여러 서브 에이전트가 병렬로 작업할 때 진행 상황을 파악할 수 있는 가시성로컬 대시보드로 병렬 작업 상태를 모니터링
