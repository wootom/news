02창업 과정

  • 창업자 이승재 = 서울대 화학생물공학부, 첫 창업은 태양광 압축 쓰레기통(이큐브랩)
  • 계기 = 사무실 인테리어 직접 하며 겪은 어려움 + 이케아·지인 집 경험
  • 2014.7 법인 설립, 시작은 '오늘의 인테리어' 페이스북 채널(2015년 '오늘의집' 개명)
  • 초기 콘텐츠 = 온라인 사진 수집 → 전문가 사례 → '일반인 사례'로 전환(공감 반응)
  • 성장 유인책 = 사진 속 제품에 정보 붙이는 '태그 기능'

03커머스 전환과 재무

지표내용
테스트 판매이틀 만에 1천만 원↑

  • 손익: 장기 적자 → 2024년 첫 흑자(영업익 5.8억, 창업 10년 만) → 2025년 다시 147억 손실
  • 2025 적자 원인 = 자회사·해외법인 6곳에 약 495억 투입, 전부 적자(지분법 손실 3년 연속 증가)
  • 체력 = 현금성 자산 2,400억↑, 외부 차입금 0(적자지만 무차입)

04기술적 맥락 — 레일즈와 기술부채

  • 서비스 전체가 루비온레일즈 단일 애플리케이션(콘텐츠·커머스·시공·프론트 한 덩어리)
  • 이유 = MVP 관점 초고속 개발·실험 우선, "부채는 나중에 탁월한 개발자가 해결" 신념
  • 2021년 모놀리식 5대 문제 = 장애 전파, 부분 확장 난, 수정 난, 영향범위 불명, 배포 지연, 언어 종속
  • 2021년 9~12월 = 신규 개발 전면 중단, 전 개발자 구조 개편 투입(목표 트래픽 10배)

05핵심 방법론 — MSA 전환의 진짜 교훈

  • 전환 예상 3~5년(2021.11 시작), 프론트 리액트 이전만 수년 소요
  • 고통 사례 = 루비 세션(마샬 포맷)을 Go로 직접 구현(원문에 우는 이모지)
  • 진짜 문제 = 프레임워크가 아닌 '도메인 경계 미분리' → 무엇으로 만들었나보다 안에서 나뉘었나가 난도 결정
  • 레일즈 제거 이유 3가지 = ① 여러 언어 혼용으로 장점 퇴색 ② 익숙지 않은 개발자 실수 ③ 한국 시니어 레일즈 채용난 → 모두 '사람 문제', 기술 부족 아님

06현황 시나리오

  1. 2026.8 현재도 레일즈 사용 중(기술스택 페이지·채용공고·깃허브 포크 3건 확인)
  2. MSA '페이지2' 완료 보고 없음 → 2024년 쪼갠 서비스 재통합 층 '슈퍼루트' 구축(쪼개면 합칠 일 생김)
  3. 시공 사업 = 2023년 "중계자일 뿐" → 2025~2026 직접 시공·1년 하자보증(입장 완전 전환)

07전망 — AI 네이티브 전환

  • 오늘의집 = 스스로 'AI 네이티브 조직' 선언, 사내 에이전트 '오집사' 운영
  • 효과 = 고객문의 답변 4분→20초, 대시보드 쿼리 이틀→15분, 사내 AI 사용량 1.5년 만에 4배
  • 함의 = 2022년 "레일즈 개발자 채용난"이라는 전환 이유가 AI 코딩 도구로 흔들림 → 기술 결정의 전제가 얼마나 오래 갈 조건인지 점검 필요
