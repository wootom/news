DeskRPG는 Hermes 에이전트를 3D 오피스에서 회의·칸반·업무로 운영하는 오픈소스 플랫폼이다.

Hermes 에이전트를 3D 오피스에서 회의·칸반·크론으로 운영하는 DeskRPG 설치와 활용법.

01핵심 개요

  • 단테랩스의 DeskRPG는 Hermes 에이전트 프로필을 3D NPC로 연결해 가상 오피스에서 관리하는 오픈소스 프로젝트다.
  • Hermes의 칸반·크론·기억·일정 데이터를 DeskRPG에 연동하며, 카드 변경은 양쪽에 동기화되도록 구현했다.
  • 로컬에서는 npx deskrpg init과 npx deskrpg start로 실행할 수 있으며, 서버 운영에는 24시간 VPS 사용을 제안했다.
  • 회의 기능은 참여자·최대 턴수·수동·자동 진행을 설정하고, 회의 결론을 후속 칸반 카드로 등록할 수 있다.
  • 영상은 멀티 에이전트가 병렬 작업에는 유리하지만 순차 작업에서는 성능이 저하될 수 있다고 설명한다.

02핵심 주장 / 논점 구조

  • 영상은 이름과 역할을 가진 프로필 중심의 도구를 ‘AI 팀메이트 플랫폼’으로 정의하며, 세션·작업 중심 코딩 에이전트와 구분한다.
  • 코딩 에이전트는 세션을 다시 열어 맥락을 관리하는 반면, 팀메이트 방식은 같은 프로필에게 다시 말해 연속성을 이용한다.
  • 반복 업무, 여러 사람이 쓰는 운영 업무, 리서치·초안·검수처럼 역할별 후속 확인이 필요한 일에 팀메이트 방식이 적합하다고 제시한다.
  • 에이전트를 많이 두는 것보다 권한·비용·삭제·배포 승인·최종 검토의 경계를 설계하는 일이 중요하다고 강조한다.

03AI 팀메이트와 멀티 에이전트 동향

  • 영상은 2월 Anthropic의 Agent Teams, 3월 Asana의 AI Teammates, 7월 Block의 Buzz를 관련 흐름으로 언급한다.
  • 8월에는 xAI의 Grokbot과 Hermes Agent의 본 모드가 출시됐으며, 공통 방향은 에이전트를 팀원처럼 활용하는 것이라고 설명한다.
  • Anthropic 자료에서 일반 채팅의 통째 위임 비율은 작년 8월 49%에서 11월 45%로 낮아졌고, Claude Code에서는 79%까지 나타났다고 소개한다.
  • GitHub의 에이전트 오케스트레이션 신규 레포는 2024년 94개, 2025년 1,762개, 올해 9월까지 11,537개라고 영상은 제시한다.

04분업 구조와 위임 위험 관리

  • Cognition은 여러 에이전트가 같은 내용을 동시에 수정하면 충돌과 병목이 생길 수 있다고 했으며, 읽기는 분담하고 쓰기는 한 에이전트가 맡는 구조를 제시했다.
  • 검토 에이전트에는 앞선 작업 맥락을 과도하게 주지 않아야 독립적으로 문제를 찾고 인지동화를 줄일 수 있다고 설명한다.
  • Google 연구팀의 260개 멀티 에이전트 구성 실험에서 병렬 작업은 최대 81% 향상, 순차 작업은 최대 70% 저하됐다고 소개한다.
  • 영상은 Replit의 프로덕션 DB 삭제, Cursor의 백업 포함 데이터 삭제, 하루 AWS 비용 약 900만 원 사례를 권한 설정 부재의 위험으로 언급한다.

05DeskRPG와 Hermes의 연동 구조

  • DeskRPG는 AI 엔진이 아니라 Hermes를 보여주고 조작하는 3D 가상 오피스 인터페이스이며, 기존 Hermes 프로필이 NPC 캐릭터가 된다.
  • 터미널에서 만든 Hermes 칸반 카드는 오피스 게시판에 나타나고, 오피스에서 수정한 카드도 Hermes 쪽에 동기화된다.
  • 기억, 칸반 카드, 일정 기록은 Hermes에 저장되므로 DeskRPG를 다시 설치해도 Hermes 기록은 유지된다고 설명한다.
  • 같은 서버의 컨테이너 환경에서는 컨테이너를 지우더라도 Hermes 기록 보존을 위해 볼륨을 남겨야 한다고 안내한다.

06로컬 실행과 Hostinger VPS 배포 절차

  • 로컬 실행은 터미널에서 npx deskrpg init을 입력한 뒤 npx deskrpg start로 시작하며, 브라우저에서 localhost:3000에 접속한다.
  • 노트북이 잠들거나 꺼지면 크론 작업도 멈추므로, 지속 실행이 필요한 비서형 에이전트에는 24시간 서버가 필요하다고 설명한다.
  • 영상은 Hostinger VPS의 KVM 2를 기준으로 CPU 2코어·RAM 8GB를 Hermes 최소 사양으로 안내하고, Docker Manager에서 compose URL로 배포한다.
  • 환경 변수에는 HERMES_API_KEY, TRAEFIK_HOST, HERMES_DASHBOARD_PASSWORD를 설정하며, 방화벽에서는 TCP 22·80·443 포트를 허용한다.

073D 오피스의 회의·칸반·결과물 운영

  • 사용자는 캐릭터와 자기 정보를 만들고, Noah·Oliver 같은 Hermes 프로필에 페르소나·외형·AI 모델을 설정해 직원으로 등록한다.
  • 오피스는 빌트인 5개 3D 맵 중 선택해 만들 수 있으며, NPC 인접 채팅·호출·그룹 채팅과 인간 동료 초대 기능을 제공한다.
  • 회의실에서는 참여자, 최대 턴수, 수동·자동 진행을 정하고 회의를 시작하며, 영상 예시에서는 최대 5턴으로 뉴스레터 주제를 논의했다.
  • 회의 결론은 후속 업무 카드로 등록되며, 카드 상태·선후행 작업·실행 로그를 확인하고 결과물 메뉴에서 마크다운·이미지·링크 등을 모아 볼 수 있다.

08용어 사전

용어뜻
AI 팀메이트 플랫폼세션보다 이름·역할·성격·도구·일정이 연결된 프로필을 중심으로 에이전트를 운영하는 도구 범주다.
Hermes Agent서버에 직접 설치해 기억, 일정, 도구 사용과 작업 수행을 지원하며 DeskRPG의 AI 엔진으로 연결되는 오픈소스 에이전트다.
DeskRPGHermes 프로필을 3D NPC와 가상 오피스로 표현하고 채팅, 회의, 칸반, 크론, 결과물 관리를 제공하는 프로젝트다.
칸반업무 카드를 상태별로 관리하는 보드이며, DeskRPG와 Hermes 사이에서 카드 생성·수정 상태가 동기화된다.
크론정해진 시간에 반복 업무를 실행하도록 관리하는 스케줄 기능으로, 컴퓨터가 꺼져 있으면 실행되지 않을 수 있다.
TraefikVPS에서 DeskRPG에 HTTPS 도메인 접근 경로를 만들기 위해 함께 배포하는 컨테이너 서비스다.
