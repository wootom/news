행동형 AI 에이전트는 유저별 격리와 비밀 관리, 외부 행동 승인 관문으로 운영해야 한다

유저별 셀 격리, 비밀 금고, 전용 브라우저와 승인 관문으로 에이전트 서비스를 설계한다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

외부 행동이 남기는 흔적과 에이전트의 7개 설계 영역

  • 영상은 한 행동형 AI 비서가 유저에게 묻지 않고 식당에 전화하고, 이틀 뒤 같은 호텔에 두 번 더 전화한 사례로 시작한다. AI라고 밝히지 않은 일로 대표가 공개 사과했다고 설명한다.
  • 발표자가 운영하는 플랫폼은 문자 요청을 받아 글과 이미지를 만들고, 미리보기를 보낸 뒤 승인되면 Instagram, Threads, X에 게시한다.
  • 에이전트 설계 영역을 입력, 격리 단위, 생각, 실행, 바깥 행동 통제, 기억, 먼저 움직이기의 7칸으로 나눈다. 데모에서는 생각과 실행이 보이지만 서비스 사고는 나머지 영역에서 생긴다고 말한다.

테넌트 대신 유저별 Durable Object 셀로 격리

  • 큰 데이터베이스에 모든 유저의 행을 넣는 테넌트 방식은 조회 조건이 빠지면 데이터가 섞이고, 데이터베이스 장애나 무거운 유저의 부하가 전체에 영향을 줄 수 있다고 설명한다.
  • 발표자는 유저마다 Cloudflare Durable Object 셀을 하나씩 두고, 유저 아이디로 해당 셀을 부른다. 셀마다 SQLite 저장소가 있으며 요청은 한 번에 하나씩 처리된다.
  • 문자가 오면 공용 색인에서 행을 찾고, 나머지 작업은 해당 셀 안에서 처리한다. 일이 없는 셀은 잠들어 비용이 들지 않으며, 가상 머신의 격리 성질 중 필요한 부분만 취한 구조라고 설명한다.

모델에 진짜 비밀을 노출하지 않는 금고 구조

  • 에이전트는 SNS 토큰과 비밀번호, 이중 인증 시드 등을 다루므로 모델이 비밀을 볼 경우 게시물이나 DM의 지시문, 로그와 에러 트레이스를 통해 노출될 수 있다고 짚는다.
  • 에이전트에는 대리 토큰만 주고, 진짜 비밀은 공개 주소가 없는 별도 워커 안에서만 푼다. 요청이 외부로 나가는 경계에서 대리 토큰을 진짜 토큰으로 바꿔 붙인다.
  • 비밀은 봉투 암호화로 저장하며 유저별 데이터 키를 마스터 키로 감싼다. 금고를 부를 수 있는 워커는 두 개로 제한하고, CI가 설정을 검사한다.

유저별 Chrome 컨테이너와 사람의 로그인 개입

  • 공식 API로 처리할 수 없는 브라우저 작업과 로그인 세션 유지를 위해 유저마다 Chrome이 들어 있는 컨테이너를 둔다. 컨테이너의 실행과 종료는 Durable Object가 맡는다.
  • 10분 동안 작업이 없으면 스냅샷과 암호화 백업을 남기고 컨테이너를 끈다. 다시 작업이 생기면 백업에서 복원해 로그인 상태를 이어 가지만, 복원 지연 때문에 필요할 때만 켜는 옵션으로 둔다.
  • 첫 로그인이나 이중 인증처럼 에이전트가 처리할 수 없는 화면은 사람이 맡는다. 15분 동안 유효한 1회용 링크로 화면을 유저에게 넘기고, 모델에는 상태와 이유 코드만 전달한다.

외부에 닿는 쓰기를 검사하는 행동 관문

  • 조회와 초안 작성은 유저와 에이전트 사이에서 끝나지만, 게시·댓글·DM은 다른 사람에게 닿고 되돌릴 수 없다. 그래서 외부에 닿는 모든 쓰기를 하나의 관문으로 모은다.
  • 관문은 연락처나 링크 포함 여부, 중복 게시 여부 같은 코드 규칙을 먼저 검사한 뒤, 글을 작성한 모델과 분리된 심사 모델이 통과·보류·차단 중 하나로 판정한다.
  • 판정 결과는 게시물의 바이트에 묶인 토큰으로 발급된다. 글이 한 글자라도 바뀌면 토큰이 일치하지 않아 금고가 진짜 토큰을 내주지 않는다.
  • 에이전트가 먼저 시작한 게시에는 미리보기를 보내고 최대 24시간 동안 답을 기다린다. 유저가 직접 게시를 승인해야 나가며, 관문은 먼저 그림자 모드로 판정과 오탐률을 기록한 뒤 차단을 켠다.

셀 구조의 운영상 대가와 Cloudflare 의존성

  • 데이터가 유저별 셀로 흩어져 전체 고객을 한 번에 조회하기 어렵고, 셀마다 스키마 버전이 다를 수 있어 깨어날 때 부족한 마이그레이션 단계만 적용한다.
  • 스키마는 추가만 하고 삭제하지 않는 규칙을 둔다. 발표자는 같은 기능을 다른 클라우드에서 찾기 어렵고 플랫폼 장애가 모든 셀에 영향을 주는 점을 구조의 대가로 받아들였다고 말한다.

인프런 강의의 구성과 수강 전 확인 사항

  • 인프런 강의 「행동형 AI 에이전트 설계와 구축」은 12개 섹션, 85강, 21시간 34분 분량이다. 데이터 설계와 비밀 금고, Chrome 컨테이너, 게시 워크플로, 행동 관문, 보안 점검과 운영 배포를 다룬다.
  • 강의는 화면 녹화형 라이브 코딩이 아니라 설계 그림·설정·코드 발췌를 활용한 슬라이드 강의이며, 저장소 전체 코드는 제공하지 않는다. 나레이션은 발표자의 목소리를 학습한 AI 음성으로 제작했다고 밝힌다.
  • 중급 이상을 대상으로 하며 TypeScript 서버 코드를 읽고 쓸 수 있어야 한다. 완성본 데모와 첫 동작 확인을 포함한 5강은 무료 미리보기로 열려 있고, 영상에서는 블랙프롬프트데이 기간 11월 20일까지 25% 할인이 적용된다고 안내한다.

용어 사전

용어뜻
행동형 에이전트도구를 실행해 게시나 전화처럼 외부에 흔적을 남기는 에이전트로, 서비스 운영에는 실행 전 통제가 필요하다.
Durable Object영상에서 유저별 셀을 만들고, 셀 안의 요청과 Chrome 컨테이너 실행을 맡기는 Cloudflare 구성 요소다.
테넌트 방식하나의 데이터베이스에 여러 유저의 데이터를 두고 행마다 소유 유저를 표시하는 방식이다.
봉투 암호화유저별 데이터 키로 비밀을 보호하고, 그 데이터 키를 다시 마스터 키로 감싸 저장하는 방식이다.
바깥 행동 관문게시·댓글·DM 같은 외부 쓰기에 규칙 검사와 별도 모델 판정, 필요한 경우 유저 승인을 적용하는 경로다.
