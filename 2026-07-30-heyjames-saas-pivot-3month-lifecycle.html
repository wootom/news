SaaS 만들어 5번 피벗하고 번 돈 1000만원, 이제 수명은 3개월입니다 (헤이제임스)

'핑거'라는 단일 브랜드로 5번 이상 서비스를 피벗(프로젝트 관리 → HTML 프로토타이핑 → 앱빌더 → 영상제작 SaaS)하며 실제 결제 매출 약 1,000만 원을 만든 경험담. 내부 비용 절감으로 수천만 원을 아꼈지만, AI 발전 속도가 빨라지면서 SaaS 라이프사이클이 3~6개월에서 이제 1~3개월로 단축돼 지속적 개선 없이는 곧바로 도태된다는 교훈을 공유한다.

01핵심 개요

항목내용
브랜드핑거(Finger) — 5번+ 피벗한 단일 SaaS 브랜드
총 결제 매출약 1,000만 원(비용 절감분 수천만 원은 별도)
대표 피벗에이전시 내부툴 → 프리랜서 PM → HTML 프로토타이핑 → 앱빌더 → 영상제작
기술 스택Svelte+Vercel+Supabase → Ruby on Rails(수일 만에 제작)
핵심 교훈SaaS 수명 1~3개월, 방치 시 매출 즉시 하락

02핵심 내용 구조 — 하나의 브랜드, 다섯 번의 피벗

'핑거'는 원래 에이전시 내부용 견적·계약·DB모델링·PM 통합 도구였다. 외부 출시 시 기능을 간소화한 프리랜서 PM 툴로 전환했고, 이후 사용자가 실제로 쓰는 HTML 프로토타이핑 기능으로 좁혔다가, 앱빌더, 최종적으로 영상제작 SaaS까지 총 5번 이상 피벗했다. '딸각'(자동화·편리함)이라는 브랜드 이미지를 유지하기 위해 서비스만 갈아끼운 셈이다.

03기술적 맥락 — 바이브 코딩과 Ruby on Rails

초기에는 Svelte + Vercel 배포 + Supabase 백엔드로 만들었으나, Supabase의 마이그레이션·RLS 난이도와 CDC 불편함 때문에 비개발자 바이브 코딩에는 권하지 않게 됐다. Ruby on Rails로 전환한 뒤엔 Opus 3.5 수준부터 AI가 거의 온전히 맡겨도 될 만큼 잘 짜서 2~3일 만에 서비스를 완성했다.

04핵심 워크플로우 — 매출 발생 후 즉시 드라이브

오픈·홍보 직후 몇십만 원 결제가 일어났고 1~2개월 내 100만 원가량 매출이 났다. 그러나 에이전시 매출(수억 원)에 비해 얕잡아보고 방치하자 매출이 급격히 꺾였다. 매출이 발생하면 즉시 사용자 조사·피드백·재결제 장치를 빠르게 보완해야 유지되거나 성장하며, 그냥 두면 저절로 커지지도 유지되지도 않는다.

05활용 시나리오

프리랜서 PM 버전은 100만 원대 초기 결제를, HTML 빌더 버전은 부트캠프 B2B 단체 계약으로 수백만 원을, 영상제작 버전은 연결제·크레딧 구매로 또 수백만 원을 만들었다. 다만 지금은 Claude Code + 영상제작 스킬 조합이 핑거보다 낫다고 본인이 인정할 만큼 자체 도구가 AI 기본 조합에 추월당했다.

06현황 및 전망

경쟁자는 Claude Code·Codex 같은 범용 AI 도구 자체다. 어떤 스킬 조합이 내 SaaS보다 더 좋은 결과를 더 간편하게 내놓기 때문에, 사이클이 3~6개월도 아닌 1~3개월로 단축됐다. 계속 개선하거나 다음 SaaS를 연달아 출시해 전체 수익을 유지해야 하며, 100만 원 매출도 '더 파볼 가치가 있다는 증거'로 재평가해야 한다는 반성을 남긴다.
