비개발자를 위한 클로드 코드 6시간 완주 코스

title: 비개발자를 위한 클로드 코드 6시간 완주 코스

01핵심 개요

항목내용
채널Nate HerkAI Automation
소재비개발자를 위한 클로드 코드(Claude Code) 실전 6시간 강의
핵심코딩 지식 없이도 클로드 코드를 "AI 직원"처럼 관리해 지식노동·자동화 전반을 처리하는 방법론
결론모델보다 컨텍스트·스킬·서브에이전트 설계가 핵심이며, 사람은 결과물을 관리·검수하는 매니저 역할로 전환해야 함

02AI 네이티브 마인드셋 6대 스킬

  • AI 퍼슨 되기 — 하나의 AI 도구를 골라 실제 업무 ROI를 만들어 조직 내 "AI 담당자"로 포지셔닝
  • 테이스트(taste)와 판단력 — AI 산출물을 무비판적으로 신뢰하지 않고 검수·피드백 루프 유지
  • 컨텍스트 엔지니어링 — 프롬프트 엔지니어링보다 중요, AI에게 실제 업무 맥락(문서·데이터·과거 사례)을 지속 제공
  • 반복 속도(iteration speed) — 완벽한 계획보다 빠른 시제품 제작 후 개선, 단 "완료 기준"(북극성 지표) 사전 설정 필수
  • 자비스(Jarvis) 구축 — 사람이 매번 트리거하지 않고 스스로 작동하는 시스템, 단 워크플로우(결정론적)와 에이전트(비결정론적)를 구분해 선택
  • 자기만의 보험(복수 소득원) — 하나의 전문 분야를 여러 형태(강의·뉴스레터·컨설팅 등)로 확장해 리스크 분산

03클로드 코드 기본 구조

  • 3개 제품 계층 — 클로드 챗(대화형)·클로드 코워크(간단 자동화)·클로드 코드(가장 강력, 로컬 파일+온라인 도구 모두 접근)
  • AI 하니스 개념 — AI 모델(엔진)·하니스(자동차)·사용자(운전자)의 3중 구조로 이해
  • 설치 및 요금제 — Pro($20)/Max($100·$200) 구독 필요, 데스크톱 앱·VS Code 확장·터미널 등 어디서 써도 동일하게 작동
  • 토큰과 모델 비용 — 하이쿠(저가·고속)·소네트(균형)·오퍼스/페이블(고성능·고비용), 입력보다 출력 토큰이 더 비쌈
  • 프라이버시 — 소비자 플랜은 학습 데이터 옵트인 여부 설정 가능, 회사 민감정보 업로드 전 반드시 사내 정책 확인

04CLAUDE.md와 프로젝트 구조

  • CLAUDE.md — 매 대화 시작 전 자동으로 읽히는 시스템 프롬프트, 프로젝트 개요·라우팅맵·스타일 규칙을 자연어로 기술
  • 글로벌 vs 프로젝트 레벨 — 글로벌 CLAUDE.md는 모든 프로젝트에 적용(선호도·금지 표현 등), 프로젝트 레벨은 해당 폴더에서만 적용
  • .claude 폴더 — settings.json(권한 설정)·agents(서브에이전트)·skills(스킬) 세 가지가 핵심 구성요소
  • 피드백 루프 — 결과물에 대한 사람의 평가를 CLAUDE.md/스킬에 반영해 다음 실행부터 자동 개선

05도구 연결과 프롬프팅

  • API·ENV 파일 — API 키는 .env 파일에 저장(GitHub에 노출 안 됨), 서드파티 도구(Tavily 등)와 연결해 검색력 강화
  • Google Workspace CLI(GWS) — Gmail·Drive·Docs·Sheets·Slides·Calendar를 하나의 CLI로 통합 접근, 100여 개 사전 제작 레시피 내장
  • 커넥터 vs 수동 연결 — 데스크톱 앱 내장 커넥터는 편리하지만 하니스 종속적, .env 방식은 도구 불가지론적(tool-agnostic)이라 이식성 높음
  • 프롬프팅 4원칙 — 역할(role) 부여, 배경·구체적 맥락 제공, 네거티브 프롬프트(하지 말아야 할 것 명시), 검증(AI 스스로 결과를 증명하게 하기)
  • 권한 모드 — 오토모드·매뉴얼·플랜모드·바이패스 모드, 실제 안전장치는 프롬프트가 아니라 "도구 자체를 주지 않는" 툴 레이어 제한

06스킬과 서브에이전트

  • 스킬(Skill) — 재사용 가능한 SOP를 마크다운 파일로 패키징, YAML 프런트매터의 description으로 자동 호출(프로그레시브 디스클로저)
  • 스킬 제작 두 경로 — 사전 설계 후 요청하거나, 실제 작업을 먼저 수행한 뒤 "이 과정을 스킬로 만들어줘"로 역추출
  • 오픈소스 스킬 재사용 — GitHub 공개 저장소(예: superpowers 플러그인)의 마크다운 스킬을 그대로 가져와 사용 가능, 단 프롬프트 인젝션 검증 필요
  • 서브에이전트 — 메인 세션과 별도 컨텍스트 창을 가진 전문가 에이전트, 값싼 모델(하이쿠 등)에 위임해 비용 절감 및 메인 컨텍스트 오염 방지
  • 서브에이전트 활용 신호 — 대량 파일 읽기, 반복 작업, 병렬 독립 작업, 편향 없는 검토가 필요할 때 위임 / 단순 수정이나 순차 의존 작업은 위임 불필요
  • 컨텍스트 창 관리 — 100만 토큰 한도 내에서 약 25%(25만 토큰) 도달 시 세션 핸드오프 스킬로 요약 후 /clear로 초기화, "덤 존(context rot)" 방지

07웹사이트 빌드와 신뢰 가능한 자동화 설계

  • 웹사이트 5대 해킹 — CLAUDE.md 사전 설정, 프런트엔드 디자인 스킬 설치, 스크린샷 루프(AI가 직접 화면을 보고 반복 개선), 영감 사이트/컴포넌트 참조, 브랜드 자산(로고·가이드라인) 첨부
  • AI 시스템 피라미드 — 챗봇(사람이 트리거) → 워크플로우(결정론적 자동화) → AI 워크플로우(단계는 고정, 일부만 AI) → 에이전트(완전 비결정론적) 순으로 자율성·리스크·비용 증가
  • 신뢰 설계 원칙 — 프롬프트는 "제안"에 불과하므로 위험한 동작(삭제·발송 등)은 아예 툴 레이어에서 제거해 원천 차단
  • 이메일 트리아지 사례 — 순수 AI 에이전트보다 라우팅 규칙 기반 워크플로우로 재설계하니 실패율이 크게 감소(객관적 로직은 블루, 생성형 AI는 그린으로 구분)

08활용 시나리오

  • 지식노동 자동화 — Gmail/캘린더/ClickUp/Slack 등을 CLAUDE.md에 연결한 개인 "AI 운영체제"를 구축해 이메일 트리아지, 회의 브리핑, 리포트 생성을 자동화
  • 콘텐츠·마케팅 제작 — 브랜드 자산과 프런트엔드 디자인 스킬을 결합해 랜딩페이지·프레젠테이션·YouTube 분석 리포트를 몇 분 만에 산출
  • 사내 자동화 컨설팅 — 병목(constraint) 지점을 먼저 찾아 북극성 지표를 설정한 뒤, 필요 최소 수준(챗봇/워크플로우/에이전트)으로 자동화를 설계해 리스크와 비용을 통제

09용어 사전
