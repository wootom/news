앤트로픽 실험 결과, 에이전트 메모리는 예측과 드리밍으로 관리해야 한다

앤트로픽 실험으로 확인한 에이전트 메모리 최적화 및 드리밍 활용법

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

에이전트 메모리의 정의와 뇌 구조 비유

  • 앤트로픽은 모델 가중치 변경, 인컨텍스트 러닝, 컴팩션을 제외하고 세션 종료 후에도 유지되는 파일 저장 데이터를 에이전트 메모리로 정의한다.
  • 사람의 해마가 경험을 기록하고 수면 중 신피질로 전달하는 과정에 빗대어, 작업 중 로그를 쌓고 나중에 다시 훑어 정리하는 단계를 강조한다.
  • 메모리는 미래에 대한 예측으로, 특정 패턴이 재사용되거나 사실이 검증될 것이라고 가정하여 다음 세션의 토큰과 시간을 절약하는 수단이다.

CL 벤치마크를 통한 모델별 메모 작성 능력 비교

  • CL 벤치마크 1.0에서 소넷 4.6은 검증되지 않은 추측만 나열했으나, 오퍼스 4.7은 확인된 사실과 미확인 정보를 구분하기 시작했다.
  • 오퍼스 5는 채점된 답에 확인 표시와 정정을 남기며, 규칙-근거-함정 경고의 4단계 사이클을 처음으로 완주했다.
  • 오퍼스 5.5와 소넷 5.5도 동일한 방식으로 메모 고리를 닫아 지속 학습 성능을 향상시켰다.

포켓몬스터 레드 게임 실험: 기록량과 성과의 역관계

  • 소넷 3.7은 전투와 아이템마다 파일을 생성해 413개 파일을 만들었으나 배지는 1개만 획득하고 게임 진행에 시간을 낭비했다.
  • 페이블 5는 화면에 보이지 않는 전략과 직접 확인한 규칙만 9개 파일에 기록해 배지 4개를 획득했다.
  • 잉어킹 포획 실패 사례에서 볼 연속 실패 시 대기 입력을 넣는 규칙을 메모로 남기며, 화면 정보 대신 경험칙을 기록하는 것이 중요함을 입증했다.

프롬프트 지시 효과와 모델별 자율성 차이

  • 강한 모델인 오퍼스 4.7과 5에는 메모 폴더 존재만 알려주면 충분했으나, 실패 기록 지시를 주면 오히려 성능이 하락했다.
  • 약한 모델인 소넷 6은 메모를 읽지 않고 가설을 검증하지 않아, 읽기와 검증 지시를 주면 점수가 거의 2배로 올랐다.
  • 최신 모델에는 사용자가 기억하라고 하거나 가치가 있을 때만 메모하라는 간단한 지시만 주고 나머지는 모델 판단에 맡기는 것이 효과적이다.

드리밍(Dreaming)을 통한 메모 오류 수정 사례

  • 달마지산 동굴에서 포켓몬 센터 위치를 잘못 기억해 3회 낙하했으나, 드리밍으로 원본 대화 기록과 대조해 메모를 수정했다.
  • 수정된 메모를 기반으로 다시 실행하자 동굴 입구를 정확히 찾아 블루시티에 도달했으며, 틀린 메모는 없는 메모와 동일한 실패 결과를 낳았다.
  • 드리밍은 메모를 위키 형태로 재구조화하여, 4억 2천만 토큰 규모의 스테인리스 문서에서 검색보다 높은 정답률을 기록했다.

클로드 코드 MEMORY.md 관리 전략과 한계

  • 클로드 코드는 MEMORY.md의 처음 200~250줄만 자동 로드하므로, 이 영역은 상세 내용 대신 파일 경로를 가리키는 인덱스로 유지해야 한다.
  • 지시 파일이 길수록 준수율이 떨어지므로, 드리밍을 활용해 상세 정보는 하위 파일로 내리고 상위에는 링크만 남기는 구조를 권장한다.
  • 메모 작성 시점, 드리밍 비용, 위키 유지보수 비용 등 해결되지 않은 문제들이 존재하며, 대화 기록 검색을 기본 메모리로 삼는 것도 합리적이다.
