02핵심 내용 구조

  • 테스트 목적: Fable 5가 Opus 4.8 대비 실제로 얼마나 나은지 검증 — Claude 답변 기준 "단순 작업은 차이 없음, 일이 어렵고 길수록 차이 확대" → 1:23 발언 구간
  • 테스트 대상: 16,000개 이상 파일·4,000개 이상 폴더의 무거운 실사용 옵시디언 볼트
  • 작업 방식: VS Code에서 에이전트 호출 → "아무것도 지우지 말 것" 제약 하에 청소 계획서 작성 → 단계 실행
  • 진단 결과의 반전: 실제 파일 수 55,000개, 그중 노트는 18,000개뿐 — 파이썬 가상환경 2개가 25,000개+ 파일 점유(전체의 약 절반) → 3:35 진단 구간
  • 디스크 측면: 영상 원본 47GB + 옛 백업 19GB 별도 발견
  • 해법: 삭제가 아닌 "장부 제외" — 옵시디언 설정에서 해당 폴더를 인덱스·싱크 대상에서 제외(숨김). 파일은 디스크·파인더에 전부 보존, 설정 한 줄 지우면 원복 → 4:58 설명 구간
  • 결과: Phase 1만으로 24,000개 파일 인덱스 제외 = 절반 이상 다이어트 → 5:31 결과 구간

03기술적 맥락

  • 옵시디언은 볼트 내 모든 파일을 노트 여부와 무관하게 검색 인덱스에 포함 → 가상환경·바이너리가 성능 저하의 실제 원인
  • 6단계(Phase 1~6) 계획: 진단 → 인덱스 제외 → 대용량 이동 등 "삭제 없는 이사" 중심 설계
  • 핵심 철학 4줄: ①진단 먼저 ②범위는 노트가 아님 ③안전한 것부터 ④숫자로 검증

04전략적 의미

  • Fable 5의 차별점은 "복잡하고 긴(long-running) 작업"에서의 계획 수립·안전장치 설계 능력 — 이전 모델 대비 더 전략적·안전한 작업 수행 체감
  • Fable 5 구독 내 사용은 2026-06-22까지 한시 제공(Pro·Max 구독료 내 처리), 이후 크레딧 차감 방식 전환 → 2:21 안내 구간

05핵심 워크플로우

  1. 백업 필수 — 볼트 폴더 통째 복사 후 작업 시작
  2. 에이전트에 "삭제 금지" 제약 + 청소 계획서 먼저 요청
  3. 계획서를 다른 모델로 교차 검토 — 작업하던 모델은 자기 오류를 못 찾는 경우 존재
  4. Phase별 실행 → 숫자(파일 수)로 효과 검증
  5. 핸드오프 문서로 재사용 가능하게 보존

06활용 시나리오

  • 수만 개 파일로 느려진 옵시디언/노트앱 볼트의 안전 경량화
  • 코드·가상환경이 섞인 지식관리 폴더의 인덱스 최적화
  • 공유된 핸드오프 문서를 받아 자기 볼트 청소 계획과 비교·적용

07현황 및 전망

  • Fable 5 무료(구독 내) 체험 기한 6/22 — 그 전 대형·장기 작업 테스트 권장
  • "어렵고 긴 작업일수록 차이 커짐" 가설이 실전에서 확인 — 향후 에이전트형 장기 작업이 신모델 평가의 기준점이 될 전망
