오늘 GPTers x 뽀짝이 오픈채팅방에서 오고 간 대화의 핵심 내용을 주제별로 요약했습니다.

01AI 모델 토큰 사용량 및 관리

  • AI 모델 사용 시 토큰 소모량에 대한 논의와 관리 방안 공유
  • 하트비트(Heartbeat) 크론 작업이 토큰을 많이 소모하여, 해당 작업을 다른 방식으로 분리하거나 리눅스 기본 크론탭으로 옮기는 방안이 논의됨.
  • 오픈클로(OpenCLaW)의 크론 기능 대신 리눅스 크론탭을 활용하여 토큰 사용량을 절감하는 방법이 언급됨.
  • GPT 사용 시 토큰 절약을 위한 전략 (크론 작업 분리, 대시보드 관리 등) 공유.
  • 클로드 코드를 사용할 때 평문으로 저장된 크론탭 작업을 암호화하는 과정에서 토큰이 많이 사용되었으나, 오류 없이 성공적으로 완료된 사례가 공유됨.

02Hermes (AI 에이전트) 활용 및 설정

  • Hermes와 Google Workspace (Gmail, Google Drive 등) 연동 방법에 대한 문의가 있었으며, googleworkspace/cli 사용 여부가 논의됨.
  • Hermes에서 workspace path와 cwd path의 차이점에 대한 상세한 설명이 공유됨.

* 워크스페이스 경로: "내가 어떤 프로젝트를 하고 있는지"를 나타내는 기준 * CWD 경로: "명령어와 파일 작업이 실제로 실행되는 현재 위치" * 두 경로가 다를 수 있으며, 파일 작업 전에 항상 두 경로를 확인해야 하는 중요성이 강조됨. * Hermes가 예상 밖 경로에서 실행될 수 있는 여러 상황 (CLI 실행 위치, Gateway/Telegram/Discord/Slack 환경, Docker/Modal/Daytona 샌드박스, Cron job, terminal.cwd 설정 등)에 대한 설명이 제공됨. * Hermes에게 workspace path와 cwd path를 확인하게 하는 프롬프트가 공유됨.

  • Hermes 업데이트 시 프로필 연동 여부에 대한 질문이 있었고, 동일한 곳에 설치된 경우 같이 진행된다는 답변이 있었음.
  • Hermes에서 Claude 플랜 사용 여부 및 API 결제, 프록시 우회 등의 방법이 논의됨.
  • Hermes의 에이전트 기능 개선에 대한 긍정적인 평가가 언급됨.

03오픈클로(OpenCLaW) 및 기타 AI 도구 활용

  • 오픈클로(OpenCLaW)를 활용하여 AI 에이전트 개인 하네스 구축에 성공한 사례가 공유됨 (네이버 API로 실시간 인기글 가져오기, 키워드 검색 등).
  • 오픈클로에 대한 정보가 잘 정리된 외부 사이트 링크가 공유됨: openclaw.dmssolution.co.kr
  • 오픈클로를 코딩 용도로 활용하여 크론탭을 만들고 실행하며, 새로운 작업을 추가할 때 기존 작업을 읽어와 내용을 이해시키는 방식이 공유됨.

04AI 영상 편집 및 활용 사례

  • AI를 활용한 여행 영상 컷 편집 사례가 공유됨.
  • video-use 검토 및 ElevenLabs API 전사를 Whisper 로컬 모델 사용 방식으로 수정하여 진행.
  • Fable 또는 Opus 모델을 사용하여 편집을 진행했으며, 로컬 영상을 편집하는 경우 추가 비용이 발생하지 않음 (오직 클로드 코드 토큰 비용만 발생).
  • Mac 또는 Windows 환경 모두에서 가능하다고 언급됨.

05AI 모델 및 기술 동향

  • Faible 모델 사용 시 라우팅 기능으로 인해 실제로는 Opus 모델로 전환될 수 있다는 점이 논의됨.

* /btw 명령어를 통해 현재 사용 중인 모델을 확인할 수 있음. * Faible이 아닌 Opus로 자동 전환되는 경우를 방지하려면, 처음부터 Faible이 위임하도록 지시하는 것이 좋다는 의견이 제시됨. * Faible에서 "메시지 감지 시 모델 전환" 폴백 기능이 강제 라우팅으로 인해 무력화될 수 있다는 의견이 있었음.
