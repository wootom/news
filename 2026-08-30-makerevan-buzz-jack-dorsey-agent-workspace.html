왜 다들 Buzz로 가나 — 별 3만 개 받은 잭 도시 회사의 오픈소스

잭 도시의 회사 Block이 만든 오픈소스 'Buzz'는 노스터 프로토콜 위에 사람과 AI 에이전트를 동일한 신원 모델로 앉혀, 컨텍스트 왕복 비용을 이벤트 로그 하나로 없애는 실험이다.

01정체 — 채팅앱도 개발도구도 아닌 것

  • 깃허브 공개 6개월 만에 별 3만1천개, 포크 4천개에 육박. 공식 설명은 "사람과 에이전트가 함께 일하는, 내가 소유한 릴레이 위의 작업공간".
  • 채팅앱이라기엔 깃 저장소를 품고, 개발도구라기엔 채널·DM이 있다 — 한 줄로 정의하기 어려운 하이브리드.

02없앤 낭비 ① — 사람과 에이전트 사이 복사·붙여넣기

  • 기존 방식: 터미널에서 에이전트 실행 → 결과를 슬랙에 복사 → 팀원이 답장 → 다시 터미널로 복사. 에이전트는 이 대화 흐름 자체를 보지 못한다.
  • Buzz는 에이전트를 채널 안에 사람과 나란히 앉혀, 노스터 프로토콜의 키페어 신원 모델을 사람·에이전트가 동일하게 사용 — 모든 행동에 암호서명이 남아 나중에 조작 불가능. "에이전트는 봇이 아니라 멤버다."
  • 공식 데모: 사람 셋이 스택 논의 후 에이전트(범블)를 호출해 포팅 계획 재작성 지시 → 범블이 상태 레이어를 다른 에이전트(피즈)에게 위임 → 피즈가 다시 허니를 호출. 에이전트끼리 같은 스레드를 공유해 컨텍스트 재설명이 필요 없다.

03구조 — 이벤트 로그 하나

  • 메시지·반응·캔버스 수정·워크플로우 실행이 전부 서명된 JSON 이벤트로 같은 로그에 쌓여 검색이 한 번에 끝난다(포스트그레스 전문검색 인덱스 하나).
  • 이벤트마다 붙는 'kind' 정수 하나가 라우팅 전부 — 새 기능은 새 kind 정의로 끝나고, 구버전 클라이언트는 모르는 kind를 무시해 깨지는 변경이 원칙적으로 없다.
  • 러스트로 짠 릴레이는 인증→서명검증→멤버십확인→저장→팬아웃의 파이프라인 중 색인·감사로그·워크플로우는 비동기로 던져 응답 속도를 앞당긴다.

04없앤 낭비 ② — 도구 간 탭 전환

  • 깃을 이벤트로 취급 — 브랜치가 스레드, PR이 채팅 카드로 뜬다. 데모에서 에이전트 둘이 각각 소스PR·배포PR을 올리면 세 번째 에이전트가 리뷰하고 사람을 불러 승인만 요청 — 탭 전환 없이 한 화면에서 종료.
  • 기술적으로 릴레이가 깃 스마트 HTTP를 직접 받고, 푸시 전 정책 훅이 권한을 확인 — 에이전트가 커밋해도 서명 덕분에 누가 했는지 항상 남는다.

05없앤 낭비 ③ — 자동화의 무한루프 방지

  • 워크플로우 엔진(야믈 작성): 트리거 4종(메시지/이모지/시각/웹훅), 액션 7종(메시지, DM, 채널주제변경, 반응, 웹훅호출, 승인요청, 대기).
  • 방어 설계: 조건식 평가 100ms 제한, 웹훅 리다이렉트 차단·응답 1MB 제한, 동시실행 100개 초과시 즉시 거절, 워크플로우가 만든 메시지는 다른 워크플로우를 재발동하지 않음(무한루프 구조적 차단).

06아직 안 되는 것 (Developer Preview)

1,400개현재 열린 이슈 수
1,800개현재 열린 PR 수
  • 사람 승인 대기 액션이 문서엔 있지만 실제로는 실행 실패 처리 — 가장 중요한 안전장치가 미완성.
  • DM 보내기·채널 주제 변경 액션이 아직 껍데기, 모바일(플러터)은 진행 중, 노스터란 이름과 달리 릴레이 하나가 단독 권위를 가져 실제 P2P는 아님, 자체 호스팅에 도커·포스트그레스·레디스·러스트·노드가 모두 필요.

07지금 쓸 이유가 있는 두 부류

  • 에이전트를 2개 이상 굴리는 사람 — 특정 모델에 묶이지 않는 공용 규약(에이전트 클라이언트 프로토콜)으로 클로드 코드·코덱스·구스를 한 채널에서 대화시킬 수 있다.
  • 대화 기록을 외부에 두면 안 되는 팀 — 전부 자체 서버에서 돌고, 감사 로그가 해시체인으로 묶여 중간 삭제 시 바로 티가 난다. 맥·윈도우·리눅스 앱과 레일웨이 원클릭 배포 지원, 아파치 2.0 라이선스로 상업적 사용·포크 모두 가능.
