클로드로 나만의 '디자인 운영체제' 만들기 — 모델 자유·워크플로우 통합·자동 발행까지 (잭 로버츠)

01핵심 개요

항목내용
발표자잭 로버츠(Jack Roberts) — 테크 스타트업 매각 경험자, 현재 AI 스타트업 운영, 클로드 코드 마스터클래스 운영
핵심 주제클로드 코드로 프롬프트만으로 직접 만드는 개인용 '디자인 운영체제(Design OS)'
기반 도구클로드 디자인(Claude Design) 앱 + 클로드 코드(Claude Code) + 블루타토(Blotato, 소셜 발행 자동화 도구)
핵심 문제의식클로드 디자인은 결과물을 외부로 내보내거나 다른 모델과 연동할 수 없고, 회사만의 워크플로우에 맞춘 커스터마이징이 불가능함
제시하는 해법로컬 컴퓨터에서 100% 구동되는 자체 디자인 OS를 만들어 모델 선택의 자유, 워크플로우 통합, 자동 발행까지 확보
구조레벨 1(디자인 시스템 이식) → 레벨 2(모든 모델 연동) → 레벨 3(디자인+자동화 파이프라인 완성)
부가 기능비용/ROI 대시보드, 메모리 시스템, 야간 자동 정리('드리밍')

02핵심 기능/내용 구조

  1. 문제 제기 — 클로드 디자인 앱의 구조적 한계: 클로드 디자인으로 아름다운 그래픽 시스템은 만들 수 있지만, 만든 디자인을 소셜미디어에 올리거나 클라이언트에게 바로 전달할 방법이 없다. 또한 사용자는 클로드가 새 기능을 만들어주길 기다려야 하는 수동적 입장이며, 모두가 비슷한 룩앤필의 결과물을 받게 되어 차별화가 어렵다는 점을 지적한다 (01:28).
  2. 디자인 OS의 기본 개념: 로컬 컴퓨터에서 100% 구동되며, ChatGPT·Gemini·Claude 등 원하는 모델을 자유롭게 골라 쓸 수 있고, 원하는 통합(인테그레이션)을 직접 선택할 수 있는 자체 제작 시스템이다. 실제로 화자는 이미지 생성 시 참고 이미지를 첨부하고 크레딧 비용을 미리 확인하는 화면, 컴퓨터 내 이미지를 텍스트 검색이 아닌 '매직 스캔'(내용 기반 인식)으로 찾아내는 기능을 시연한다 (02:53).
  3. 레벨 1 — 기존 디자인 시스템을 내 OS로 이식하기: 클로드 디자인에서 만든 디자인 시스템(예: 화자의 'Jack Rabbit' 시스템)을 Share → Project HTML → Project Archive 순으로 내보내면 HTML 아카이브 파일이 다운로드된다. 이 파일을 클로드에게 "내 디자인 OS에 추가해달라"고 프롬프트하면, OS 안의 'System' 탭에 해당 디자인 시스템이 등록되어 이후 어떤 프롬프트에서도 동일한 스타일로 결과물을 생성할 수 있다 (04:11).
  4. 레벨 2 — 모든 AI 모델과 연동하기: 클로드 크레딧이 소진되거나 특정 모델(GPT-5.6, GLM-5.3 등 벤치마크 상위 모델)을 쓰고 싶을 때, 이미 로그인된 ChatGPT 계정 등을 그대로 활용해 별도 API 크레딧 소모 없이 디자인 OS 안에서 모델을 전환할 수 있다. 화자는 이를 "버튼 한 번 클릭"으로 표현하며 특정 벤더에 종속되지 않는 유연성을 강조한다 (08:16, 09:36).
  5. 레벨 3 — 디자인과 업무 자동화의 완전 결합: 인스타그램 성장을 목표로, 클로드에게 인스타그램 캐러셀(carousel) 디자인 시스템을 만들게 하고 이를 소셜 발행 자동화 도구 '블루타토(Blotato)'와 연결해 여러 플랫폼(인스타그램·페이스북·핀터레스트·링크드인 등)에 즉시 발행하는 파이프라인을 구축한다. 블루타토 설정에서 각 SNS 계정을 OAuth로 연결한 뒤 API 키를 클로드에 전달하면, 디자인 OS 안에 '캐러셀' 섹션이 생성되어 기존 카드 세트를 불러와 텍스트만 바꿔 재생성(예: "August 2026"을 "September 2026"으로 변경)하거나 새 캐러셀을 만들어 곧바로 여러 채널에 발행(publish)할 수 있다 (13:56, 17:15, 20:29).
  6. 부가 관리 기능: 화자는 OS 내 'Insight' 섹션에서 모델별 크레딧 사용량을 확인할 수 있다고 소개하며, 나아가 클로드가 매일 밤 채팅 로그를 분석해 개선점을 찾아주는 '드리밍(dreaming)' 기능과 모든 발언을 저장하는 메모리 시스템도 통합했다고 언급한다 (05:40, 11:56).

03기술적 맥락

이 영상에서 소개하는 '디자인 OS'는 별도의 상용 제품이 아니라, 화자가 클로드 코드에게 자연어 프롬프트만으로 직접 설계·구현시킨 개인 프로젝트다("제 디자인 OS 전체는 프롬프트만으로 만든 것"). 즉 로우코드/노코드에 가까운 방식으로, 클로드가 코드를 작성해 로컬 웹 앱(Create·Library·Studio·System·Insight 등의 탭 구조)을 완성하는 '에이전틱 코딩(agentic coding)' 워크플로우가 핵심 기반이다. 디자인 시스템 이식은 클로드 디자인이 제공하는 '프로젝트 아카이브(Project Archive)' 내보내기 기능(HTML 형식)에 의존하며, 이는 표준 웹 포맷이라 모델·플랫폼에 무관하게 재사용 가능하다. 모델 전환은 각 사용자가 이미 보유한 구독(ChatGPT Plus 등) 세션을 그대로 활용하는 방식으로, 별도 API 과금 없이 기존 로그인 상태를 재사용하는 것이 특징이다. 발행 자동화는 블루타토라는 제3자 SaaS의 API/MCP 연동을 통해 이뤄지며, 각 SNS 플랫폼과는 OAuth 인증으로 연결된다.

04전략적 의미

화자는 이 구조를 통해 세 가지 전략적 가치를 제시한다. 첫째, 특정 벤더(Anthropic)에 대한 종속을 피하고 크레딧 소진이나 가격 정책 변화에 흔들리지 않는 '주권(sovereignty)'을 확보한다는 점("항상 자기 디자인 시스템의 주권을 가져야 한다", 09:11). 둘째, 상용 앱이 아직 만들지 않은 자기 회사만의 워크플로우(예: 인스타그램 캐러셀 자동 발행)를 직접 구현함으로써 경쟁자와의 결과물 차별화를 꾀할 수 있다. 셋째, 디자인·자동화·발행을 하나의 파이프라인으로 묶으면 팀원(예: 인스타그램 편집 담당자)에게 계정 접근 권한만 주고 창작 통제권을 위임할 수 있어 조직 확장성이 커진다는 점을 강조한다 (18:20).

05핵심 워크플로우 또는 비교표

레벨목표핵심 동작결과
레벨 1기존 디자인 시스템 이식클로드 디자인에서 Share → Project HTML → Archive 내보내기 → 클로드 코드에 추가 요청내 OS의 'System' 탭에 해당 스타일 등록, 재사용 가능
레벨 2모델 종속 탈피이미 로그인된 ChatGPT/Gemini 등 계정을 OS에 연동크레딧 소진 시에도 버튼 클릭으로 타 모델 전환, 추가 API 과금 없음
레벨 3업무 자동화 결합블루타토 계정 연동(OAuth) → API 키를 클로드에 전달 → 캐러셀 디자인·발행 기능 생성인스타그램·페이스북·핀터레스트·링크드인 등에 원클릭 동시 발행

06활용 시나리오

  1. 크레딧 소진 시 업무 연속성 확보: 클로드 크레딧을 다 쓴 상황에서도 이미 로그인된 ChatGPT나 Gemini 계정으로 전환해 동일한 디자인 시스템으로 작업을 이어갈 수 있다.
  2. 1인 마케터의 SNS 콘텐츠 파이프라인 자동화: 인스타그램 성장에 집중하는 1인 운영자가 캐러셀 디자인 템플릿을 만들어두고, 매번 텍스트(날짜·주제)만 교체해 재생성한 뒤 여러 플랫폼에 동시 발행함으로써 콘텐츠 제작-배포 시간을 크게 단축한다.
  3. 에이전시/팀의 크리에이티브 위임 구조 구축: 화자처럼 인스타그램 편집 담당자에게 계정 접근 권한만 부여해 담당자가 직접 디자인 OS 내에서 콘텐츠를 만들고 발행하도록 함으로써, 관리자의 개입 없이도 브랜드 일관성을 유지한 채 제작량을 늘릴 수 있다.
  4. 비용 관리 대시보드로 모델별 지출 최적화: 'Insight' 탭에서 각 AI 모델·제공자별 크레딧 사용량을 확인해, ROI가 낮은 모델 사용을 줄이고 예산에 맞춰 작업을 배분하는 의사결정에 활용할 수 있다.

07현황 및 전망

영상 말미에서 화자는 이 디자인 OS가 자신이 운영하는 '클로드 코드 마스터클래스' 및 '에이전틱 운영체제(Agentic Operating System)' 유료 프로그램의 일부로 제공되며, 재단(파운데이션) 설정부터 웹사이트·디자인 시스템 구축, 수익화까지 다루는 별도 강의로 이어진다고 안내한다. 즉 이 영상 자체는 개념 증명(proof of concept) 성격이 강하고, 구체적인 코드나 설치 가이드는 유료 콘텐츠로 유도되는 마케팅 구조를 갖는다. 다만 프롬프트만으로 로컬 앱을 구성하는 에이전틱 코딩 접근 자체는 재현 가능한 흐름으로 소개되며, 블루타토 같은 제3자 자동화 도구와의 연동이 실제 발행까지 이어지는 장면이 시연된다. 향후 관전 포인트는 이런 개인 제작 OS가 클로드/OpenAI 등 벤더가 직접 제공하는 공식 기능(예: 네이티브 발행 연동)으로 흡수될지, 아니면 계속 서드파티 자동화 도구에 의존하는 형태로 남을지에 있다.

08용어 사전

용어한줄설명비유/예시
디자인 OS (Design Operating System)여러 AI 모델·디자인 시스템·발행 도구를 한 곳에서 다루도록 직접 만든 로컬 통합 앱여러 앱을 오가지 않고 한 데스크에서 모든 업무를 처리하는 '만능 작업대'
클로드 디자인(Claude Design)Anthropic이 제공하는 디자인 생성 웹 앱, 결과물 내보내기(Export)는 되지만 자동 발행은 불가그림은 그려주지만 우체국까지는 안 데려다주는 화실
프로젝트 아카이브(Project Archive)클로드 디자인의 디자인 시스템을 HTML 형태로 내보내는 기능작업 파일을 압축해 다른 프로그램에서도 열 수 있게 포장하는 것
블루타토(Blotato)여러 SNS 계정에 콘텐츠를 한 번에 발행하도록 연결해주는 제3자 자동화 서비스여러 우체국 창구를 한 번에 대신 접수해주는 대행 창구
매직 스캔(Magic Scan)파일명이나 메타데이터 없이도 이미지 내용을 인식해 검색하는 기능라벨이 없는 상자도 안을 들여다보고 찾아주는 검색 로봇
드리밍(Dreaming)AI가 야간에 자동으로 사용 로그를 분석해 개선점을 제안하는 기능매장이 문 닫은 밤사이 재고를 정리해두는 야간 직원
