OpenClaw 멀티플레이어는 에이전트 세션을 공유해 협업 과정을 드러내지만 통제와 검증은 남는다

OpenClaw는 공유 세션으로 협업 과정을 드러내고, OCE는 조직 에이전트의 통제 기반을 제시한다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

01핵심 개요

  • 발표자는 터미널·Codex Desktop·여러 컴퓨터로 작업 환경을 넓혔지만, 팀원 참여가 자신을 거치는 병목은 남았다고 말한다.
  • OpenClaw 멀티플레이어 서버에서는 같은 권한의 팀원이 세션을 보고 프롬프트를 넣으며, 발표자는 초대 대상을 신뢰하는 사람으로 제한하라고 경고한다.
  • 세션 공개는 코드 변경의 이유와 동료의 작업 과정을 공유해 충돌을 줄이고 배움을 돕는다는 팀의 체감으로 소개되지만, 정량 성과는 제시되지 않는다.
  • 자동화 루프는 Discord·Twitter·GitHub를 살피고 재현·수정·검증·별도 에이전트 리뷰 뒤 반영하는 흐름이며, 취향은 사람의 몫으로 남긴다.
  • OCE는 샌드박싱·서비스 계정·리뷰 등으로 조직 내 에이전트를 관리하는 오픈소스 컨트롤 플레인으로 발표됐고, 시연의 일부 응답은 기대와 달랐다.

02핵심 주장 / 논점 구조

  • 모델이 빠르게 좋아지는 동안 일하는 방식과 하네스가 따라가지 못해, 이전 워크플로가 답답하고 낡게 느껴진다는 것이 발표의 출발점이다.
  • 팀원 모두 에이전트를 쓰더라도 서로의 작업을 모르면 협업은 느려지고, 한 사람이 메시지를 전달하는 ‘Meat Proxy’가 병목이 된다고 설명한다.
  • OpenClaw 멀티플레이어는 세션을 함께 보고 지시하는 방식으로 이 문제를 다루며, 발표 후반에는 조직 단위 에이전트 관리용 OCE를 소개한다.
  • 발표에서 제시된 속도·행복감·협업 개선은 팀의 경험과 주장으로 제시되며, 정량 지표나 독립 검증 자료는 나오지 않는다.

03터미널에서 팀 서버까지 넓어진 작업 환경

  • 발표자는 작년에는 터미널에서 여러 세션을 띄워 작업했고, 모델이 좋아지면서 에이전트 진행을 위해 Esc 키로 자주 개입할 필요가 줄었다고 말한다.
  • 이후 Codex Desktop으로 옮겼지만 실험과 세션이 늘어 컴퓨터의 디스크 공간과 성능 부담이 커졌다고 설명한다.
  • 부하를 나누기 위해 여러 컴퓨터를 쓰고 Codex를 dev box에 연결했으며, 에이전트가 클라우드에서 테스트하도록 grab box도 만들었다.
  • 작업 환경을 늘려도 팀원이 참여하려면 여전히 발표자를 거쳐야 했고, 그래서 팀이 서로의 세션에 참여하는 방식을 탐색하기 시작했다.

04공유 세션의 작동 방식과 초대 조건

  • 시연에서 에이전트는 새 게임을 즉석에서 만든 것이 아니라 팀이 이미 만들어 둔 Lily Lane을 찾아왔다고 발표자가 설명한다.
  • 예전에는 에이전트가 풀 리퀘스트를 돌려주면 혼자 열어 이어서 작업했지만, 공유 화면에서는 여러 사람이 같은 세션에 프롬프트를 넣는다.
  • 서버에서는 누구나 서로의 세션을 보고 프롬프트를 넣을 수 있으며, 발표자는 세션을 건드려도 괜찮은 사람만 초대하라고 경고한다.
  • 랍스터 요청 뒤 게임에는 상어도 등장했고 접속자가 몰려 입장을 막는 장면이 나왔다. 상위 기여자 초대는 향후 계획으로 언급됐다.

05세션 기록이 드러낸 리뷰 과정과 팀 도구

  • 대화 기록은 무엇이 바뀌었는지뿐 아니라 왜 바뀌었는지를 보여줄 수 있지만, PR에 기록을 첨부해 달라는 요청에는 응한 사람이 적었고 발표자도 꺼린 적이 있다고 한다.
  • 동료가 테이블을 작게 바꾼 사례에서 발표자는 세션을 열어 작업 맥락을 확인하고, 처음의 부정적 판단을 바꿨다. 이 장면은 상상해 보라는 사례로 제시됐다.
  • 서버는 앱보다 프로젝트가 모이는 장소로 묘사된다. 여러 서버와 저장소에 흩어졌던 대시보드·플러그인을 한곳에서 다루려는 방향이다.
  • daily claw는 병합 내용을 신문처럼 정리하지만 자주 틀릴 수 있고, 회의 요약은 Luna를 이용한 프롬프트로 만들며 에이전트 음성 응답은 시연하지 않았다.
  • 동료의 사이드바 디자인 세션에서는 여러 시안과 편집기, 다른 팀원의 합류가 보였지만 발표자도 최종 반영 버전을 알지 못했다.

06반복 루프와 완료 목표의 차이

  • 발표자는 Discord·Twitter·GitHub를 살피는 모니터와 작은 CLI를 활용해 데이터를 가져오고, 특정 이슈를 분류해 조사와 오류 재현을 시도한다고 설명한다.
  • 오류가 분명히 재현되면 수정안을 만들고 해결 여부를 확인한 뒤, 다른 에이전트가 리뷰하고 나서 자동 반영할 수 있는 흐름을 제시한다.
  • 루프는 계속 확인하는 작업이고 /goal은 정해진 최종 상태를 향한다. 발표자는 성능 확인 루프와 SQLite 접근 방식의 점진적 마이그레이션 목표를 예로 들었다.
  • SQLite 마이그레이션은 발표자 말로 18일째 진행 중이며 100개가 넘는 PR이 반영됐지만, 아직 끝나지 않았다고 설명한다.
  • 여러 머신에서 돌던 루프는 멈추거나 위치를 파악하기 어려울 때가 있었다고 한다. 좋은 결과를 가르는 취향과 최종 판단은 사람에게 남긴다.

07OCE의 보안 설계와 시연에서 확인된 한계

  • OpenClaw Enterprise(OCE)는 여러 에이전트를 배포·설정·통제하는 오픈소스 컨트롤 플레인으로 소개됐으며, 멀티테넌시와 거버넌스, 보안 경계를 내세운다.
  • 발표자가 설명한 원칙은 에이전트와 결정론적 코드의 실행 공간 분리, 네트워크·파일·저장소 접근 제한, 다른 모델의 auto-review, 전용 서비스 계정이다.
  • 프리셋 시연에서 Fred는 코드베이스 읽기 전용 권한을 받고 Linear 쓰기는 팀 승인을 거치도록 설정됐으며, Slack 접근도 부여됐다.
  • Fred는 질문에 기대한 답 대신 릴리스 노트를 가져왔고 발표자는 플러그인 문제일 수 있다고 말했다. Cooper에게 요청한 대시보드 기능의 완성 여부도 확인되지 않는다.
  • 발표자는 OCE를 공개하고 Kubernetes처럼 에이전트 배포의 표준이 되겠다는 구상을 제시했으며, Red Hat·NVIDIA와의 협력과 Trail of Bits 등이 참여한 Patch the Planet도 언급했다.

08용어 사전

용어뜻
세션에이전트와 나눈 작업 대화 한 묶음으로, OpenClaw 멀티플레이어에서는 팀원이 이를 보고 프롬프트를 넣을 수 있다.
하네스에이전트에게 일을 맡기고 결과를 받는 작업 환경을 가리키며, 발표자의 환경은 터미널에서 Codex Desktop과 여러 컴퓨터로 확장됐다.
루프와 /goal루프는 정해 둔 일을 반복해 확인하는 자동 작업이고, /goal은 SQLite 마이그레이션처럼 정해진 완료 상태를 향하는 작업이다.
컨트롤 플레인여러 에이전트를 한곳에서 배포·설정·통제하는 관리 층으로, OCE는 조직 단위 에이전트 운영을 위한 오픈소스 플랫폼으로 소개됐다.
프리셋조직이 에이전트의 하네스와 서비스 계정, 도구 접근 권한 등을 미리 묶어 설정하는 에이전트 번들이다.
