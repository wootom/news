핵심 개요 — 바이브코딩 vs 에이전틱 코딩
구분바이브코딩 (Vibe Coding)에이전틱 코딩 (Agentic Coding)
정의자연어만으로 AI가 코드를 생성, 결과물을 직접 수용AI가 코드를 작성하되, 인간이 설계·검증의 마스터마인드 역할 유지
에이전트 수단일 에이전트, 동기 대화다수 에이전트, 비동기 병렬 실행
인간 역할결과물 승인/거부아키텍처 결정, 스펙 작성, 품질 게이트 관리
한계컨텍스트 과부하, 세부 오류 누락초기 셋업 비용, 비용 증가
2026 트렌드개인 프로토타입 수준팀 단위 프로덕션 표준으로 부상
핵심 전환점: 2026년은 단일 AI 어시스턴트(지휘자 모델)에서 에이전트 팀 오케스트레이터(지휘관 모델)로의 전환 원년. AWS·LangGraph·Anthropic이 공통 인터페이스를 채택하며 에이전트 간 통신 프로토콜이 표준화되고 있음.
02
에이전트 팀 구성 — 6가지 역할 분담 (Squid 모델 기반)
핵심 원칙: 코드를 작성한 에이전트가 코드의 정확성을 판단하지 않는다. 역할 분리가 품질의 기반.
기획 / 아키텍처
PM Agent
원시 스펙을 받아 ADR(Architecture Decision Record) 작성, 기능을 순서화된 태스크로 분할, DDD 용어 사전 유지. Claude는 PM과 소프트웨어 아키텍트 역할을 병합 가능.
개발 / 구현
Software Engineer Agent
TDD(Test-Driven Development) 방식: 실패 테스트 작성 → 최소 코드 통과 → 리팩터링. git, gh 등 CLI 직접 사용. MCP 래퍼 미사용(유연성 확보).
검증 / QA
Tester Agent
SWE가 통과시킨 테스트의 거짓 신뢰를 잡아내는 적대적 E2E 엣지 케이스 패스. SWE가 이미 실행한 해피패스 테스트는 재실행하지 않고 결과를 수용.
코드 리뷰
PR Reviewer Agent
diff만 검토. 데드코드·중복·테스트 커버리지 누락·문서 준수 여부 확인. 핫패스의 성능 리뷰만 수행. 1회성 스크립트 마이크로 최적화 명시적 금지.
CI/CD 관리
On-Call Agent
CI 파이프라인이 통과될 때까지 루프. SWE 루프 내에 있을 때는 자주 스킵되는 문제를 해결하기 위해 별도 에이전트로 승격. 최대 5회 재시도.
메타 개선 (선택)
Self-Improve Agent
(Human Gate 필수)
실행 결과를 스캔해 CLAUDE.md·스킬·서브에이전트 업데이트 제안. 반드시 인간 검토 후 적용. 무분별한 자동 적용 시 시스템 품질 저하 위험.
03
오케스트레이션 패턴 3단계 — 단순 위임 → 병렬 팀 → 대규모
Pattern 1
Subagents — 집중 위임
  • Task 도구로 부모→자식 에이전트 생성
  • 독립 태스크는 병렬 실행, 의존 태스크는 순차
  • 부모가 의존성 그래프 수동 관리
  • 파일 소유권 명확히 분리 필수
  • 약 22만 토큰 — 비용 중립적
  • 시작점으로 권장. 설정 불필요.
Pattern 2
Agent Teams — 진정한 병렬
  • 공유 태스크 리스트 + 의존성 자동 해제
  • 팀원 간 P2P 메시지 (리드 경유 불필요)
  • Git Worktree로 에이전트별 격리 실행
  • 파일 잠금으로 동시 편집 충돌 방지
  • 3-5명 팀원이 최적 (비용 선형 증가)
  • CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1
Pattern 3
Orchestration at Scale
  • 5-20+ 에이전트, 다중 레포지토리
  • 시각적 대시보드로 진행 상황 모니터링
  • diff 검토 및 병합 제어권 인간 유지
  • 클라우드 VM에서 비동기 실행 가능
  • Ralph Loop: 원자 태스크 반복 루프
  • Multi-model 라우팅으로 비용 최적화

도구 3계층 — 용도별 최적 선택
Tier 1 — 내장형 (즉시 사용)
단일 터미널 세션, 추가 도구 불필요. 시작점.
Claude Code Agent Teams Subagents (Task 도구)
적합: 1-3개 기능 병렬 개발, 팀 입문
Tier 2 — 로컬 오케스트레이터
3-10 에이전트, 시각적 대시보드, diff 리뷰 제어.
Conductor (Melty Labs) Gas Town (Steve Yegge) Multiclaude Vibe Kanban Claude Squad
적합: 중규모 팀, 알려진 코드베이스 병렬 스프린트
Tier 3 — 클라우드 비동기
태스크 할당 후 자리 비움, PR로 결과 수신.
Claude Code Web (claude.ai/code) GitHub Copilot Coding Agent Jules (Google/Gemini) Codex Web (OpenAI) Cursor Cloud Agents
적합: 백로그 야간 처리, 터미널 없는 환경
중규모 팀 권장 조합: 평소 인터랙티브 작업은 Tier 1(Agent Teams), 병렬 스프린트는 Tier 2(Conductor), 백로그 소화는 Tier 3(Claude Code Web). 세 계층 모두 상황에 따라 혼용.

06
품질 게이트 3종 — 신뢰할 수 있는 출력물 확보
핵심 관점 전환: 2026년 병목은 생성(Generation)이 아니라 검증(Verification). 에이전트는 빠르게 코드를 만들지만, 그 코드가 올바른지 확신하는 것이 어렵고 중요한 작업.
Gate 1
Plan Approval — 코드 전 계획 검토
팀원이 구현 전 계획을 작성 → 리드가 검토 후 승인/거부. 나쁜 계획을 수정하는 비용이 나쁜 코드를 수정하는 비용보다 훨씬 저렴.
Gate 2
Hooks — 라이프사이클 자동 검증
TaskCompleted 후크: lint + 테스트 통과 시에만 완료 처리. TeammateIdle 후크: 에이전트가 유휴 전 모든 테스트 통과 확인. 실패 시 에이전트가 계속 작업.
Gate 3
AGENTS.md — 복합 학습 메모리
발견된 패턴·주의사항·스타일 규칙 누적. 매 세션 시작 시 모든 에이전트가 읽음. 인간이 직접 작성·승인. AI 자동 생성 금지 (성공률 3% 하락, 비용 20% 증가 연구 결과).
AGENTS.md 권장 구조 (인간 직접 작성)
## STYLE
코딩 스타일, 네이밍 규칙, 컴포넌트 패턴 등 팀 표준 기술
## GOTCHAS
에이전트가 자주 실수하는 함정, 특정 라이브러리 주의사항 등
## ARCH_DECISIONS
아키텍처 결정 이유, 사용하지 않는 패턴과 그 이유
## TEST_STRATEGY
테스트 작성 원칙, 통합 테스트 우선 여부, 사용 도구
07
중규모 팀 도입 로드맵 — 3단계 확장
Phase 1
1-2주
개인 → Subagents 전환
각 팀원이 Claude Code에서 Task 도구로 서브에이전트 위임 실습. AGENTS.md 초안 작성. 파일 소유권 규칙 정립. /scaffold 스킬로 프로젝트 표준 구조 생성. 목표: 단순 기능 1개를 3개 서브에이전트로 병렬 구현 경험.
Phase 2
3-4주
Agent Teams + Day/Night 워크플로우
CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 활성화. PM+SWE+Tester 3인 팀으로 /night 파이프라인 운영. Conductor(Tier 2) 도입으로 시각적 관리. Plan Approval과 Hooks 품질 게이트 설정. ADR 디렉터리 구축 시작. 목표: 전체 기능 하나를 /night로 완전 자동화.
Phase 3
5-8주
6 에이전트 풀팀 + 클라우드 스케일
PM+SWE+Tester+PR Reviewer+On-Call+Self-Improve 전체 역할 활성화. Claude Code Web(Tier 3)으로 백로그 야간 처리. Multi-model 라우팅 도입(계획→저비용, 구현→Sonnet/Opus, 리뷰→보안 특화). Ralph Loop으로 지속적 개선. AGENTS.md 자동화 제안 → 인간 검토 루틴 정착. 목표: 스프린트 처리량 3배 달성.
인간이 유지해야 할 판단 영역 (에이전트에게 위임 불가)
  • 아키텍처 설계 및 API 경계 결정
  • 만들지 않을 기능 결정 (No라고 말하기)
  • 전체 시스템 맥락으로 에이전트 출력물 검토
  • AGENTS.md 모든 항목 직접 작성/승인
  • Self-Improve Agent 제안 검토 후 반영 여부 결정
  • 스펙(기능 요구사항)의 정밀도 유지
스펙이 레버리지다. 모호한 스펙은 수십 개 병렬 에이전트 전체에 오류를 곱한다. 정밀한 스펙은 전체 팀의 품질을 배가한다.
