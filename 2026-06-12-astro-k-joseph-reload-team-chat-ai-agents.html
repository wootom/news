항목내용

문제 의식에이전트 개별 성능은 뛰어나지만 사람이 중간에서 컨텍스트 복붙 — 하루 1시간+ 낭비 (00:14)

02핵심 기능 구조

  • 채널: 슬랙처럼 목적별 채널 생성, 사람+에이전트가 멤버로 공존
  • @멘션 위임: 사람이 채널에 요구사항 1회 게시 → 오케스트레이터 에이전트(openclaw)가 태스크 분해·할당
  • 태스크 보드: 에이전트가 생성·할당·완료 처리하는 작업 목록, 사람도 직접 태스크 생성 가능 (07:42)
  • 공유 메모리: 모든 에이전트가 같은 메모리 공간 읽기·쓰기 — 작업·결정·수정 내역 자동 기록, 재브리핑 불필요 (14:59)
  • 자율성 다이얼: 24/7 완전 자율 실행 ↔ 사람 승인 대기 중 선택, 필요 시 에이전트가 사람을 태그 (00:49)

03기술적 맥락

  • 연동 = MCP(Model Context Protocol) 서버 등록: Reload에서 에이전트 생성 → MCP 설정 복사 → Cursor 설정/Claude Code 프롬프트/openclaw 세션에 붙여넣기
  • 백그라운드 자동 수신: Claude Code는 loop 명령, openclaw은 cron job으로 미확인 멘션·태스크 폴링 (12:30)
  • 컨텍스트 그래프: 결정·인계 내역이 그래프로 축적 — 오래 쓸수록 스택 전체가 똑똑해지는 구조(제작사 주장)

04전략적 의미

  • 멀티에이전트 병목 = 모델 성능이 아니라 에이전트 간 컨텍스트 전달임을 정확히 겨냥
  • 개인 차원을 넘어 팀 단위: 디자이너의 Claude Code + PM의 openclaw + 엔지니어의 Cursor가 한 워크스페이스 공유
  • "AI 도구 사용"에서 "AI 팀 매니징"으로 사용자 역할 전환

05핵심 워크플로우 (영상 데모)

  1. Reload 가입 → 워크스페이스·채널(product-dev) 생성
  2. 에이전트 온보딩: 이름·핸들 지정 → MCP 설정 복사 → 각 도구에 등록 → 연결 테스트
  3. 채널에 요구사항 게시: 습관 추적 앱에 ① 주간 회고 기능 ② 랜딩 페이지 추가, openclaw 태그
  4. openclaw이 부모 태스크 + 병렬 서브태스크 생성: 주간 회고=Claude Code, 랜딩+라우팅=Cursor
  5. 양쪽 완료 보고 → openclaw이 검수 후 태스크 종료 → 앱에 두 기능 반영 확인
  6. 후속: 다크/라이트 모드 토글을 Claude Code에 직접 멘션 (11:30) → 1차 구현에 React hydration 버그 → 후속 멘션으로 원인 진단·수정 완료

06활용 시나리오

  • 1인 개발자: 리서치 에이전트 → 코딩 에이전트 → QA 에이전트 자동 릴레이, 수면 중 24/7 작업
  • 스타트업 팀: 직군별 에이전트를 공용 채널에 모아 기능 개발 스프린트 자동 분배
  • 사이드 프로젝트: 버그 리포트를 태스크로 등록하면 담당 에이전트가 자동 수정·보고

07현황 및 전망

  • 데모 기준 Claude Code·Cursor·openclaw·Devin·Hermes 에이전트 연동 확인
  • 한계 신호: 1차 구현 버그(다크모드 토글 미작동)처럼 사람 검수 루프는 여전히 필요
  • 협찬성 리뷰 가능성 고려 — "오래 쓸수록 똑똑해진다" 등 효과 주장은 직접 검증 필요
