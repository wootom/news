AI로 결제 기능 만들 때 정해야 할 7가지 — 진짜 문제는 환불에서 시작됩니다

01핵심 개요

항목내용
채널헤이제임스 - AI 쉽게 배우기
주제AI로 결제 기능 구현 시 반드시 결정해야 할 정책 7가지 (결제보다 환불·취소가 진짜 난제)
한 줄 요약결제가 되는 건 AI로 5분, 그러나 서비스가 되려면 주문상태·금액검증·환불·이중결제 방지 등 결정이 먼저 필요, 절반은 법이 정한 것
실습'동네치킨' 배달 사이트에 토스페이먼츠 테스트 결제 붙이기 — '뚝딱 버전' vs '실제 서비스 수준' 비교

02결제의 본질

구분내용
PG의 역할카드번호는 우리 서버에 오지 않음. 돈은 결제대행사(PG, 예: 토스페이먼츠)가 처리
우리의 역할'장부' 관리 — 어떤 주문이 얼마이고 결제·취소·환불됐는지 기록
핵심 원칙금액은 서버가 재확인. 브라우저가 보낸 금액은 조작 가능(10만원→1원 시도 실재). PG 통보 후 서버가 주문금액 대조해야 완료 처리

03정해야 할 7가지 결정 (절반이 법과 얽힘)

#항목핵심
1주문 상태 설계결제대기·완료·취소·환불진행중·환불완료 등 다단계. CS의 언어이자 장부 정합성의 기반
2청약 철회(법)전자상거래법상 7일 내 단순변심 환불 가능, 사업자는 3영업일 내 환불(지연 시 연 15% 이자). 디지털콘텐츠는 사전 고지 시 예외
3부분 환불3개 중 1개 반품 시 금액·배송비·쿠폰 할인 배분 정책 필요. 정답 없어 서비스별 규칙 필수
4이중 결제 방지버튼 연타·새로고침 시 중복 결제 차단. 한 주문에 결제 하나만 성립하게 잠금
5결제 실패 처리한도초과·잔액부족은 정상 상황. 안내 문구("카드 한도 확인, 주문 30분 유지")가 매출을 가름
6결제 내역 페이지고객이 직접 결제·환불 진행상황 확인 → CS 문의 수십 건 대체
7환불 규정 고지결제 전 규정 노출. 취소 버튼을 숨기면 '다크패턴'으로 제재 대상

04다크패턴 규제 배경

구분내용
사건작년 10월 공정거래위원회가 OTT·음원 등 구독 플랫폼에 시정명령·과태료
이유돈을 잘못 받아서가 아니라 해지·환불 경로를 어렵게 만들어서(가입은 버튼 하나, 해지는 여러 단계)
정의다크패턴 = 사용자를 불리하게 유도하는 UI. 법 개정으로 제재 대상화

05실전 프롬프트의 차이

구분내용
뚝딱 버전"토스페이먼츠 테스트 결제로 카드결제 되게 해줘" — 결제창은 뜨나 금액대조·취소·환불 코드 없음, 결제 버튼도 없음
서비스 버전8가지 정책을 명시 + "정하지 않은 정책은 먼저 질문해줘" → AI가 자동승인/수동승인 등 되물음 → 답변이 곧 정책 문서
구독 결제갱신 시점·해지 처리·플랜 변경 차액 계산이 추가. 다크패턴 규제가 가장 강한 영역(무료→유료 전환 시 별도 명시 동의 필요). 단건 결제 장부가 기반

06완성된 서비스의 조건

구분내용
금액 검증토스 통보 금액이 주문금액과 다르면 승인 취소
부분 환불클라이언트 숫자 불신, 서버가 단가×수량 직접 계산
이중결제같은 주문 잠금, 이미 결제된 건은 성공 처리
환불 신청고객이 내역에서 직접 신청 → 환불진행중→완료
운영자 화면상태별 검색, 환불 신청 대기함, 3영업일 초과 시 기한경과 경고 표시

07용어 사전

용어설명
PG(결제대행사)Payment Gateway. 실제 카드결제를 처리하는 회사(토스페이먼츠 등)
다크패턴사용자를 불리한 선택으로 유도하는 기만적 UI 설계
청약 철회전자상거래법상 소비자가 7일 내 단순변심으로도 계약을 철회할 권리
통신판매업자돈을 받는 순간부터 적용되는 전자상거래법상 지위
