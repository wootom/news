🔄 기존 방식 vs 멀티 에이전트 방식
❌ 기존 단일 세션 방식
  • 채팅창 하나에서 모든 작업
  • Stateless: 세션 끝나면 리셋
  • 하나의 AI에 모든 역할 부여
  • 구구절절 프롬프트 필요
  • 확장·병렬 처리 어려움
✅ 멀티 에이전트 방식
  • 역할별 에이전트 분업 운영
  • Stateful: 상태·목표 지속 관리
  • 오케스트레이터가 에이전트 지휘
  • 목표만 주면 자율 수행
  • 병렬·순차 처리로 확장 가능

🔑 핵심 개념 3가지
PaperClip — 에이전트 오케스트레이션 프레임워크

AI 에이전트들을 사람처럼 조직화해 관리하는 오픈소스 도구. 각 에이전트에게 역할(페르소나)을 부여하고 목표 기반으로 자율 작업 배분

Hermes — 에이전트 간 통신 프로토콜

멀티 에이전트 시스템에서 각 에이전트의 메시지 라우팅과 상태 관리를 담당. PaperClip과 연동해 에이전트 팀 통신 강화

Purpose-Driven 접근 — 목표 기반 에이전트 운영

상세 프롬프트 대신 목표만 할당하면 에이전트가 스스로 계획·실행. Codex의 /goal 명령어, Claude Code의 에이전트 뷰도 같은 방향

💡 전략적 의미
에이전트 OS가 다음 AI 트렌드 — 단일 에이전트 튜닝에서 멀티 에이전트 운영 관리로 논의 이동
오픈소스 생태계 성장 — PaperClip, Hermes 모두 커뮤니티 집단 지성으로 빠르게 발전 중
Human-in-the-Loop 설계 — 완전 자동화보다 사람의 감독·개입 구조를 처음부터 포함해야
지금 선제 학습이 기회 — 아직 불완전하지만, 가능성을 보고 먼저 익힌 사람이 유리
🎯 활용 시나리오
1주식·코인 콘텐츠: 시장 데이터 수집 + 분석 + 발행 에이전트 자동 분업
2코드 리뷰: 코드 분석 + 테스트 + 문서화 에이전트 협업 파이프라인
3리서치 자동화: 검색 + 요약 + 보고서 작성 에이전트 체인
4고객 지원: 문의 분류 + 답변 생성 + 에스컬레이션 관리 에이전트
