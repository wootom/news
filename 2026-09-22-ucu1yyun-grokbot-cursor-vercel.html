GrokBot과 Cursor를 조율해 팝업 플랫폼 랜딩 페이지를 배포하는 과정을 공개했다.

GrokBot·Cursor로 팀을 꾸리고 Vercel에 팝업 플랫폼 랜딩 페이지를 배포했다.

01핵심 개요

  • Ship by Thursday는 샌프란시스코 음식 팝업 운영 경험을 바탕으로 팝업 운영 시스템을 만들겠다는 계획을 밝혔다.
  • 시제품용 GrokBot과 본격 개발용 Cursor 하네스를 구분하고, 개발 봇 Tater와 운영·크리에이티브 역할의 봇을 구성했다.
  • GitHub 저장소 popup.git을 만든 뒤 HTML 기반 초기 랜딩 페이지를 올리고 Vercel에 연결해 배포했다.
  • 신청 정보 저장소로 Notion 데이터베이스를 우선 검토한 뒤 PlanetScale Postgres 연결을 기술 방향으로 논의했다.
  • 회사 도메인으로 shipbythurs.day를 확보했으며, 회사 사이트와 실제 제품의 도메인은 분리할 계획이다.

02핵심 주장 / 논점 구조

  • 초기에는 빠르게 만들고 버릴 수 있는 시제품을 GrokBot으로 제작하고, 본격적인 구현은 Cursor에 맡기는 흐름을 제시했다.
  • 제품·시장 적합성을 찾는 단계에서는 기술 스택 논쟁보다 빠르게 무언가를 만드는 일이 중요하다고 말했다.
  • GrokBot은 봇 조율과 자동화, Cursor 하네스는 코드 작성과 제품 개발에 강점이 있다고 구분했다.
  • 봇이 코드와 PR을 통해 함께 발전하는 구조를 구상했으며, 이후에는 PR 대신 main 브랜치에 직접 올리라는 규칙을 정했다.

03Ship by Thursday의 사업 구상과 역할 분담

  • 회사 이름은 더 적합한 이름을 찾기 전까지 Ship by Thursday를 쓰기로 했다.
  • 샌프란시스코에서 음식 팝업을 열고, 그 경험을 토대로 팝업 운영 플랫폼을 만들 계획이다.
  • 로런은 기술을 맡는 CTO, 로샨은 제품을 이끄는 CPO로 언급됐으며 진행자는 CEO 역할을 맡았다.
  • 매트는 운영 팀·회사 매뉴얼·시장 진출 계획을 준비하고, 로런은 서비스 연동과 데이터베이스 설정을 맡는 것으로 요약됐다.

04시제품 봇과 AI 개발팀 구성

  • Steve에게 기존 시제품이 지루하고 밋밋하다는 피드백을 전달하고, Grok Pot에 새 시제품을 요청했다.
  • 시제품 담당 봇의 이름 후보로 Spud, Tater, Gnocchi가 나왔고 최종적으로 Tater를 선택했다.
  • 운영 봇과 크리에이티브 디렉터 봇도 만들었으며, 크리에이티브 디렉터는 이름과 큰 방향을 돕도록 설정했다.
  • 마케팅 봇은 브랜딩·이름·디자인 팀 조율을 맡도록 구상했고, 모든 봇이 저장소에 PR을 보낼 수 있는 방식을 언급했다.

05Cursor 클라우드 에이전트 활용 방식

  • Cursor 클라우드 에이전트로 프런트엔드와 백엔드의 뼈대를 만들고, 손님과 대화하는 동안 개발을 진행하려 했다.
  • GrokBot 안에서 봇에게 Cursor 클라우드 에이전트를 만들도록 지시해 Cursor의 개발 역량을 활용하는 방식을 설명했다.
  • 클라우드 에이전트는 자체 가상 머신에서 앱을 테스트하고 화면을 클릭할 수 있으며 CPU 실행 기록도 수집할 수 있다고 말했다.
  • Tater에게 클라우드 에이전트를 쓰도록 지시하고, 장기 작업의 기술적 맥락을 관리할 프로젝트도 만들었다.

06GitHub·Vercel 랜딩 페이지 배포

  • GitHub 저장소 popup.git을 만들고 Slack에 공유했으며, 랜딩 페이지를 저장소에 올려 호스팅하기로 했다.
  • 초기 플랫폼은 index.html 하나로 구성됐고, 스타일은 모두 인라인인 임시 형태라고 설명했다.
  • Vercel에서 GitHub의 popup 저장소를 연결하고 main 브랜치에 푸시하면 배포되도록 설정했다.
  • 배포 주소가 생성됐지만 아직 기능은 없었으며, 회사 랜딩 페이지는 shipbythurs.day에 연결하기로 했다.

07데이터베이스·도메인·개발 운영 결정

  • 랜딩 페이지 신청 정보를 저장하기 위해 Google Sheets, Notion 데이터베이스, 파일 기반 DB 방안을 검토했다.
  • Notion 연결로 작은 데이터베이스를 먼저 만들자는 요청이 있었으나, 이후 PlanetScale Postgres를 바로 연결하자는 의견이 제시됐다.
  • PlanetScale 인증 정보를 기다리는 동안에는 테이블 설계와 의존성 준비를 먼저 진행해 작업이 막히지 않도록 요청했다.
  • 도메인 후보로 claimastall.com, stall.run, nightmarket.app, popup.place, openstall.co 등이 제시됐고 shipbythurs.day를 확보했다.

08용어 사전

용어뜻
GrokBot가벼운 시제품 제작에 쓰는 하네스이자 봇 조율과 자동화에 강점이 있다고 설명된 도구다.
Cursor 하네스코드를 작성하고 제품을 만드는 데 강점이 있어 본격 개발 작업을 넘길 대상으로 언급됐다.
클라우드 에이전트자체 가상 머신에서 앱을 실행·테스트하고 화면 클릭과 CPU 실행 기록 수집을 할 수 있는 Cursor 작업 환경이다.
VercelGitHub 저장소를 연결해 랜딩 페이지를 배포하고 도메인을 연결하는 호스팅 서비스로 사용됐다.
PlanetScale Postgres신청 정보 등 서비스 데이터를 저장할 데이터베이스 후보로 연결이 논의된 PlanetScale의 Postgres 환경이다.
Ship by Thursday팝업 운영 시스템을 만들기 위해 사용한 회사명이며, 여러 회사를 만드는 모회사로 설명됐다.
