이제 터미널 안 씁니다 — 클로드 코드 데스크탑 앱으로 바뀐 것들

01핵심 개요

항목내용
형식클로드 코드를 몇 달간 터미널로만 써온 개발자가 올해 4월 전면 개편된 데스크탑 앱으로 옮긴 뒤, 실제 작업 방식이 어떻게 바뀌었는지 다섯 가지 차이로 짚고 앱의 버그와 한계까지 함께 밝히는 단독 진행 영상
화자메이커 에반(Maker Evan), 유튜브 채널 운영자
핵심 문제의식"예쁘다"가 아니라 같은 작업을 할 때 "손이 몇 번 덜 가는가"를 기준으로 터미널과 데스크탑 앱을 비교해야 한다는 것. 이 반복 동작의 차이가 하루 수십 번 쌓이면 실제 작업량 자체가 달라진다는 주장
핵심 내용세션 관리, 프로젝트·모델 전환, 브라우저 자동화, 작업 공간 레이아웃, 예약/자동 실행 다섯 영역에서 데스크탑 앱이 터미널 대비 반복 조작을 크게 줄여준다는 것이 핵심 주장이며, 동시에 앱의 실제 버그 사례와 터미널이 여전히 우위인 영역(세밀한 옵션 지정, 스크립트 자동화, 원격 서버 작업)도 균형 있게 제시
핵심 메커니즘데스크탑 앱은 터미널과 "같은 엔진"을 쓰고 같은 규칙 파일·설정·스킬·권한을 공유하므로 둘 중 하나로 갈아타는 문제가 아니라 상황에 맞게 손에 맞는 도구를 고르는 문제라는 것이 결론

02핵심 기능/내용 구조

  1. 세션 관리 — 창을 나누는 대신 목록에서 클릭: 터미널에서 여러 작업을 동시에 진행하려면 탭을 열거나 화면을 쪼개거나 창을 새로 띄워야 하고, 어느 창이 어느 프로젝트인지 헷갈려 엉뚱한 창에 명령을 친 적이 여러 번 있었다고 밝힌다. 데스크탑 앱은 왼쪽에 세션 목록이 상시 표시되어 진행 중·완료·정지 상태가 한 줄씩 보이고, 클릭 한 번으로 해당 대화로 진입한다. 컨트롤+탭으로 다음 세션 이동, 커맨드+N으로 새 세션 생성, 상태별·프로젝트별 필터링이 가능하며 완료된 세션은 자동으로 목록에서 정리된다. 세션마다 작업 폴더가 "깃 워크트리(git worktree)" 방식으로 완전히 분리되어 있어(프로젝트 내 숨은 폴더에 각 세션 사본이 생성) 두 세션이 같은 파일을 동시에 고쳐도 충돌하지 않으며, 브랜치 이름 접두어도 커스터마이즈 가능하다. 터미널에서 이 워크트리 생성·이동·정리를 직접 하려면 손이 많이 가서, 결국 한 번에 하나씩만 작업을 시키게 됐다는 것이 화자의 경험.
  2. 프로젝트·모델 전환 — 목록 클릭 한 번: 터미널에서 프로젝트를 바꾸려면 폴더로 이동해 다시 실행하고 경로 입력·엔터·재구동 대기가 필요하지만, 앱에서는 목록에서 폴더를 고르면 끝이며 해당 폴더에 설정된 규칙 파일과 스킬이 자동으로 따라온다. 원격 실행과 로컬 실행, 클라우드에 여러 저장소를 붙이는 것도 같은 화면에서 선택 가능. 모델 전환도 보내기 버튼 옆 목록에서 클릭 한 번이며, 현재 사용 중인 모델이 항상 화면에 표시된다. 화자는 무거운 설계는 고성능 모델에, 단순 정리는 빠르고 저렴한 모델에 맡기는 판단을 하루에도 여러 번 내리는데, 이 전환이 가벼워야 실제로 그 판단을 실행에 옮기게 된다고 강조한다.
  3. 브라우저 자동화 — 크롬 확장으로 로그인된 내 브라우저를 그대로 사용: 터미널에서 브라우저 작업을 시키려면 플레이라이트(Playwright) 같은 도구를 연결해 새 브라우저 창을 띄워야 하는데, 이 창에는 로그인 정보·쿠키·세션이 전혀 없어 로그인 화면 앞에서 멈추고 인증 정보를 별도로 입력해야 한다. 더 큰 문제는 페이지를 한 번 읽을 때마다 화면 구조 전체가 컨텍스트로 전달되어 복잡한 페이지는 5만 토큰 이상을 소모하고, 클릭 몇 번에 대화 한 판의 컨텍스트가 소진되는 경우도 있다는 것. 데스크탑 앱은 크롬 확장을 통해 사용자가 이미 로그인해서 열어둔 실제 크롬 탭을 그대로 사용하며(새 창을 띄우지 않음), 컨텍스트 소모도 전체 창의 10% 미만 수준으로 줄어든다. 다만 확장 설치가 필요하고, 로그인된 브라우저를 그대로 넘겨준다는 것은 그만큼 위험도 함께 온다는 뜻이므로 결제나 게시처럼 되돌리기 어려운 작업은 직접 확인 후 실행해야 한다고 경고한다.
  4. 작업 공간 — 창 하나를 격자로 분할해 한 화면에서 완결: 데스크탑 앱은 한 창을 여러 칸으로 나눠 쓸 수 있으며, 터미널도 컨트롤+백틱(`)으로 현재 세션이 작업 중인 폴더 기준으로 한 칸에 열 수 있어 "터미널을 버리는 게 아니라 안으로 넣는" 구조다. 파일 편집기도 대화에 뜬 파일 경로를 클릭하면 앱 안에서 바로 열리고, 디스크 상의 변경 사항을 감지해 알려주며, 변경 diff를 보여주는 화면도 별도로 있다. 미리보기 칸에서는 웹 페이지·문서·이미지를 띄우거나 로컬 서버를 돌려 실제 화면으로 확인할 수 있어 "만들고, 보고, 고치는" 과정이 한 창에서 끝난다. 컨트롤+O로 도구 호출 전체를 보는 상세 모드와 결론만 보는 요약 모드를 전환할 수 있고, 커맨드+세미콜론으로 "옆 대화"를 열어 원래 대화 흐름을 방해하지 않고 곁가지 질문을 처리할 수 있다. 화자는 요즘 왼쪽은 대화, 가운데는 변경 diff, 오른쪽은 미리보기로 화면을 셋으로 나눠 쓴다고 소개한다.
  5. 예약/자동 실행 — 사람이 지켜보지 않아도 도는 기능: 정해진 시간에 자동 시작, 저장소 이벤트 발생 시 시작, 외부 신호로 시작 등 여러 트리거를 하나의 규칙에 동시에 걸 수 있고, 요금제별로 하루 실행 횟수 제한이 있다. 검사 실패 시 자동 수정을 시도하거나 검사 통과 시 자동 병합하도록 설정할 수 있으며, 완료 시 알림이 뜨고 활동 화면에서 세션 수·모델별 사용량을 집계해 볼 수 있다. 화자는 이를 통해 자신의 작업 습관을 처음으로 숫자로 확인했다고 언급. 터미널에서도 스크립트와 예약 실행으로 동일한 것을 구현할 수 있고 오히려 더 자유롭지만, 대부분의 사용자는 그 설정을 끝까지 하지 않는 반면 화면에 버튼으로 노출되면 실제로 켜게 된다는 것이 핵심 차이로 제시된다.

03기술적 맥락

데스크탑 앱의 세션 격리는 "깃 워크트리(git worktree)"라는 기존 git 기능을 앱이 자동으로 관리해주는 방식이다. 워크트리는 하나의 저장소에서 여러 브랜치를 서로 다른 폴더에 동시에 체크아웃할 수 있게 하는 git 기능으로, 원래도 존재했지만 생성·전환·정리를 수동으로 해야 해서 번거로웠다. 앱은 세션을 새로 만들 때마다 이 과정을 자동화해 별도 폴더에 격리된 작업 사본을 제공하고, 세션이 끝나면 정리까지 맡는다. 브라우저 자동화 쪽에서는 기존 방식(Playwright 등 브라우저 제어 도구로 완전히 새로운 브라우저 인스턴스를 원격 조종)과 크롬 확장 방식(이미 실행 중인 브라우저의 탭에 접근)의 구조적 차이가 핵심이다. 새 인스턴스 방식은 인증 상태가 없어 로그인부터 다시 해야 하고 페이지 전체 DOM 구조를 매 요청마다 텍스트로 직렬화해 전달해야 하므로 토큰 소모가 크지만, 확장 방식은 이미 인증된 세션의 탭 콘텐츠에 접근하므로 이 두 문제가 동시에 해소된다고 설명한다. 앱과 터미널 CLI는 동일한 실행 엔진, 동일한 규칙 파일(설정)과 스킬, 동일한 권한 체계를 공유하므로 세션을 한쪽에서 시작해 다른 쪽에서 이어가는 것도 가능하다.

04전략적 의미

첫째, 이 영상은 도구 선택 기준을 "기능 목록 비교"가 아니라 "동일 작업에 필요한 조작 횟수"로 재정의한다. 모델 전환이나 세션 이동처럼 사소해 보이는 반복 동작이 명령어 암기를 요구하면 결국 안 하게 되고, 화면에 버튼으로 노출되면 실제로 하게 된다는 관찰은 도구 설계가 사용자의 행동 습관 자체를 바꾼다는 주장으로 이어진다. 둘째, 브라우저 자동화의 인증 상태 문제는 AI 에이전트가 실무에 투입될 때 반복적으로 부딪히는 장벽인데, "새 브라우저를 원격 조종"에서 "이미 로그인된 내 브라우저의 탭에 접근"으로 전환하는 것이 토큰 비용과 준비 작업을 동시에 줄이는 실질적 해법으로 제시된다. 다만 이는 로그인 상태를 AI에 그대로 노출한다는 뜻이라, 되돌리기 어려운 액션(결제·게시)에 대한 사람의 최종 확인이라는 안전장치가 반드시 함께 따라와야 한다는 점도 명시한다. 셋째, 예약 실행 기능에 대한 관찰 — "터미널이 더 자유롭지만 사람들이 설정을 끝까지 안 한다"는 지적은, 자동화 도구의 실질적 채택률이 이론적 유연성보다 진입장벽의 낮음에 좌우된다는 일반적 원칙을 보여준다. 넷째, 화자는 앱과 터미널이 "같은 엔진"을 공유한다는 점을 반복 강조하며 양자택일이 아닌 상황별 도구 선택을 결론으로 제시하는데, 이는 세밀한 옵션 제어·스크립트 자동화·원격 서버 작업처럼 아직 앱이 커버하지 못하는 영역이 분명히 남아 있다는 균형 잡힌 인정이기도 하다.

05핵심 워크플로우 또는 비교표

영역터미널 방식데스크탑 앱 방식핵심 차이
세션 전환탭 열기/화면 분할/새 창, 명령어로 이전 대화 목록 조회 후 번호 선택상시 표시되는 세션 목록에서 클릭, 컨트롤+탭/커맨드+N 단축키창 혼동으로 인한 오조작 방지, 상태·프로젝트별 필터링
세션 격리워크트리 수동 생성·이동·정리세션 생성 시 워크트리 자동 격리·자동 정리동시 작업 시 파일 충돌 방지, 관리 부담 제거
프로젝트 전환폴더 이동 후 재실행, 경로 입력·대기목록에서 폴더 선택, 규칙 파일·스킬 자동 연동재구동 대기 시간 제거
모델 전환(영상에서 터미널 방식 별도 언급 없음, 옵션 지정으로 가능)보내기 버튼 옆 목록에서 클릭 한 번, 현재 모델 상시 표시전환이 가벼워 실제로 자주 바꾸게 됨
브라우저 자동화Playwright로 새 브라우저 인스턴스 구동, 로그인 필요, 페이지당 최대 5만+ 토큰 소모크롬 확장으로 로그인된 기존 탭 접근, 새 창 없음준비 작업 제거, 컨텍스트 소모 창 전체의 10% 미만
작업 공간창/탭을 오가며 대화·diff·미리보기를 개별 확인격자 분할로 대화·diff·미리보기를 한 창에서 동시 확인화면 전환 없이 만들고 보고 고치는 루프 완결
자동 실행스크립트 작성, 크론 등 예약 설정, 로그 별도 확인 (더 자유로움)화면 내 트리거 설정(시간/이벤트/외부 신호), 실패 시 자동 수정, 통과 시 자동 병합, 완료 알림설정 진입장벽이 낮아 실제 채택률이 높음

06활용 시나리오

  1. 여러 저장소·기능을 동시에 진행하는 개발자: 이쪽 저장소에서 신규 기능을, 저쪽에서 어제 못 잡은 버그를 동시에 진행하고 싶을 때, 세션 목록과 워크트리 자동 격리를 활용해 창 혼동이나 파일 충돌 없이 여러 작업을 병행할 수 있다.
  2. 관리자 화면·로그인 필요 서비스에서 반복 조회·게시 작업을 자동화하려는 실무자: 매일 관리자 대시보드에서 숫자를 확인하거나 로그인 후 자료를 내려받는 루틴이 있다면, 크롬 확장 기반 브라우저 자동화로 별도 인증 설정 없이 작업을 맡기되 되돌리기 어려운 액션은 직접 확인하는 워크플로우를 설계할 수 있다.
  3. 비용·성능 균형을 위해 모델을 자주 바꾸는 사용자: 설계 단계는 고성능 모델, 반복 정리 작업은 저비용 모델로 나눠 쓰고 싶을 때, 목록 클릭 한 번으로 전환되는 UI를 활용해 이 판단을 매번 실행에 옮길 수 있다.
  4. 야간·주말에 검사·수정·병합을 무인으로 돌리고 싶은 팀: 저장소 이벤트나 정해진 시간에 트리거를 걸어 검사 실패 시 자동 수정, 통과 시 자동 병합까지 설정해두고, 완료 알림과 활동 집계 화면으로 사후 확인만 하는 방식으로 CI 유사 루틴을 구성할 수 있다.
  5. 원격 서버 작업이나 다른 프로그램에 끼워 넣는 스크립트 자동화가 필요한 사용자: 이런 경우는 영상에서도 터미널이 여전히 더 빠르고 확실하다고 인정하므로, 앱과 터미널을 상황에 따라 병행하는 것이 적합하다.

07현황 및 전망

클로드 코드 데스크탑 앱은 올해 4월 화면이 전면 개편되어 세션 목록과 분할 작업 공간이 도입됐다고 소개된다. 화자는 앱에 실제 버그가 다수 존재한다고 밝히는데, 앱 실행 직후 화면이 그대로 멈추는 문제(앱 껍데기와 내부 실행 파일 버전 불일치로 발생), 삭제되지 않고 유령처럼 남아 목록에는 뜨지만 실제로는 존재하지 않는 폴더 탭 문제를 직접 겪었다고 언급한다. 윈도우 환경에서는 설치 실패, 시작 지연(약 30초), 메모리 사용량 급증(약 20기가바이트) 등의 사용자 불만이 더 많이 제기되었고 일부는 수정하지 않기로 결정되어 반발을 샀다고 전한다. 화자 본인도 화면 렌더링 오류나 재시작이 필요한 상황을 가끔 겪어 중요한 작업 전에는 앱을 새로 켜고 시작한다고 밝힌다. 그럼에도 "버그는 시간이 지나면 고쳐지지만, 손이 많이 가는 구조적 문제는 시간이 지나도 고쳐지지 않는다"는 판단 기준으로 앱 사용을 지속한다고 결론짓는다. 세밀한 실행 옵션 지정, 스크립트 기반 자동화, 원격 서버 작업은 여전히 터미널이 우위인 영역으로 남아 있다고 인정하며, 앱과 터미널이 같은 엔진·설정·스킬·권한을 공유하는 만큼 향후에도 완전 대체가 아닌 병행 사용 구도가 이어질 것으로 전망한다.

08용어 사전

용어한줄설명비유
깃 워크트리(Git Worktree)하나의 저장소에서 여러 브랜치를 서로 다른 폴더에 동시에 체크아웃하는 git 기능같은 책의 여러 편집본을 각각 다른 책상 위에 펼쳐놓고 동시에 고치는 것
플레이라이트(Playwright)코드로 브라우저를 원격 조종해 웹 페이지를 자동으로 조작·테스트하는 도구로봇 팔로 새 브라우저 창을 대신 클릭해주는 것, 단 로그인 정보는 없는 상태
크롬 확장(Chrome Extension)브라우저에 설치해 기존 브라우저 기능을 확장하는 프로그램이미 열려 있는 내 브라우저 탭에 조수를 앉혀 대신 조작하게 하는 것
컨텍스트(Context)AI가 한 번에 참고할 수 있는 대화·데이터의 총량(토큰 단위로 측정)대화 한 번에 들고 다닐 수 있는 메모지의 총 분량
옆 대화(Side Conversation)원래 대화 흐름을 유지한 채 별도 창에서 곁가지 질문을 처리하는 기능회의 중 옆 사람에게 귓속말로 따로 물어보고 본 회의 기록에는 안 남기는 것
