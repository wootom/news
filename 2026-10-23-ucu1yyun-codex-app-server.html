Codex App Server는 같은 하네스를 다양한 클라이언트에 연결해 맞춤형 에이전트 앱을 만들게 합니다.

Codex App Server로 하네스를 공유해 맞춤형 클라이언트와 에이전트 앱을 만드는 방법을 소개합니다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

01핵심 개요

  • Codex의 작업은 모델만으로 이뤄지지 않으며, 파일과 명령을 다루고 작업 범위를 정하는 하네스가 함께 작동한다.
  • App Server와 Codex Harness는 Apache 2 라이선스 오픈 소스이며, Responses API 호환 API와 LM Studio·Ollama 연결이 언급됐다.
  • JSON-RPC 스타일 프로토콜은 Codex 앱과 IDE 확장 등에 공통으로 쓰이고, 120개가 넘는 클라이언트 메시지를 제공한다.
  • 개발자 지시문·동적 도구·스레드별 샌드박스로 에이전트를 조정하며, Python SDK를 쓰거나 Codex에 구현을 요청할 수 있다.
  • App Server는 여러 스레드와 상호작용형 클라이언트를 만들 때 유용하고, codex exec는 스크립트 작업에 적합하다고 설명한다.

02핵심 주장 / 논점 구조

  • 모델은 판단하는 두뇌, 하네스는 도구와 작업 범위를 갖춘 작업실, App Server는 클라이언트와 작업실을 잇는 접수 창구로 비유한다.
  • App Server 프로토콜을 이용하면 Codex Harness 위에 직접 인터페이스를 만들고 하네스 기능과 통합할 수 있다.
  • 발표자는 두 요소가 오픈 소스이며 Apache 2 라이선스라고 설명하고, 포크해 수정할 수 있다고 말한다.
  • 다른 모델 제공자도 연결할 수 있지만, Responses API와 호환되는 API가 필요하다고 조건을 덧붙인다.

03하나의 App Server를 공유하는 클라이언트

  • JSON-RPC 스타일 App Server는 Codex 앱과 IDE 확장, VS Code 확장 등 OpenAI의 퍼스트파티 인터페이스를 구동한다.
  • 발표자는 Xcode, JetBrains, Theo의 T3 code, RemoteX 등도 같은 하네스와 App Server를 사용한다고 언급한다.
  • Claude Code에서 Codex를 쓰는 플러그인도 App Server와 하네스를 활용하며, 코드 리뷰나 작업 위임 사례가 제시된다.
  • 서로 다른 화면이 같은 작업 기반을 공유하므로 클라이언트 인터페이스를 바꾸어도 하네스를 재사용할 수 있다는 설명이다.

04메시지 흐름과 에이전트 설정

  • 클라이언트와 App Server는 메시지를 주고받으며, 스레드 시작·프로젝트와 설정 정보·응답 스트리밍(delta) 등이 이벤트로 나타난다.
  • 발표자는 Codex 앱과 App Server 사이의 실제 이벤트를 가로채 확인하는 inspector를 만들어 시연한다.
  • 클라이언트 메시지는 120개가 넘으며, 스레드와 턴 수정, goal 설정, 플러그인 목록, 파일 검색과 파일 시스템 수정 등을 포함한다.
  • developer instructions는 기존 시스템 지시문에 내용을 보태는 방식이며, 발표자는 자체 지시문을 새로 쓰기보다 이를 먼저 권한다.
  • 동적 도구와 스레드별 모델·제공자·샌드박스 설정을 활용해 도구와 파일·네트워크 접근 범위를 조정할 수 있다.

05실행 파일·버전·연결 방식

  • App Server는 Codex CLI의 일부로 제공되는 같은 바이너리이며, Codex 앱 번들에도 포함된다고 설명한다.
  • Windows 앱 번들에는 Linux용과 Windows용 바이너리가 있으며, WSL 모드에서는 Linux용을 사용한다고 발표자는 말한다.
  • 프로토콜은 버전마다 자주 바뀌므로 해당 버전의 TypeScript 바인딩이나 JSON Schema를 생성해 앱과 함께 배포하는 방식을 권한다.
  • App Server는 표준 입출력(stdio)이나 WebSocket으로 실행할 수 있으며, 적합한 연결 방식은 사용 사례에 따라 달라진다.
  • 사용자가 설치한 CLI에 의존하면 버전 차이나 변경 문제가 생길 수 있어, 사용할 하네스 버전을 앱에 포함하라고 조언한다.

06통합 방법과 Doom 시연

  • 최근 공개한 Python SDK는 생명주기 관리를 처리하고 ChatGPT 로그인 통합을 쉽게 하며 익숙한 인터페이스를 제공한다고 소개된다.
  • 발표자는 문서를 지정해 Codex에게 프로토콜 구현을 요청하는 방법도 제시하고, Visual Basic으로 Windows 네이티브 앱을 만든 사례를 든다.
  • Doom 시연은 Cloudflare의 Doom WASM 렌더러를 사용하는 Electron 앱에서 진행되며, 게임 엔진은 대부분 C로 구현됐다고 설명한다.
  • 게임 안에서 Codex를 실행하고 Electron IPC로 App Server에 연결해 대화를 주고받으며, 시연 모델은 5.5라고 밝힌다.
  • 동적 도구로 체력·방어구·무기·탄약을 제공하고, 현재 디렉터리 질문에는 발표자의 컴퓨터에서 ZShell을 호출하는 모습을 보여 준다.

07codex exec와의 차이 및 활용 당부

  • codex exec는 비대화형으로 작업을 시작하는 명령이며, CI/CD나 PR 자동 수정 같은 스크립트 작업에 적합하다고 설명한다.
  • App Server는 에이전트와 상호작용하는 클라이언트나 여러 Codex 스레드를 동시에 다루는 용도에 적합하다고 비교한다.
  • 여러 exec 호출을 직접 병렬화하는 대신 App Server에서 새 스레드 이벤트를 보내 작업을 띄울 수 있다고 말한다.
  • 새 도구는 deferred로 표시해 필요할 때 검색하도록 하고, 도구 설명이 context window를 불필요하게 차지하지 않도록 권한다.
  • 기반 지시문을 바로 대체하지 말고 developer instructions를 덧붙이는 데서 시작하라고 다시 강조한다.

08용어 사전

용어뜻
하네스(Harness)모델이 파일을 읽고 명령을 실행하며 정해진 작업 범위 안에서 일하도록 뒷받침하는 환경이다.
App ServerCodex 하네스와 클라이언트 사이에서 요청과 이벤트를 주고받게 하는 JSON-RPC 스타일 프로토콜이다.
developer instructionsCodex의 기존 시스템 지시문 위에 덧붙여 특정 앱의 사용 사례에 맞게 에이전트를 조정하는 지시문이다.
deferred tools도구를 시스템 프롬프트에 미리 넣는 대신 tool search로 필요할 때 찾도록 설정하는 방식이다.
codex execCodex에 비대화형으로 작업을 시작시키며, 스크립팅과 CI/CD 같은 자동화에 적합하다고 소개된 명령이다.
