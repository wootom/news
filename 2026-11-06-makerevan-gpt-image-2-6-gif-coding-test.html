GPT Image 2.6의 GIF 생성과 코딩 모델 조합 실험 결과 및 실패 원인 분석

GPT Image 2.6의 GIF 생성력과 코딩 모델 조합별 성능 차이 및 실패 원인 분석

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

GPT Image 2.6 공개 및 API 모델 특성

  • OpenAI가 11월 4일 공개한 Images 2.6은 프롬프트 입력 시 움직이는 GIF를 생성하며, 속도는 이전보다 50% 빨라졌다.
  • API 모델은 속도 중심의 Flare와 품질 일관성 중심의 Sunburst로 나뉘며, Flare는 품질 낮음 설정 시 6초에 한 장 생성된다.
  • 이미지 출력 단가는 100만 토큰당 30달러로 2.5 버전과 동일하며, GIF 지원에도 가격 변동이 없었다.

가상 AI 모델 출시 페이지 제작 실험 설계

  • 세상에 없는 가상의 AI 모델 'GPT-6.2 Astra'의 출시 페이지를 제작하는 과제를 설정하고, 이미지 모델과 코딩 모델 4가지 조합으로 실험했다.
  • 실험 조건은 GPT Image 2.6으로 콘셉트와 GIF를 생성한 뒤, 이를 참조해 HTML과 CSS로 실제 페이지를 코드로 재구성하는 것이었다.
  • A(Opus 5.5+Flare), B(GPT-6.1 Sol+Sunburst), C(Opus 5.5+Sunburst), D(GPT-6.1 Sol+Flare) 조합으로 Evals 서비스를 통해 동시에 실행했다.

조합별 결과물 및 성능 비교

  • Opus 5.5 조합은 콘셉트 이미지를 참조해 GIF를 생성하고 아이콘별 GIF를 따로 뽑아 결과물 재현도가 높았으며, 실행 시간은 17~18분, 토큰 사용량은 260~430만으로 많았다.
  • GPT-6.1 Sol 조합은 참조 없이 텍스트로만 GIF를 요청하고 아이콘을 묶어 처리해 실행 시간이 7~9분, 토큰 사용량이 110만으로 효율적이었으나 재현도는 낮았다.
  • 특히 C 조합(Opus 5.5+Sunburst)은 일식 이미지를 재료로 활용해 코드로 애니메이션을 구현했으며, JavaScript 없이 HTML/CSS만으로 동작하는 페이지를 완성했다.

GIF 생성 실패 원인 및 기술적 한계

  • 총 36번의 이미지 요청 중 12번이 실패했으며, 이는 프레임 수나 해상도 제한으로 인한 요청 거절이었지 그림 품질 문제가 아니었다.
  • GIF는 애니메이션 스프라이트 시트 방식으로 생성되며, 총 픽셀 상한 829만 제한으로 프레임 증가 시 해상도가 낮아지는 구조이다.
  • fal.ai 경유 시 16프레임이 상한이었으며, 832픽셀 16프레임 요청은 픽셀 상한 초과로 에러가 발생해 크기를 줄여 재요청해야 했다.

실무 적용 시 주의사항 및 권장 워크플로우

  • 페이지 내 숫자와 문구는 모두 모델이 지어낸 것이므로 실제 서비스 적용 전 인적 검수가 필수이며, 콘셉트와 코드 간 시각적 차이도 발생할 수 있다.
  • OpenAI 공식 API의 수정 엔드포인트는 GIF를 지원하지 않지만, fal.ai 경유 시 가능하므로 직접 API 사용 시 주의가 필요하다.
  • 권장 워크플로우는 콘셉트 이미지 생성, 이를 참조한 16프레임 내외 GIF 생성, 그리고 GIF를 코드화하라는 명시적 프롬프트 입력 순서이다.
