01핵심 개요

항목내용
채널빌더 조쉬
에이전트헤르메스 (Nous Research 제작)
설치 위치Slack + VPS 서버
핵심 특징셀프 임프루빙(자가 개선) + 메모리 기능 내장
데모 시나리오10가지 (회의록·견적·세금계산서·아침브리핑 등)

02핵심 내용 구조

  • 헤르메스 정체 — Nous Research의 Slack/터미널 어디서나 실행되는 에이전트
  • 셀프 임프루빙 — 매일 학습으로 점점 회사에 최적화
  • 회사 운영 레이어 — Slack·Notion·ERP·이메일을 통합 컨텍스트로 읽음
  • 승인 구조 — 맥락 읽기 → 도구 실행 → 사람 승인 3단계
  • 데모 10종 — 아침 브리핑 / 견적서 / 세금계산서 / 회의록 자동화 등
  • 보안 권고 — VPS 격리 · 토큰 비노출 · 권한 분리 · 로그 관리

03기술적 맥락

  • Nous Research — 오픈소스 AI 연구조직, 헤르메스 시리즈 모델 공개
  • Slack 봇 통합 — 한 줄 입력 → 헤르메스가 회사 데이터 통합 응답
  • 컨텍스트 적재 우선 — 회의록·이메일 모두 Slack에 모아 학습 자료화
  • VPS 호스팅 — 회사 외부 VPS에 헤르메스 설치 → 격리 환경 권장
  • MCP·도구 연동 — 견적서·세금계산서 등 사내 도구 API와 연결
  • 메모리 영속성 — 매번 새 채팅 아닌 누적 컨텍스트 활용

04전략적 의미

  • 회사 운영 레이어 추가 — 직원이 아닌 "운영 레이어"로 포지셔닝
  • AI 네이티브 컴퍼니 — 데이터 적재 → 에이전트 활용이 표준 전환
  • 점진적 확장 — 회의록 자동화부터 시작해 단계적으로 자동화 범위 확대
  • 인력 대체 아님 — 직원 대체 아닌 의사결정·복잡 업무 보조
  • 거버넌스 필요 — 보안·권한·승인 설계가 도입 성공의 핵심

05핵심 워크플로우

단계내용
1. 회사 맥락 적재회의록·이메일·Slack 메시지를 채널에 누적
2. 에이전트 설치VPS에 헤르메스 설치 → Slack 봇 연동
3. 도구 연동견적서·세금계산서·ERP API 등록
4. 시나리오 정의아침 브리핑·자동 회신 등 트리거 설정
5. 승인 게이트중요 작업은 사람 승인 후 실행
6. 자가 개선매일 사용 데이터로 응답 품질 개선

0610대 활용 시나리오

  • 아침 우선순위 브리핑 — "오늘 대표가 봐야 할 일" 자동 정리
  • 견적서 작성 — 거래처·상품 정보 기반 자동 견적 문서 생성
  • 세금계산서 발급 — 규격 입력으로 자동 발급
  • 팀원별 할 일 제안 — 각 직원 업무 분배 제안
  • 회의록 → 견적서 자동화 — 회의록 업로드 → 견적 초안 자동 생성
  • 거래처 히스토리 회상 — 과거 대화·견적 검색
  • 반복 보고 자동화 — 정해진 시간에 자동 보고서 생성
  • 이메일 응답 초안 — 회사 톤·맥락 반영한 초안 작성
  • 프레젠테이션 작성 — 클라이언트 맞춤 슬라이드 초안
  • 운영 알림 — 누락 작업·중요 일정 능동 알림

08현황 및 전망

  • 셀프 임프루빙 트렌드 — 매일 학습하는 에이전트가 차세대 표준
  • MCP 생태계 — Slack·Notion·ERP 등 표준 커넥터 확산
  • 거버넌스 산업화 — AI 보안·승인 설계 컨설팅 시장 형성 전망
  • 완벽 환상 경계 — 헤르메스도 아직 미완 — 점진적 도입 권장
  • 회사별 맞춤화 — 동일 도구라도 적재 데이터에 따라 결과 차별화
