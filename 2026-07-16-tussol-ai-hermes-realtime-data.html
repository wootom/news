01핵심 개요

항목내용
채널투쏠ㅣAI 에이전트
주제n8n과 헤르메스(Hermes) 에이전트를 SSH 터널로 연결해 실시간 웹훅(Webhook) 자동화 워크플로우 구축
한 줄 요약n8n의 SSH 노드로 호스팅어 서버 안 도커(Docker) 컨테이너의 헤르메스를 호출해, 신호가 들어올 때마다 24시간 자동 응답하는 에이전트 파이프라인을 만든다
핵심 결론 1헤르메스 단독 웹훅 설정은 인증·포트·라우팅·터널 등이 복잡하지만, 이미 쓰던 n8n의 SSH 노드로 우회하면 훨씬 간단하다
핵심 결론 2헤르메스는 도커 컨테이너로 보호돼 있어, 서버가 아니라 컨테이너에 직접 명령어를 넣어야 호출된다
핵심 결론 3호스팅어 VPS(가상 서버)를 상시 켜 두면 개인 PC를 켜 둘 필요 없이 24시간 자동 에이전트 운영이 가능하다

02핵심 내용 구조

발표자는 그동안 반복 작업은 크론잡(cron job, 예약 실행) 등으로 쉽게 처리했지만, "실시간 신호가 들어올 때 즉시 반응하는 웹훅"을 헤르메스·클로드 코드·코덱스 같은 에이전트로 어떻게 붙일지 고민해 왔다고 밝힌다. 웹훅 기능은 원래 존재했지만 직접 세팅이 너무 복잡해, 이미 사용 중이던 n8n(노코드 워크플로우 자동화 도구)과 결합하는 방식을 제안한다.

  • 문제 인식: 헤르메스를 웹훅으로 붙이려면 인증, 포트 설정, 라우팅, 터널 등을 직접 구성해야 해 복잡하다. 또한 헤르메스가 localhost(로컬호스트, 내 컴퓨터 내부 주소) 안에 있어 외부 서비스와 연결이 안 된다.
  • 해결 아이디어: n8n에 있는 SSH 노드를 활용. SSH는 "다른 컴퓨터에 명령어를 대신 쳐 주는 통로"로, 두 서버 사이에 연결 통로를 만들어 준다.
  • 연결 절차: 레일웨이(Railway)에서 n8n을 돌리고, 호스팅어(Hostinger) VPS에 헤르메스를 설치한 뒤, n8n SSH 노드에 서버 IP·포트·유저네임(root)·루트 패스워드를 입력해 두 서버를 연결.
  • 도커 문제 해결: 서버에 바로 명령을 보내면 "헤르메스 없음" 오류 발생. 헤르메스가 도커 컨테이너 안에 설치돼 있기 때문. docker ps로 컨테이너 이름을 확인한 뒤, 해당 컨테이너에 질문을 넣는 방식으로 호출 성공.
  • 실전 데모: 탈리(Tally) 폼 → n8n 웹훅 수신 → Set 노드로 이름·이메일·취미 정제 → 헤르메스에 CRM(고객관계관리) 정보 전달 → 이메일 초안 자동 생성.

03기술적·시장 맥락

핵심은 "자동화(단순 반복)"와 "에이전트 워크플로우(맥락 판단·생성)"의 결합이다. 기존에는 솔라피(Solapi) 같은 도구로 알림 메시지를 예약 발송하는 정도의 단순 자동화만 했지만, 웹훅에 에이전트를 붙이면 고객이 폼을 제출하는 즉시 뒤에서 헤르메스가 CRM 적재, 리포트 작성, 메시지 예약까지 처리할 수 있다. 24시간 상시 구동을 위해 개인 PC 대신 호스팅어 VPS를 활용하는 점이 실용적 포인트다.

또한 -q 명령 옵션을 쓰면 헤르메스 창에 직접 들어가지 않고 밖에서 바로 질문할 수 있으며, 답변만 출력하게 할 수도 있다고 설명한다. 슬랙(Slack) 연동 시에는 헤르메스를 태그하지 않아도 문자 하나로 자동 응답하도록 세팅해 둘 수 있다.

04전략적 의미

이 워크플로우는 "실시간 트리거 → n8n 수신 → SSH 통로 → 헤르메스/클로드 코드 실행 → 결과 반환"이라는 재사용 가능한 패턴을 제시한다. 웹훅·카톡·스케줄 등 다양한 트리거를 n8n에서 받아 뒤단 에이전트로 넘길 수 있어, 개인·소규모 운영자도 상시 가동 AI 에이전트를 저비용으로 구축할 수 있는 길을 연다.

06활용 시나리오 / 투자 시사점

  1. CRM 자동 응대: 고객이 문의 폼을 제출하면 헤르메스가 즉시 정보 정리·이메일 초안 작성·CRM 적재까지 수행.
  2. 상시 가동 알림 에이전트: 호스팅어 VPS를 켜 두어 개인 PC 없이 24시간 신호 대기·자동 처리.
  3. 슬랙 기반 즉시 응답 봇: 탈리 폼 결과를 슬랙에 올리고, 태그 없이도 헤르메스가 자동으로 작업 실행.

07현황 및 전망

발표자는 24시간 구동 에이전트를 최근 집중적으로 실험 중이며, 이번 영상은 "웹훅으로 헤르메스를 받아 돌리는" 기초 워크플로우를 소개하는 단계라고 밝혔다. 향후 더 정교한 트리거 기반 에이전트 워크플로우를 계속 소개할 계획이다.
