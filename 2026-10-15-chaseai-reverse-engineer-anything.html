Rhea는 앱별 분석 도구와 증거 기반 질의로 기존 소프트웨어를 맞춤형 구현의 설계도로 바꾼다

Rhea는 앱별 도구와 근거 기반 분석으로 소프트웨어를 맞춤형 구현의 설계도로 바꾼다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

01핵심 개요

  • Rhea는 데스크톱 앱·웹사이트 등 20종이 넘는 소프트웨어를 분석해 맞춤형 구현을 위한 구조와 작동 원리를 정리한다.
  • 영상은 저장소가 20만 개가 넘는 별을 받았고, 녹화 시점에는 206,000개라고 설명한다.
  • 시연 대상 Whisperflow는 Electron 앱과 Windows·Mac 기능을 다루는 네이티브 헬퍼로 나뉘어 분석된다.
  • 네이티브 헬퍼 분석에는 Ghidra를 써 27분 동안 56,000개가 넘는 함수를 식별했고, JavaScript 분석은 7분간 진행됐다.
  • Claude와 Rhea는 근거를 확인하며 질문과 답변을 주고받고, 최종적으로 새 맞춤형 앱을 만들기 위한 플레이북을 만든다.

02핵심 주장 / 논점 구조

  • Rhea의 목적은 이미 존재하는 소프트웨어를 그대로 복제하는 데 그치지 않고, 구조를 파악해 사용자의 생활·업무에 맞는 새 버전을 만드는 것이다.
  • Rhea는 애플리케이션 유형에 따라 적절한 도구와 스킬을 선택하는 MCP 도구로 소개된다.
  • 영상은 분석 요청, 앱 구조 매핑, Claude와 Rhea의 질의응답, 새 구현을 위한 플레이북 작성의 네 단계로 작동 방식을 설명한다.

03분석 요청과 근거가 표시되는 주장

  • 사용자는 Claude Code에 Rhea 설치를 요청한 뒤, Whisperflow를 구성 요소별로 분석해 달라는 식의 프롬프트를 보낼 수 있다.
  • Rhea는 플레이북을 불러오고 대상에 맞는 도구를 고른 다음, 앱의 작동 방식에 관한 질문과 요약을 만든다.
  • 각 분석 주장은 확인됨(seen), 추론됨(inferred), 알 수 없음(unknown)으로 표시되며 확인 가능한 경우 코드 근거가 함께 제시된다.
  • Whisperflow에서는 마이크 작동, 단축키, 녹음 정리, 텍스트 입력과 전달 과정 등이 조사 항목으로 다뤄진다.

04Whisperflow 구조와 분석 도구 선택

  • 분석 과정에서 Whisperflow는 Electron 앱과 Windows·Mac에서 키 입력 등을 처리하는 네이티브 헬퍼, 두 부분으로 구분됐다.
  • Claude가 직접 파악하기 어려운 헬퍼에는 기계어 분석 도구인 Ghidra가 사용됐다.
  • 영상은 Ghidra가 기계어를 어셈블리로 바꾸고, 이를 바탕으로 의사 코드 형태의 설명을 만드는 도구라고 소개한다.
  • Electron 앱 쪽에는 JavaScript 분석기가 사용됐으며, Claude도 저장소의 스킬 없이 코드를 직접 읽을 수 있었다.

05Ghidra와 JavaScript 분석의 수치

  • Ghidra 분석에는 27분이 걸렸고, Whisperflow 헬퍼에서 56,000개가 넘는 함수를 식별했다.
  • Electron 앱의 JavaScript 분석은 7분이 걸렸으며, 1,500개보다 조금 적은 항목을 찾았다.
  • 영상은 Ghidra가 NSA에서 만들어졌으며 오픈소스라고 설명한다.
  • 분석 결과는 구성 요소, 문자열, 웹 주소, 호출 관계 등을 담은 맵으로 정리돼 이후 질문에 활용된다.

06Claude와 Rhea의 질의응답 및 사례 결과

  • 매핑 뒤 Claude는 작고 구체적인 질문을 던지고, Rhea는 사실과 근거를 붙여 답하는 조사 루프가 진행된다.
  • 헬퍼에 관한 기계어 수준 질문에는 Rhea 호출 13회로 필요한 정보를 얻었다고 영상은 설명한다.
  • Electron 앱에 관한 질문에서는 Rhea 호출 5회와 자체 검색 40회가 이뤄졌고, Claude가 직접 코드를 살펴보기도 했다.
  • 조사가 끝나면 작동 방식과 정보의 근거를 정리해 사용자가 새 코드를 작성할 수 있는 플레이북으로 이어진다.

07도구별 스킬의 의미와 활용 방향

  • 영상은 Claude Code만으로 역공학을 시도하는 것보다, 유형별 절차와 도구가 정리된 저장소를 이용하는 편이 수월하다고 주장한다.
  • Go 바이너리, Rust 바이너리, SQLite 데이터베이스 등 서로 다른 대상에 맞춰 분석 방법을 선택하도록 설계됐다고 설명한다.
  • 따라서 영상이 제안하는 핵심 질문은 무엇을 복제할지가 아니라, 분석을 바탕으로 무엇을 맞춤화해 새로 만들지다.
