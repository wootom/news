Codex에서 Grok·Kimi3도 쓴다 — Open Codex 프록시와 Composer 2.5 (배움의 달인)

Open Codex라는 오픈소스 프록시 도구를 설치해, Codex 앱 하네스 안에서 Grok·Kimi3·DeepSeek·MiniMax 등 타사 모델을, 반대로 Claude Code 안에서 GPT 모델을 교차 사용하는 방법을 시연한다. 특히 xAI의 Grok Composer 2.5 Fast 모델로 프레젠테이션 자료를 생성하니 기존 Codex 모델 13분 56초 대비 9분 12초로 약 4분 빨라져 속도 우위를 확인했다. 하나의 하네스 장점을 유지하면서 저렴·고속 모델로 갈아끼우는 효율화가 핵심이다.

02핵심 내용 구조 — 하네스와 모델의 분리

기본적으로 Claude Code는 Claude 모델(Sonnet·Opus·Fable)만, Codex 앱은 GPT 모델만 쓸 수 있다. Open Codex는 이 제약을 프록시로 우회해, 하네스(도구)와 모델을 분리한다. 즉 Codex의 UI·플러그인 생태계를 그대로 쓰면서 내부 실행 모델만 Grok이나 Kimi3로 바꿔 끼울 수 있다.

03기술적 맥락 — 설치와 GUI 구성

npm으로 설치 후 ocx init → ocx start → ocx gui로 실행하고 localhost:10100에서 GUI에 접속한다. 대시보드에서 '섀도우 호출 가로채기'(스레드 제목·커밋 메시지 등 보조 작업)를 저렴·고속 모델(예: Composer 2.5 Fast)로 지정해 토큰 비용을 절감한다. 프로바이더 탭에서 OpenAI·xAI·DeepSeek·MiniMax·Cerebras 등을 API 키로 등록한다.

04핵심 워크플로우 — 모델 교차와 계정 전환

Codex 앱을 완전히 재실행하면 모델 선택창에 등록한 모든 모델이 나타나 실시간 전환이 가능하고, 이전 대화 맥락을 유지한 채 모델만 바꿔 이어간다. OpenAI 계정을 여러 개 등록하면 사용량이 임계값(약 90%)에 도달할 때 맥락을 끊지 않고 자동으로 다음 계정으로 전환된다. Claude Code에서는 GPT 5.6 Terra 등을 등록해 Claude의 스킬·하네스를 그대로 활용할 수 있다.

05활용 시나리오

Codex의 '사이트(site)' 플러그인 도구로 문서를 첨부해 PPT용 사이트를 생성하되, 실행 모델을 Grok Composer 2.5 Fast로 지정하면 링크 공유형 프레젠테이션을 빠르게 만들 수 있다. 발표자료 자동 생성, 저비용 보조작업 처리, 다계정 무중단 작업 등에 유용하다.

06현황 및 전망

Claude OAuth는 타사 프록시 재사용 시 계정 정지 위험이 경고되어 발표자는 등록을 보류했다. Orca(멀티 오케스트레이션)가 하나의 작업을 여러 모델로 분산한다면, Open Codex는 하나의 하네스에서 모델만 교체하는 접근으로 서로 결이 다르다. 저렴·고속 모델의 실전 투입 여지가 커지는 흐름을 보여준다.
