사람은 "무엇을 저장할지"만 결정하면 된다.

1
왜 Obsidian + Claude Code인가

Obsidian은 뛰어난 저장소지만 노트를 체계적으로 연결하고 유지하는 작업이 번거롭다. Claude Code는 자연어 명령으로 파일을 생성·수정할 수 있는 AI CLI다. 이 둘을 연결하면 "두뇌(AI) + 창고(Obsidian)"가 된다.

2
CLAUDE.md — AI에게 주는 운영 설명서

Claude Code는 세션 시작 시 볼트 루트의 CLAUDE.md를 자동으로 읽는다. 이 파일에 규칙을 적어두면 AI가 매번 같은 방식으로 동작한다.

  • 폴더 구조 정의: 어디에 무엇을 저장하는지 명시
  • 금지 사항: 10-Sources/ 수정 금지, status: active는 사람만 변경
  • frontmatter 표준: title, type, tags, status 필드 형식 지정
  • 세션 체크리스트: 시작 시 읽어야 할 파일 순서 명시
## 세션 시작 체크리스트
1. CLAUDE.md 읽기
2. 20-MOC/index.md 읽기 (전체 노트 파악)
3. 99-System/log.md 최근 5개 항목 확인
4. 요청 유형 파악 (Ingest / Query / Lint)
3
3가지 핵심 사용 패턴

📥 Ingest

URL·메모·파일을 주면 요약 + frontmatter + 링크까지 자동 생성. YouTube, 웹 기사, PDF 모두 처리.

🔍 Query

"KV Cache 내 노트 찾아줘" → 내 볼트 내용 기반으로 답변. 인터넷이 아닌 나만의 지식 DB 활용.

🏥 Lint

고아 노트, 모순 내용, 오래된 정보 자동 탐지. 삭제·병합·업데이트 권고만 하고 실행은 사람이 결정.

5
초보자가 막히는 4가지 포인트

⚠️ AI가 뭔가 잘못 수정

CLAUDE.md에 금지 사항을 명시하면 해결. "10-Sources/ 수정 금지" 한 줄로 방지 가능.

⚠️ 노트가 많아 못 찾겠다

20-MOC/index.md 정기 갱신을 요청. Ingest마다 자동 업데이트 설정 권장.

⚠️ AI가 뭘 했는지 모른다

99-System/log.md를 append-only로 운영. 모든 세션 이력이 누적 기록됨.

⚠️ 다음 세션에 맥락 소실

세션 시작 체크리스트(CLAUDE.md + index.md 읽기)를 CLAUDE.md에 명시하면 해결.

6
알고 써야 하는 한계
  • 비용 발생: Claude Code는 API 토큰 소모 — 대량 Ingest 시 비용 계산 필요
  • 자동화의 역설: 규칙 없이 쓰면 잘못된 노트가 대량 생성될 수 있음
  • status 관리 필수: LLM 생성 노트는 반드시 사람이 검토 후 status: active로 변경
  • 백업 필수: Claude Code가 파일을 편집하므로 git 또는 클라우드 백업 설정 필수
7
