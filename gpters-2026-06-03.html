01LLM(Large Language Model) 성능 및 토큰 관리

  • 정보 정제 파이프라인의 중요성: 불필요한 입력 토큰(bloat)이 LLM 성능을 저하시킬 수 있으며, 정보 정제 파이프라인을 구축하여 성능 향상을 이룰 수 있다는 경험 공유가 있었습니다. 특히 Gemini 모델에서 이러한 문제가 두드러지는 것으로 체감된다고 언급되었습니다.
  • LLM의 똑똑함과 불필요한 정보: AI가 불필요한 정보를 덜 읽을수록 더 똑똑해질 수 있다는 원리에 대한 논의가 있었습니다.
  • Claude 모델 버전별 성능 체감:

* Claude 4.7 버전이 멍청해졌다는 평이 있었고, 4.8 버전은 4.6보다 프로세스 단위로 일을 더 잘하고 보고를 더 잘하는 느낌을 주지만, 작업 과정이 길어지거나 컴팩트하는 데 시간이 더 오래 걸리는 것 같다는 의견이 제시되었습니다. * 4.8 버전에서는 지침을 추가하니 4.6보다 나아지고 토큰 소모량도 줄었다는 경험담이 있었습니다. * 코클 터미널 사용 경험으로는 코워크나 컴퓨터 사용 체감은 모르겠으나, Claude 4.7 문제 이후 Codex를 주력으로 사용하게 되었다는 의견도 있었습니다.

02터미널 추천 및 사용 경험

  • Waveterm 추천: Windows 사용자들에게 Waveterm이 파일 읽기 및 폴더 탐색이 가능하여 편리하다고 추천되었습니다.

* Waveterm GitHub 링크: https://github.com/wavetermdev/waveterm

  • AI 기능 연동 관련 질문: Waveterm의 AI 기능 연동(OAuth)이 어렵고, AI 기능 제외 시 wmux 대비 장점이 있는지에 대한 질문이 있었습니다.
  • Claude를 통한 터미널 활용: Claude에 문의하여 터미널을 설치하고 사용해봤는데 만족스러웠다는 경험담이 공유되었습니다.

03AI 도구 (ChatGPT, Codex, Hermes, Claude) 사용 관련 문제 및 현황

  • ChatGPT 계정 정지 문제: 아동 성착취 활동 규정 위반으로 ChatGPT 계정이 갑자기 정지된 사례가 공유되었으며, 이전에 Codex Goal만 돌려둔 상태였다는 점이 언급되었습니다. 소설 작가들 사이에서 유사한 억울한 경험이 있다는 정보도 공유되었습니다.

* Discord 계정 정지 사례: 유사하게 Hercules Codec 연결 후 스팸 게시글 집중 게시로 Discord 계정이 정지되었다가 1주일 만에 복구된 사례도 있었습니다. * 해결책: OpenAI 측에 해명 메일(로그 첨부)을 보내는 것을 해결책으로 제안했습니다.

  • Codex 사용량 및 토큰 소모:

* "자동 개발" 기능을 켜 놓으면 12시간에 주간 할당량의 30%를 사용할 정도라고 언급하며 높은 토큰 소모를 지적했습니다. * Codex Goal을 많이 사용하면 토큰 소모가 빠르다는 의견이 있었고, 특히 코딩 작업을 시키면 팍팍 줄어든다는 경험담도 공유되었습니다. * Codex의 X2 토큰 혜택이 6월 1일부터 없어진다는 정보가 있었습니다.

  • Hermes 및 OpenAI, Claude 사용 현황:

* Hermes, Codex, OAuth 기능이 잘 작동하고 있는지에 대한 질문이 있었습니다. * Hermes를 오픈클론 복구용으로 설치했으나 장점을 아직 잘 모르겠다는 질문에, 오픈클론 사용자가 Hermes보다 2배 이상 많다는 정보가 공유되었습니다. * 모바일에서 맥미니 작업 세션을 그대로 사용할 수 있게 된 후 Hermes 다운이 훨씬 잘 되는 것 같다는 의견이 있었습니다. * Hermes에서 Opus OAuth가 가능하다는 소식이 공유되었습니다. ChatGPT의 딱딱한 응답보다 Opus가 친근한 느낌을 준다고 언급되었습니다. * 하지만 약관 위반의 위험이 있어 계정 정지 가능성이 있다는 우려도 제기되었습니다.
