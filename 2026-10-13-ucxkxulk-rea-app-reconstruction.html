REA는 설치 앱만 분석해 23분 만에 주요 기능을 재현했지만 내부 설계와 예외 처리는 놓쳤다.

REA는 설치 앱의 기능을 상당 부분 재현했지만, 근거 해석 오류가 내부 설계 차이로 이어졌다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

01핵심 개요

  • REA는 새 디컴파일러가 아니라 기존 분석 도구를 에이전트가 호출하고 결과와 근거를 기록하게 하는 연결 계층이다.
  • 소스와 인터넷을 차단한 실험에서 에이전트는 설치된 Electron 앱과 샘플 자료 13개를 조사했다.
  • 클론은 23분 만에 주요 자료 관리 흐름을 구현했지만 폴더·컬렉션 복원 등 일부 기능은 빠졌다.
  • 평가 점수는 100점 만점에 74점이었고, 근거 24건 중 22건은 원본과 맞았으며 한 건은 틀렸다.

02핵심 주장 / 논점 구조

  • 영상의 초점은 앱을 완벽히 복제하는 것보다, AI 에이전트가 원본 소스 없이 설치된 앱을 얼마나 이해하는지 확인하는 데 있다.
  • REA는 기능을 코드 수준으로 해석하도록 돕지만, 남겨진 근거가 있다고 해서 에이전트의 해석까지 반드시 맞는 것은 아니다.
  • 실험에서 주요 기능과 화면·데이터 구조는 상당 부분 재현됐지만 예외 처리와 내부 설계에는 차이가 확인됐다.
  • 결과는 한 번의 실험이므로 REA의 일반적인 성능이나 REA만의 효과로 확대해 해석할 수 없다고 밝혔다.

03REA의 도구 연결과 근거 기록

  • REA는 코딩 에이전트가 역공학 도구를 MCP나 명령줄로 호출하고, 분석 결과를 추적 가능한 형태로 정리하도록 연결한다.
  • 네이티브 실행 파일은 Ghidra·Hopper·IDA 같은 기존 엔진으로 분석하고, Electron·JavaScript 앱은 번들과 모듈 관계를 읽는다.
  • 실행 중인 앱과 웹페이지를 관찰하는 기능도 있으며, REA가 새로운 디컴파일러를 만든 것은 아니라고 설명한다.
  • 에이전트가 판단에 사용한 사실과 출처 기록은 ‘에비던스’로 남지만, 그 해석이 맞는지는 별도로 검증해야 한다.

04Serpent 앱과 실험 설계

  • 대상은 Electron 기반 오픈소스 자료 관리 앱 Serpent로, Eagle 라이브러리 가져오기와 원격 저장소 연결 구조가 있었다.
  • 패키징한 앱은 약 618MB였고, 샘플 라이브러리에는 이미지·영상 13개와 태그 세 종류를 넣었다.
  • 분석 에이전트에는 패키징된 앱과 REA만 제공하고 원본 프로젝트 폴더, 웹 검색, 기타 조회를 금지했다.
  • 작업 시간 상한은 75분이었으며 시간, 도구 호출 수, 에비던스 수, 평가 점수를 측정했다. 결과는 한 번 실행한 사례다.

05분석에서 클론 구현까지

  • 에이전트는 앱 번들에서 Electron 앱임을 파악하고, JavaScript 정적 분석과 실제 앱 실행 관찰을 함께 진행했다.
  • 정적 분석으로 창 생성 지점과 메인·렌더러 프로세스 사이의 브리지 및 IPC 명령을 찾았고, 실행 중에는 화면과 파일 구조를 조사했다.
  • 라이브러리는 폴더 구조였고, 검색에는 SQLite FTS5 트라이그램 인덱스가 쓰이며 파일명과 메모를 검색한다는 점을 확인했다.
  • 23분 만에 만든 클론은 Node.js HTTP 서버와 SQLite, 프레임워크 없는 HTML·JavaScript로 구성됐고 외부 패키지는 설치하지 않았다.
  • 클론은 여섯 파일, 949줄이었으며 라이브러리 열기, 가져오기, 태그·검색·정렬, 메모 수정, 휴지통 이동과 복원을 구현했다.

06평가 점수와 추가 기능 실험

  • 평가는 100점 만점에 74점이었다. 주요 기능은 30점 중 25점, 화면 구성과 데이터 모델은 각각 20점 중 16점이었다.
  • 예외 상황 처리는 15점 중 8점, 코드 구조 유사도는 15점 중 9점으로 상대적으로 낮았다.
  • 원본은 중복 파일을 식별하고 이름이 겹치면 사용자에게 묻지만, 클론은 중복 파일을 다시 등록하고 GIF도 받아들였다.
  • 에이전트는 IPC 채널 이름이 실행 중 조합된다고 잘못 판단했다. 원본에서는 채널 이름이 컴파일 시점 상수였고 명령이 타입 지정 채널 하나로 전달됐다.
  • 추가 요청으로 문단과 자료의 태그·파일명·메모를 대조해 관련 자료를 순위화하는 패널을 6분 만에 만들었고, 새 모듈은 73줄이었다.

07활용 범위와 권리·검증 유의점

  • 영상은 문서 없는 오래된 업무 시스템, 문서와 동작이 다른 API, 자체 파일 형식의 데이터 이전, 회귀 테스트 작성 등을 활용 사례로 들었다.
  • 분석 대상은 다른 회사의 상용 앱일 필요가 없으며, 자신이 만들었거나 운영 권한이 있는 프로그램이 더 적절할 수 있다고 설명했다.
  • 저작권법 제101조의3 제1항 제6호와 제101조의4를 언급하며, 조사 목적·범위에 따라 적용이 달라질 수 있다고 말했다.
  • Eagle·Raycast·CleanShot X·Paste의 약관을 10월 12일 확인했을 때 모두 역공학 금지 조항이 있었다고 밝혔다.
  • 분석 권한, 도구·원본 라이선스, 코드·디자인 자산 사용, 개인정보, 공개 자료의 근거 등을 확인하고 에이전트의 추론을 관찰 사실과 구분해야 한다.
