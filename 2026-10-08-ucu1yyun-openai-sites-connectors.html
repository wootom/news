OpenAI Sites의 핵심은 배포가 아닌 커넥터 권한 상속과 팀별 데이터 필터링

OpenAI Sites는 배포가 아닌 커넥터 권한 상속과 팀별 데이터 필터링이 핵심

01핵심 개요

  • Sites는 2026년 7월 9일 공개 베타 시작, Free/Go 요금제 미지원, 엔터프라이즈 전용 기능 포함
  • 커넥터 연동 시 조직·워크스페이스·방문자 3중 승인 필수, 기본값은 모두 꺼짐
  • 방문자 권한 범위 내에서만 데이터 읽기 가능, 쓰기 및 배경 예약 작업은 제한됨
  • D1(10GB)·R2(한도 없음) 제공, 데이터 레지던시 미지원, 배포 URL은 프로덕션 전용
  • 2026년 9월 29일 릴리스로 Plus/Pro에서 반복 일정 자동화 기능 추가

02핵심 주장 / 논점 구조

  • 영상의 핵심은 사이트 기능 자체가 아니라 커넥터를 통한 권한 관리 구조
  • 판단 기준은 공식 문서이며, 화면 데모와 문서 보장 사항을 엄격히 구분
  • KEEP: 커넥터 상속 구조, MODIFY: 숫자, DISCARD: 구버즈 실시간 연결 불가 안내

03커넥터 연동과 권한 승인 구조

  • Notion·Slack 등 약 60개 커넥터 지원, 방문자가 직접 연결해 자기 데이터만 노출
  • 사이트가 커넥티드 앱 읽기 위해 조직·워크스페이스·방문자 3중 승인 필요
  • 승인 설정 기본값은 모두 꺼짐이며, 엔터프라이즈 워크스페이스 전용 기능
  • 사이트가 워크스페이스 비공개일 때만 동작하며, 개인 요금제에서는 사용 불가

04팀별 데이터 필터링과 읽기 전용 원칙

  • 사이트 공유 시 각 방문자의 커넥터 권한을 이어받아 팀별 맞춤 콘텐츠 제공
  • Codex·아이덴티티 팀 등 방문자 소속에 따라 해당 팀 데이터만 가져옴
  • 기본은 읽기 전용이며, 쓰기는 별도 설정과 방문자 명시적 동작 필요
  • API 키 관리 없이 연결되며, 배경 예약 작업은 수행할 수 없음

05인프라 구성과 배포 제약 조건

  • D1 데이터베이스 10GB, R2 버킷 고정 한도 없음, 데이터 레지던시 미지원
  • 배포 URL은 전부 프로덕션이며, 버전을 저장·검토한 뒤에만 배포 가능
  • 공동 편집자 설정 및 MCP 플러그인 호스팅 기능 공식 문서에 명시
  • 사이트 내 인퍼런스 위젯은 실험 단계로 공식 기능 목록에 포함되지 않음

06실무 활용 사례와 자동화 기능

  • 인시던트 관리 대시보드, 데이터 웨어하우스 연결, 재무·데이터 팀용 대시보드
  • Spotify 플레이리스트 자동화: 매주 월요일 8시 Reddit 인기 음악 기반 생성
  • 2026년 9월 29일 릴리스로 Plus·Pro 요금제에서 반복 일정 자동화 가능
  • Codex로 만든 소프트웨어 호스팅, 플러그인 배포, 평가 실행 등 다양한 용도

07분석 기능 한계와 AI 사용 윤리

  • 기본 분석은 방문 수·트래픽 수준이며, 엔터프라이즈 소유 사이트에서만 제공
  • 변화 원인 조사 등 심층 분석은 Sites 밖에서 직접 측정해야 함
  • AI가 사용자를 사칭해 이메일·Slack에 글을 쓰는 행위는 명확히 금지
  • AI가 쓴 글에 사용자 이름을 붙여 발송하는 것은 선을 넘는 행위
