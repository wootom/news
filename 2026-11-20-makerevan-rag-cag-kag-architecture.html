RAG·CAG·KAG는 세대별 기술이 아니라 서로 다른 문제를 해결하는 독립된 축이다

RAG·CAG·KAG는 세대별 기술이 아닌 서로 다른 문제를 해결하는 독립된 축으로, 실무 적용 시 지식 규모와 질문 형태에 따라 혼합 설계해야 한다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

RAG, CAG, KAG의 본질적 차이와 문제 정의

  • 세 기술은 위아래 관계가 아닌 서로 다른 문제를 해결하며, RAG는 외부 지식 검색, CAG는 안정적 지식 재사용, KAG는 관계 추론에 초점을 둔다.
  • 각 기술은 엔지니어링 트레이드오프가 달라 데모 단계와 실제 운영 환경에서의 적용 전략이 완전히 구분된다.

RAG의 작동 원리와 실제 운영 시의 5가지 난제

  • 2020년 메타 연구진이 제안한 RAG는 문서를 청킹하고 임베딩하여 벡터 DB에 저장한 뒤, 질문과 유사한 청크만 프롬프트에 결합하는 방식이다.
  • 실무에서는 청크 분할 오류, 검색 실패 원인 분석, 리랭킹 비용, 낡은 문서 버전 문제, 최종 답 검증의 5가지 단계별 측정이 필수적이다.
  • 관련 문서 검색 성공과 사실적 정확성, 그리고 모델의 최종 답변 정확성은 서로 독립적으로 측정해야 하는 별개의 지표이다.

CAG의 메커니즘과 적용 한계 및 비용 구조

  • 2024년 12월 논문 'RAG를 하지 마라'는 지식이 작고 안정적일 때 문서 전체를 문맥에 올리고 KV 캐시를 재사용하여 검색 단계를 제거하는 방식을 제시한다.
  • CAG는 임베딩과 벡터 DB가 불필요하지만, 문맥 창 초과, 긴 문맥 중앙 정보 처리 정확도 저하, 캐시 만료로 인한 반복적 쓰기 비용이 주요 제약이다.
  • 앤트로픽 기준 캐시 읽기 입력 토큰은 기본 단가의 10분의 1이지만, 초기 캐시 생성 비용이 높고 기본 유지 시간이 5분으로 설정되어 있다.

KAG의 멀티홉 추론 구조와 성능 향상 결과

  • 2024년 9월 앤트 그룹 논문은 벡터 유사도의 한계를 극복하기 위해 엔티티와 관계를 지식 그래프로 구조화하여 멀티홉 추론을 수행한다.
  • KAG는 언어 모델 친화적 표현, 그래프-원문 상호 인덱스, 하이브리드 추론 엔진, 의미 정렬, 모델 강화의 5가지 구성 요소로 이루어진다.
  • 2Wiki와 HotpotQA 벤치마크에서 기존 방법 대비 F1 점수가 각각 19.6%, 33.5% 상승했으며, OpenSPG KAG로 오픈소스 공개되었다.

실무 적용 순서와 시스템 신뢰성 설계 원칙

  • 기술 선택은 지식 크기, 질문 형태, 기존 관계 데이터 존재 여부, 검증 위치, 비용 순으로 판단하며, 실제 시스템은 질문 유형별로 세 기술을 혼합 사용한다.
  • 운영 신뢰성은 특정 기술 사용 여부보다 지식 가져오기, 근거 검증, 업무 규칙 강제, 실패 처리 설계의 4가지가 비어 있는지 여부가 결정적이다.

용어 사전

용어뜻
RAG (Retrieval-Augmented Generation)외부 문서를 검색하여 언어 모델에 제공함으로써 최신 및 방대한 지식 기반 답변을 생성하는 방식
CAG (Cache-Augmented Generation)안정적인 지식을 문맥에 미리 로드하고 KV 캐시를 재사용하여 검색 지연과 오류를 줄이는 방식
KAG (Knowledge-Augmented Generation)지식 그래프를 활용하여 엔티티 간 관계를 따라 여러 단계로 논리적으로 추론하는 방식
KV 캐시 (KV Cache)모델이 문서를 읽을 때 생성된 중간 계산값을 저장하여 이후 질문 처리 시 재사용하는 메모리 구조
멀티홉 추론 (Multi-hop Reasoning)여러 개의 문서나 엔티티를 순차적으로 연결하여 하나의 질문에 답을 도출하는 복잡한 추론 과정
