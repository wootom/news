제미나이 3.7 플래시, 초당 340토큰 디코드로 에이전트 루프를 가속

채널: 안될공학 - IT 테크 신기술 · 주제: 제미나이 3.7 플래시의 디코드 속도와 에이전트 성능 상승폭 분석

01핵심 개요

항목내용
대상 모델구글 딥마인드 제미나이 3.7 플래시. 8월 13일 공개, 7월 21일 모델 카드가 갱신된 3.6 플래시를 기반으로 한 약 3주 만의 업데이트.
출력 속도아티피셜 애널리시스가 하이 리즈닝 설정에서 측정한 디코드 속도 초당 340토큰. 반면 첫 토큰까지는 약 9.8초가 소요.
지능 지수인텔리전스 인덱스 56점. 3.6 플래시 52점 대비 4점 상승이며, 57점대 상위 모델(GPT-5.6 테라, 뮤지스 스파크 1.2) 바로 아래.
벤치마크 상승프런티어 코드 1.1 메인 34.4%→43.6%, 오토메이션 벤치 17%→30.4%, OS월드 2.0 33.8%→47.9%.
가격2026년 말까지 프로모션가 입력 0.75달러 · 출력 3.75달러, 2027년부터 각각 1.5달러 · 7.5달러. 인텔리전스 인덱스 과제당 비용은 약 40달러.
포지셔닝구글이 "코딩과 에이전트를 위한 워크호스 모델"로 소개. 24시간 작업을 맡기는 제미나이 스파크에 이미 투입.
화자 관점화자는 답변 하나의 완성도보다 판단·생성·툴 호출·재판단이 반복되는 루프의 회전 속도가 이 모델의 핵심이라고 본다.

02핵심 기능/내용 구조

영상은 신규 모델 발표를 일상적으로 다루지 않는다는 전제에서 출발해, 이번 제미나이 3.7 플래시에서만 관찰되는 숫자 조합을 근거로 논의를 연다. 첫 축은 속도다. 초당 340토큰이 전체 응답 시간이 아니라 생성 시작 이후의 디코드 속도라는 점을 짚고, 첫 토큰까지 약 9.8초가 걸린다는 상반된 수치를 함께 제시한다. 이어 LLM 추론을 프리필과 디코드로 나눠 각 단계에서 무엇이 병목인지 설명한다. 두 번째 축은 성능이다. 인텔리전스 인덱스 4점 상승과 코딩·자동화·컴퓨터 조작 벤치마크의 상승폭을 나열하되, 개별 수치보다 코딩과 툴 사용 영역의 상승이 두드러진다는 방향성에 무게를 둔다. 세 번째 축은 비용과 시간이다. 프로모션 단가, 과제당 비용, 타임 투 태스크 1.7분을 묶어 에이전트 운영 관점에서 세 지표가 함께 움직여야 한다고 정리한다. 마지막으로 제미나이 스파크 적용 사례와 측정값의 변동 가능성을 덧붙이며 마무리한다.

03기술적 맥락

화자는 LLM 추론을 입력 전체를 읽어 처리하는 프리필과 토큰을 하나씩 만들어내는 디코드로 구분한다. 프리필 구간에서는 입력 전체에 대한 연산과 함께 이후 생성에 쓰일 KV 캐시가 만들어지고, 일반적으로 보고되는 TTFT에는 프리필뿐 아니라 요청 대기와 네트워크 시간, 리즈닝 모델이라면 답을 내기 전의 내부 추론 시간까지 포함된다. 따라서 약 9.8초를 전부 KV 캐시 생성 시간으로 볼 수는 없다는 단서를 단다. 엔비디아 역시 프리필은 연산량에, 디코드는 메모리 대역폭과 지연 시간에 크게 좌우되는 별개 단계로 설명하며, 서버에서 두 단계를 따로 최적화할 수 있다. 구글은 이번 발표에서 알고리즘 이노베이션을 언급했으나 그것이 새로운 디코드 알고리즘이라고 명시하지는 않았고, 화자는 모델 구조 개선, 서빙 단계의 배칭·커널·메모리 접근 최적화, 하드웨어 활용도 개선 가운데 무엇이 기여했는지 현재 공개 정보로는 단정하기 어렵다고 본다. 성능 쪽에서는 프런티어 코드 1.1 메인 34.4%→43.6%, 오토메이션 벤치 17%→30.4%, OS월드 2.0 33.8%→47.9%로 코딩과 다단계 툴 사용 축의 상승폭이 특히 크다. 구글 설명도 작업 중 막혔을 때의 대응 능력을 높이고 다단계 계획과 툴 콜에 더 많은 연산을 배분하도록 개선했다는 같은 방향이다.

04전략적 의미

챗봇은 사람이 몇 번 질문하면 끝나지만, 에이전트는 작업 하나 안에서 모델을 반복 호출한다. 호출이 10회, 20회로 늘어나면 API 단가가 그대로 운영비가 되므로 지능·속도·비용 세 지표는 분리해서 볼 수 없다. 제미나이 3.7 플래시는 인텔리전스 56점, 초당 340토큰, 과제당 약 40달러라는 조합을 제시하고, 아티피셜 애널리시스의 타임 투 태스크에서도 하이 리즈닝 기준 평균 1.7분으로 GPT-5.6 테라 대비 약 40% 짧으며 지능과 소요 시간을 함께 놓은 비교에서 파레토 프런티어에 올랐다. 다만 화자는 이 1.7분이 출력 토큰 수를 실제 디코드 속도로 환산한 평균 생성 시간이며 TTFT와 기타 오버헤드는 제외된 값이라고 명시적으로 경고한다. 더 주목할 지점은 기반 모델을 새로 학습하지 않고도 실제 사용 성능을 크게 움직일 여지가 남아 있다는 사실이다. 3.6 플래시 모델 카드 갱신 3주 만에 나온 이번 업데이트가 개발자 피드백과 알고리즘 개선의 결과라면, 성능 향상 경로가 더 큰 모델과 더 많은 GPU에만 있지 않다는 뜻이 된다. 코딩 에이전트를 운영하는 팀에는 모델 교체 주기와 단가 재협상 주기가 함께 짧아진다는 의미이기도 하다.

06활용 시나리오

  1. 코딩 에이전트 루프 단축: 파일 읽기, 원인 추론, 코드 수정, 실행, 로그 재확인이 반복되는 작업에서 생성 구간을 짧게 가져가 다음 단계로 빨리 넘어간다.
  2. 다단계 업무 자동화: 오토메이션 벤치와 OS월드 상승폭을 근거로, 툴 호출이 여러 번 겹치는 업무 자동화 파이프라인의 실패·재시도 횟수를 줄인다.
  3. 장시간 위임형 에이전트: 24시간 작업을 맡기는 제미나이 스파크처럼 파일 수집, 이메일 초안 작성, 상태 문서 갱신을 오가는 복합 작업에 투입한다.
  4. 운영비 시뮬레이션: 호출 횟수 × 프로모션 단가와 2027년 정가를 함께 계산해, 에이전트 도입 시점과 계약 구조를 미리 설계한다.
  5. 모델 선택 기준 재정의: 벤치마크 점수 단독이 아니라 지능·디코드 속도·과제당 비용 세 축을 묶어 후보 모델을 비교하는 내부 기준을 만든다.

07현황 및 전망

화자는 초당 340토큰이 아티피셜 애널리시스가 구글 API에서 측정한 값이므로 서버 부하, 요청 조건, 리즈닝 설정에 따라 달라질 수 있다고 선을 긋는다. 구글 모델 카드에도 간헐적 지연과 타임아웃 가능성이 적혀 있다. 그럼에도 이번 모델에서 분명한 특징은 답을 내기 전에는 리즈닝에 시간을 쓰고 디코드가 시작된 뒤에는 초당 340토큰까지 뽑아내는 구조이며, 코딩과 에이전트 성능이 동시에 올라왔고 그것이 3주 만에 나왔다는 점이다. 화자는 구글이 이 디코드 속도를 어떤 방법으로 만들었는지 공개하지 않은 부분을 오히려 다음에 확인할 포인트로 꼽는다. 모델 자체의 디코드 방식을 손본 것인지, 서빙과 하드웨어 최적화가 큰 역할을 한 것인지, 둘이 함께 움직인 것인지에 따라 후속 모델의 개선 여지도 달라진다고 본다.

08용어 사전

용어한줄설명비유/예시
프리필(Prefill)입력 전체를 한 번에 읽어 연산하고 KV 캐시를 만드는 단계발표 전에 자료 전체를 훑어보는 준비 시간
디코드(Decode)토큰을 하나씩 이어서 생성하는 단계준비를 마친 뒤 실제로 말을 쏟아내는 구간
KV 캐시프리필에서 만들어져 이후 생성에 재사용되는 중간 상태 저장소매번 다시 읽지 않도록 접어둔 책갈피
TTFT요청부터 첫 토큰이 나올 때까지의 시간주문 후 첫 접시가 나오기까지의 대기
인텔리전스 인덱스아티피셜 애널리시스가 여러 평가를 묶어 산출한 종합 지능 점수여러 과목 점수를 합친 내신 평균
타임 투 태스크출력 토큰 수를 디코드 속도로 환산한 평균 생성 시간 지표실제 배송이 아닌 포장 소요 시간만 잰 값
파레토 프런티어두 지표를 동시에 개선한 모델들이 놓이는 경계선가성비 표에서 맨 바깥줄에 서는 제품
워크호스 모델반복 호출을 견디며 일상 업무를 도맡는 주력 모델화물 운반을 계속 감당하는 짐말
에이전틱 루프판단, 생성, 툴 호출, 결과 확인이 반복되는 실행 구조확인하고 고치기를 반복하는 정비 작업
배칭(Batching)여러 요청을 묶어 서버 자원 효율을 올리는 서빙 기법엘리베이터를 여러 명이 함께 타는 방식
