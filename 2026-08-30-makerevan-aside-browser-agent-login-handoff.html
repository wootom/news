AI가 로그인 앞에서 멈춥니다 — Aside 브라우저가 이 문제를 다루는 법

AI 에이전트 브라우저 'Aside'는 로그인·결제처럼 되돌릴 수 없는 순간에 멈춰 사람에게 넘기고, 사람이 처리하면 끊김 없이 이어간다 — 이 '멈춤-인계-재개' 흐름이 확장(익스텐션) 기반 에이전트와의 체감 차이를 만든다.

01왜 로그인 앞에서 멈추는가

  • 에이전트가 로그인을 "못 하는" 게 아니라 "안 하도록" 설계됐다 — 비밀번호를 모델에 넘기면 대화 기록에 남고 유출 경로도 불확실하며 되돌릴 수 없다.
  • 이는 성능 문제가 아니라 설계 문제. 잘 만든 도구는 여기서 로그인 자체를 포기하거나, 로그인은 하되 값은 보지 않는 두 갈래로 나뉜다.

02좋은 '멈춤'의 조건

  • 나쁜 흐름: 그냥 멈춰서 사람이 뭘 할지 모르게 두거나, 무리하게 진행해 엉뚱한 버튼을 누른다.
  • 좋은 흐름: ①왜 멈췄는지 말하고 ②사람이 뭘 하면 되는지 알려주고 ③처리 후 자동으로 이어간다.
  • Aside 공식 소개 영상은 "저는 로그인할 수 없습니다" 같은 한계를 화면 정중앙, 그것도 영상 도입부에 정직하게 노출한다.

03실측 — 유튜브 스튜디오 정리 작업

  • 이미 로그인된 상태에서 "최근 영상 5개 정리"를 시켰더니 40초 뒤 에러 없이 멈춰 "연결된 채널이 두 개인데 어느 쪽인가요?"라고 카드로 질문.
  • 답을 고르고 제출하자 처음부터 다시 하지 않고 멈췄던 지점에서 바로 이어감 — 저자는 이 지점에서 "감탄했다"고 평가.

04비밀번호 금고와 권한 3단계

  • 브라우저 내장 비밀번호 금고(크롬 저장값 가져오기 가능)가 로그인 화면에서 값을 대신 채우며, 모델은 "로그인됐다"는 사실만 알 뿐 값 자체는 보지 못한다.
  • 접근 정책은 항상 허용 / 잠금해제 상태에서만 / 항목별 예외의 3단계. 2단계 인증·캡차는 사람에게 넘기고, 결제·게시처럼 되돌리기 어려운 행동은 승인을 기다린다.

05확장(익스텐션) 방식과의 체감 차이

0회Aside — 유튜브 지표 조회 중 막힌 횟수(채널 확인 질문 1회로 해결)
3회+크롬 확장 — 같은 작업에서 페이지 이동·스크롤 반복해도 목표 데이터 도달 실패
  • 확장은 남의 페이지 위에 얹혀 요소를 찾기 때문에 ①화면이 바뀌면 놓치고 ②권한 확인이 자주 끼어들고 ③도구 호출이 자주 실패한다.
  • 같은 유튜브 스튜디오 지표 조회 작업에서 확장 쪽은 페이지를 세 번 옮기고 스크롤해도 원하는 표에 도달하지 못한 반면, Aside는 채널 확인 질문 1회로 끝까지 이어갔다.
  • 작업 도중 개입도 가능 — 'Q'는 끝난 뒤 처리, '스티어'는 진행 중인 작업에 바로 반영.

06한계와 주의점

  • 시크릿 모드에서는 비밀번호 금고 사용 불가, 캡차·패스키는 결국 사람이 처리해야 하며 자리를 비우면 작업이 그대로 멈춰 있다.
  • 기억 기능이 방문 기록을 보존(30일/90일 선택), 항상 허용으로 두면 자리 비운 사이에도 로그인이 이뤄질 수 있어 위험. 벤치마크는 자체 발표 수치(제3자 검증 아님). 현재 맥 전용, 버전이 빠르게 바뀌는 초기 단계 제품.
