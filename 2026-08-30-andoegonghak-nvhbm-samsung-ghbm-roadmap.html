NVIDIA HBM 등장, 삼성 zHBM 상세 스펙 공개 3일 후... GPU 못 팔아도 ASIC/XPU 엔비디아 남는 이유

엔비디아가 이번 주 자체 설계 'NVHBM'을 발표하며 HBM 컨트롤러 표준까지 쥐려 하고 있다 — 삼성의 CHBM→AHBM→GHBM 로드맵과 견주어 그 의미를 짚는다.

01NVHBM이란

  • 엔비디아가 HBM을 직접 만들거나 적층하는 게 아니라, HBM 내부에서 어떤 데이터를 먼저 꺼낼지·XPU와 어떻게 연결할지를 규정하는 메모리 컨트롤러·인터페이스를 직접 설계해, 생산업체가 달라져도 같은 규격으로 공급하게 만드는 전략.
  • 삼성 로드맵(SHBM→CHBM→AHBM→GHBM)과 비교하면 NVHBM은 CHBM과 가장 닮아 있다 — GPU 안에 있던 메모리 컨트롤러를 HBM 베이스 다이로 내리는 구조.

02삼성 로드맵 4단계

SHBM현재 표준 HBM, 컨트롤러는 GPU/XPU 안에 위치
CHBM메모리 컨트롤러를 HBM 베이스 다이로 이전
AHBM베이스 다이에 일부 연산 기능 추가, GPU 왕복 데이터 감소
GHBMHBM 자체를 GPU 위로 적층(패키지 구조 전체 변경)
  • 컨트롤러가 아래로 내려가고, 연산이 메모리 가까이 들어가고, 결국 HBM 전체가 GPU 위로 올라가는 흐름.

03NVHBM의 노림수

  • 컨트롤러를 XPU에서 HBM 베이스 다이로 내리면 XPU 실리콘 여유 공간이 생겨 연산기·캐시를 더 넣을 수 있다 — 엔비디아는 연산공간 최대 25% 확보, 대역폭 최대 30% 향상, 전력 15% 절감을 주장.
  • 커스텀 HBM인데 공급사는 여럿 — 엔비디아가 공통 설계도를 쥐고 여러 메모리업체가 검증·공급하는 구조로, 특정 XPU 맞춤 성능을 얻으면서도 복수 공급망을 확보하는 방법.
  • 첫 협력사는 AWS 칩 설계 자회사 안나푸르나랩스(트레니움4가 NVLink 퓨전 지원 확인, NVHBM 탑재는 미확정) — 엔비디아 GPU가 안 들어가는 자리에서도 메모리·NVLink·스위치·렉은 엔비디아 기술로 남기려는 포석.

04삼성 GHBM — 더 과감한 다음 단계

230%HBM4E 대비 D램 대역폭 목표(하이칩스 발표)
70%전력 효율 개선 목표
100W1200W급 GPU + GHBM4스택 조합의 메모리 부문 절감 전력
  • HBM을 GPU 옆이 아니라 위에 쌓아 두 칩이 마주보는 면 전체로 수직 연결 — GPU 가장자리 길이(쇼라인) 한계를 근본적으로 해결.
  • 접합 방식은 하이브리드 커퍼 본딩과 웨이퍼-웨이퍼 결합 — 개별 다이 방식과 달리 불량 선별이 어려워 수율 관리가 관건.

05메모리 업체 입장 — 기회이자 위협

  • HBM 시장이 커지고 구조가 복잡해질수록 물량·제조기술의 가치는 커지지만, 여러 업체가 엔비디아가 정의한 동일 베이스 다이를 공급하게 되면 커스텀 설계 차별화 여지는 줄어든다.
  • SK하이닉스는 HBM4 베이스 다이를 직접 설계·TSMC가 제조하는 방식이었는데, 엔비디아가 같은 영역(컨트롤러·인터페이스 설계)으로 들어오며 영역 다툼 가능성이 생겼다.
  • NVHBM·GHBM 모두 아직 실제 제품 성능·양산성이 검증되지 않은 설계 목표 단계 — 가까운 시일엔 현재 2.5D 패키지를 유지하는 CHBM/NVHBM이 먼저 움직이고, 패키징 난도가 높은 GHBM은 그다음 단계가 될 가능성이 크다.
