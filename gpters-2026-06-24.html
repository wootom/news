01AI 툴 비교 및 활용 (OpenClaw, Hermes, Codex, GLM, Grok 등)

  • OpenClaw와 Hermes 비교: Hermes는 사용자의 반복적인 작업을 학습하여 시스템을 만들고, 시키지 않은 부분까지 최적화하는 데 강점이 있습니다. OpenClaw는 지시된 작업을 정석대로 처리하는 느낌입니다. 이 두 툴을 병행하여 사용하면 서로의 오류를 보완해 줄 수 있다는 의견이 있습니다.
  • AI 에이전트의 역할: 오픈클로가 헤르메스 게이트웨이 셧다운 상태를 파악하고 수정해줄 수 있는지에 대한 질문이 있었습니다.
  • OpenClaw 작업 완료 확인 문제: OpenClaw를 텔레그램으로 사용할 때 작업 완료 메시지가 오지 않는 문제에 대해, 에이전트에게 작업 위임을 시키고 크론(cron)을 걸어 완료를 확인하는 방법이 제시되었습니다.
  • AI 모델 선택 및 비용 효율:

* Deepseek v4 flash를 기본으로 Deepseek v4 pro, Gmini 등 필요한 모델을 설정하여 사용하며 비용 효율성을 높이는 방법이 공유되었습니다. * OpenClaw에 익숙한 사용자는 Claude와 CLI 방식을 병행하여 잘 활용하고 있습니다. * Codex, Grok, GLM 등 다양한 모델을 함께 사용하는 전략이 논의되었습니다. 특히 CLM5.2는 불안정하다는 의견과 함께 Grok 4.3도 중독적이라는 평가가 있었습니다.

  • Codex 사용 및 결제 관련:

* ChatGPT Plus 플랜 사용 시 36,000원으로 코덱스 사용량을 2배 늘릴 수 있다는 정보가 공유되었습니다. * 코덱스 사용량 관련하여 "5시간/일주일" 한도에 대한 혼란과 시스템 오류 의심 사례가 있었습니다. 코덱스 사용량은 다음 링크에서 확인할 수 있습니다. https://chatgpt.com/codex/cloud/settings/analytics#usage

  • 클로드에 대한 불만 및 다른 모델로의 전환 의사: 클로드의 잦은 정책 변경, 제한적인 사용량, 에이전트에서의 사용 불가, 페이블(Fable) 없이는 약하다는 점 등을 들어 다른 모델(GPT, GLM, Grok)로 전환을 고려하는 사용자가 있었습니다.
  • Grok 할인: Grok Heavy 할인은 당분간 상시 할인으로 유지될 가능성이 있다는 예측이 있었습니다.

02크롤링 및 자동화 (OpenClaw, Playwright, Chrome CDP)

  • OpenClaw를 활용한 브라우저 데이터 크롤링: OpenClaw를 이용한 브라우저 데이터 크롤링이 잘 작동하며, 보안 문제도 크게 없다는 의견이 있었습니다.
  • 크롤링 기술 스택:

* Playwright CLI와 Chrome CDP(Chrome DevTools Protocol)를 연결하여 크롤링하는 방법이 공유되었습니다. 실제 크롬을 조작하는 방식이라 효과적이라고 합니다. * WSL(Windows Subsystem for Linux), OpenClaw 환경에서 Chrome CDP를 연결하는 구체적인 코드 예시 및 설정 방법이 제시되었습니다. * curl http://10.95.xxx.xxx:9444/json/version 과 같이 CDP 연결 가능 상태를 확인하는 방법도 공유되었습니다.

  • Headless 모드: Playwright는 창을 열지 않고도 작업이 가능(headless)하며, 크롤링 작업을 만들 때는 CDP로 화면을 보면서 작업하고 실제 스킬 실행 시에는 headless 모드를 활용하는 것이 효율적이라는 의견이 있었습니다.
  • 스크립트 실행 자동화: OpenClaw의 크론 기능 대신 리눅스 자체 crontab을 사용하면 토큰 사용량을 절약할 수 있다는 정보가 공유되었습니다. Talescale을 이용하여 crontab 대시보드를 외부에서 접근 가능하게 설정하는 방법도 언급되었습니다.
  • 클로드의 크롬 확장 프로그램 활용: 클로드 코워크를 사용할 경우, 크롬 확장 프로그램을 통해 브라우저를 열어두면 클로드 코워크가 이 브라우저를 이용해 데이터 크롤링을 수행할 수 있습니다.
  • UI Path 언급: 웹 크롤링에 가장 효과적인 툴 중 하나로 UI Path가 언급되었습니다.

03맥 스튜디오 vs 맥미니 (영상 편집 및 에이전트 활용)

  • 고민: 맥미니의 한계로 영상 편집과 에이전트 추가 활용을 위해 맥 스튜디오 구매를 고려하는 상황에 대한 조언을 구하는 질문이 있었습니다.
  • 의견:

* 가벼운 4K급 영상 편집은 맥미니로도 충분하며, AI 영상물 편집이나 고사양 비트레이트/HDR 작업이 아닌 이상 맥 스튜디오까지는 필요 없을 수 있다는 의견이 많았습니다. * 맥미니(특히 프로 칩셋 모델)로도 충분하며, 전문적인 작업을 한다면 맥 스튜디오가 권장됩니다. * 단순히 영상 편집과 에이전트 활용을 위해 맥 스튜디오를 구매하는 것은 오버스펙일 수 있으며, 맥미니 2대 구매가 더 효율적일 수 있다는 의견도 있었습니다. 남는 차액으로 다른 AI 구독 서비스를 이용하는 것이 더 나을 수 있다고 합니다. * 어도비 계열 프로그램을 사용하는 경우 CUDA 때문에 엔비디아 계열(지포스) PC를 고려해야 할 수도 있으며, 맥북은 전성비가 좋은 것이지 깡성능은 지포스를 이기지 못한다는 의견이 있었습니다. * 이동 편집이 많고 다빈치 리졸브를 사용한다면 맥북도 좋은 선택입니다.

  • RAM 효율: 16GB 4대가 64GB 1대보다 효율이 좋지는 않지만, 로컬 LLM 관점에서는 애플의 MLX(Machine Learning eXpert) 기술을 활용하여 작은 모델을 더 빠르게 사용할 수 있다는 가능성이 언급되었습니다. 관련 정보는 다음 유튜브 영상에서 확인할 수 있습니다. https://youtu.be/CzgK02zsRg4?si=MslvKlYJTWYrcsCO

05Hermes와 Slack 연동 문제

  • Hermes를 Slack에 연동할 때 앱을 계속 만들어 세팅해야 하는지에 대한 질문이 있었고, 오픈클로도 비슷하며 매니페스트를 뽑아 등록하면 번거로움을 줄일 수 있지만 봇 토큰과 앱 토큰은 따로 관리해야 한다는 답변이 있었습니다.
  • 두 곳의 Hermes와 Slack을 연동하려면 각각 2개의 앱을 만들어야 합니다.
  • 한 대의 Hermes가 다른 Hermes와 통신하게 하여 직접 대화할 필요 없이 연동할 수 있는 방법도 언급되었습니다.

06GLM 5.2 (중국 모델) 보안 이슈 및 Ollama Cloud 사용

  • 보안 우려: 중국 모델(GLM) 사용 시 개인정보 수집 등 보안 이슈에 대한 질문이 있었습니다.
  • 의견:

* Ollama Cloud를 통해 사용하면 직접 연결이 아니므로 보안 이슈가 적을 것이라는 의견과 허깅페이스 등을 통해 사용하면 비용도 저렴하고 보안 걱정을 덜 수 있다는 의견이 있었습니다. * 일반적인 사용자의 입력 데이터는 정제되지 않고 양이 적어 AI 학습에 활용될 가능성이 낮으므로 일상적인 보안 우려는 과도하다는 주장도 있었습니다. * 다른 한편으로는 보안 이슈가 없을 수는 없으니 감안하고 사용하는 것이 맞다는 의견도 있었습니다. (주어진 데이터는 이미 공공재와 같다는 자조적인 농담도 있었습니다.)

  • Ollama Cloud 사용 경험: 30달러 요금제를 사용하면 사용량이 충분하며, 모델을 자유롭게 바꿔 쓸 수 있어서 만족스럽다는 사용자 경험이 공유되었습니다.
