ChatGPT 'Work' 탭, 생각보다 훨씬 강력하다 — 완전 활용 가이드

01핵심 개요

항목내용
발표 채널Futurepedia (유튜브)
핵심 주제ChatGPT의 'Work' 탭(에이전트 모드) 기능 총정리
Chat과의 차이Chat=대화형 반복 작업 / Work=목표만 주면 스스로 계획·실행·결과물 완성
대표 기능웹사이트 생성, 플러그인, 인앱 브라우저, 블록, 스킬, 스케줄 작업
처리 방식작업마다 전용 클라우드 컴퓨터 할당, 동시 다중 세션 가능
동기화웹·모바일·데스크톱 앱 간 세션 동기화 지원

02핵심 기능/내용 구조

  1. Chat vs Work 응답 방식 차이: 동일한 프롬프트("디즈니랜드 여행 계획")를 Chat과 Work에 동시에 보내면, Chat은 약 5분 만에 대화형 답변을 주지만 Work는 10분 이상 걸려 색상 코딩·체크리스트·표가 포함된 완성된 문서를 자동으로 만들어낸다. Work는 물어보지 않고도 문서화하는 것이 기본 성향이다 (02:02).
  2. 멀티 세션 동시 실행: 작업이 오래 걸리는 동안 새 세션을 여러 개 동시에 띄워 멀티태스킹할 수 있다 (01:19).
  3. 공유 가능한 라이브 웹사이트 생성: Work는 ChatGPT가 직접 호스팅하는 라이브 웹사이트를 즉석에서 만들 수 있고, 공개(public) 전환 후 URL을 커스텀해 누구에게나 공유 가능하다. 커스텀 도메인 연결과 환경변수(예: 다른 AI 모델 연동) 설정도 지원한다 (04:02).
  4. 플러그인(외부 도구 연동): 사이드 패널의 Plugins에서 캘린더, Gmail, Granola(회의 메모) 등을 연결하면 Work가 여러 도구를 오가며 정보를 취합해 프레젠테이션까지 자동 제작한다. 실제 시연에서 캘린더 일정→Granola 메모→Gmail 내용을 스스로 조합해 8장짜리 PPT를 완성하고, 시각적 검수까지 거쳐 오류 2건을 스스로 수정했다 (06:52).
  5. 데스크톱 전용 플러그인 — Remotion(모션그래픽): 데스크톱 앱에서만 동작하는 플러그인으로, 로고 이미지와 설명을 주면 편집 가능한 모션그래픽을 12분여 만에 제작한다. 결과물은 인앱 에디터에서 바로 수정 가능하다 (09:44).
  6. 인앱 브라우저를 통한 자율 브라우징: 데스크톱 앱 우측에 열리는 내장 브라우저로 ChatGPT가 직접 사이트를 클릭·입력·탐색한다. 예시로 유타주 임야 매물을 조건에 맞게 검색해 지역별 최적 매물을 각각 탭으로 열어 정리했다 (11:46).
  7. 쿠키·로그인 정보 가져오기: 설정에서 Chrome 등 기존 브라우저의 쿠키·비밀번호를 가져오거나, 로그인 정보 목록 파일을 제공해 자동 로그인하도록 만들 수 있다 (12:44).
  8. 블록(Blocks) 기능: 글쓰기 블록(이메일 초안 작성 후 바로 발송 가능), 코드 블록(칸반보드, 대시보드, 계산기, 타임라인, 플로우차트, 티어리스트 등 인터랙티브 결과물)을 즉석 생성 (14:35).
  9. 채팅 분기(Branch): 특정 응답 지점에서 대화를 새 채팅으로 분기해 원본은 유지한 채 다른 방향을 탐색할 수 있다 (17:37, 인접 구간).
  10. 스킬(Skills): 반복할 작업을 "레시피 카드"처럼 패키징해 이후 짧은 호출만으로 동일 워크플로우를 재현. Claude의 스킬 파일을 다운로드해 ChatGPT에 드래그하면 그대로 변환도 가능하다 (18:19).
  11. 스케줄 작업(Scheduled Tasks): 사이드 패널의 Scheduled 탭에서 일회성 또는 매일/매주/매시간 반복 작업을 완전 자동화. 클라우드 실행 시 컴퓨터를 꺼둬도 동작하며, 스킬을 먼저 만든 뒤 그 스킬을 스케줄에 태우는 방식을 권장한다 (19:32).

03기술적 맥락

  • 전용 클라우드 컴퓨터 할당: Work는 작업마다 별도의 클라우드 컴퓨터를 부여받아 세션 내내 작업을 누적하며 진행한다. 이는 Codex의 에이전틱 능력을 일반 사용자용으로 쉽게 만든 것이라고 설명된다 (05:16).
  • 플러그인 = 연결(connection) + 스킬(skill) 조합: 각 플러그인은 도구 접근 권한뿐 아니라 "그 도구를 올바르게 쓰는 법"을 가르치는 스킬 세트를 함께 탑재한다.
  • 데스크톱 앱 전용 기능: 로컬 파일 접근, 터미널, 인앱 브라우저, 컴퓨터 사용(computer use) 기능은 데스크톱 앱에서만 가능하며, 클라우드/온컴퓨터 실행 모드를 우측에서 전환할 수 있다 (08:50).
  • 인앱 브라우저의 진보: 과거 Chrome 확장 프로그램 기반 브라우저 사용보다 네이티브 인앱 브라우저의 탐색·클릭·입력 정확도가 크게 개선되었다고 언급된다.

04전략적 의미

  • "대화"에서 "위임"으로의 전환: Chat은 사용자가 결과를 만들어가는 과정에 계속 개입해야 하지만, Work는 최종 목표만 던지면 계획 수립부터 도구 사용, 결과물 완성까지 위임할 수 있어 업무 방식 자체가 바뀐다.
  • 일반 사용자의 에이전트 접근성 확대: 기존에는 개발자용 Codex 수준의 에이전틱 자동화가 필요했던 작업(다중 도구 연동, 장시간 자율 실행)을 비개발자도 플러그인과 스킬만으로 활용할 수 있게 되었다.
  • 완전 자동화 루프의 완성: 스킬(반복 작업 표준화) + 스케줄 작업(무인 실행)의 조합은 사람이 매번 프롬프트를 입력하지 않아도 되는 완전 자동화 워크플로우를 가능하게 한다.

06활용 시나리오

  1. 여행/이벤트 기획 커맨드 센터 제작: 여행 계획 프롬프트를 Work에 보내면 호텔 비교, 일정표, 예산 계산기, 체크리스트가 포함된 인터랙티브 웹사이트를 자동 생성하고, 가족 등과 공개 URL로 공유할 수 있다.
  2. 회의 준비 자동화: 캘린더·이메일·회의 메모 플러그인을 연결해두면 "오늘 회의 준비해줘"라는 한 줄 지시만으로 관련 자료를 스스로 찾아 종합해 편집 가능한 프레젠테이션(PPTX)까지 완성한다.
  3. 웹사이트 QA 및 버그 탐색: 인앱 브라우저로 신규 사용자처럼 사이트 곳곳을 클릭·탐색하게 하여 버그를 찾아내는 테스트 자동화에 활용할 수 있다.
  4. 콘텐츠 제작 파이프라인 자동화: Remotion 플러그인으로 로고·설명만 주고 편집 가능한 모션그래픽을 만들거나, 특정 비주얼 스타일을 스킬로 저장해 반복 요청 없이 일관된 결과물을 뽑아낼 수 있다.
  5. 정기 리포트/업무 완전 자동화: 매일/매주 반복되는 데이터 분석이나 보고서 작성을 스킬로 만든 뒤 스케줄 작업에 등록해 컴퓨터를 켜두지 않아도 클라우드에서 자동 실행되게 할 수 있다.

07현황 및 전망

  • 영상 시점 기준 Work는 이미 상당 기간 출시되어 있었고, 제작자는 실사용 경험을 바탕으로 이번 가이드를 제작했다고 밝힌다.
  • 플러그인 생태계는 "수천 개" 규모로 이미 크고, 검색을 통해 필요한 도구를 계속 발굴해 연결하는 것이 권장된다.
  • 데스크톱 앱의 컴퓨터 사용(computer use) 기능은 아직 일반 사용자 수요가 크지 않다고 평가되며, 대부분의 실용 사례는 인앱 브라우저 수준에서 충분히 커버된다는 관찰이 제시된다.
  • 스킬을 매개로 Claude 등 타사 에이전트와의 워크플로우 자산을 상호 이전할 수 있다는 점에서, 에이전트 플랫폼 간 "스킬 이식성"이 향후 경쟁·표준화 포인트가 될 가능성이 있다.
