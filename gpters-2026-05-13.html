마누스 (Manus) 결제 및 환불 이슈
  • 마누스 활용 및 장점: 웹/앱 서비스 개발에 효율적이라는 의견이 있습니다. (오목교 전자상가 영상 인용)
  • 강제 환불 사태: 마누스 프로모션 가격 오류로 인해 대규모 구매가 발생했고, 이후 서비스 측에서 강제 환불 처리를 진행했습니다.
  • 환불 과정의 불만:
  • 초기에는 일부 금액만 환불되거나, 크레딧이 사라진다는 불만이 제기되었습니다.
  • 플레이스토어 고객센터 문의를 통해 전액 환불받은 사례가 공유되었습니다.
  • 일부 사용자는 환불 후 1개월 프로 구독(4000 크레딧)을 보상으로 받았습니다.
  • 메타의 마누스 인수 무산: 메타의 마누스 인수 시도가 중국 정부의 반대로 무산되었다는 정보가 공유되었습니다.
  • 마누스 사용 팁: 환불되기 전 크레딧을 최대한 사용하는 것이 권장되었습니다.
02
AI 에이전트 (OpenClaw, Hermes 등) 활용 및 운영
  • 카카오톡 봇 만들기:
  • 기본 구조: 카톡 메시지 감지(SQLite DB 폴링) -> 키워드 매칭("뽀짝" 감지) -> OpenClaw 봇으로 AI 답변 생성 -> 카톡으로 자동 전송.
  • 필수 요소: OpenClaw 세션 접근 권한, 카톡 Mac 앱(자동화용), 메시지 읽고 보내는 스크립트.
  • 뽀짝이의 방식: 로컬에서 bash + sqlite 쿼리로 카톡 DB 읽기, AppleScript로 메시지 보내기(현재 애플스크립트 방식은 사용하지 않음), OpenClaw 자동화 시스템 연동. (관련 게시글: https://www.gpters.org/dev/post/kakaotalk-macro-era-how-lEVSOKmyNxOqCtI)
  • 카카오톡 계정: 업무용/세컨폰 계정을 사용하는 경우가 많으며, 유령 계정을 활용하기도 합니다.
  • AI 에이전트 용어 정리: OpenClaw는 사람이 스킬을 만들어 넣는 구조이고, Hermes는 작업 중 스스로 스킬을 생성한다는 설명이 공유되었습니다. (https://bbojjak-viewer.vercel.app/qna/qna-32)
  • OpenClaw/Hermes 선택 및 학습:
  • Hermes가 상대적으로 배우기 쉽다는 의견이 있습니다.
  • 모든 기능을 사용해보고 자신에게 맞는 것을 선택하는 것이 권장됩니다.
  • 22기 헤르메스 입문 스터디 참여가 권유되었습니다.
  • OpenClaw와 Hermes 모두 카카오톡 연결에 큰 차이는 없다는 의견이 있습니다.
  • Hermes 칸반(Kanban) 기능:
  • 칸반 기능을 활용하여 에이전트들이 협업하고, 역할에 맞게 스킬과 페르소나를 부여하여 작업을 분배할 수 있습니다.
  • `goal` 모드를 사용하여 작업을 연속적으로 진행시키고, 카드 완료 시 알림을 받을 수 있습니다.
  • 칸반 기능으로 작업을 시켰을 때 50분 동안 혼자 작업하는 등 효율성이 좋다는 경험담이 있습니다.
  • OpenClaw도 칸반 프로젝트를 쓰는 사용자들이 있으며, `랍스터`라는 유사 기능이 언급되었습니다.
  • Hermes의 칸반 워커들은 `kanban-worker` 스킬을 기본으로 로드하며, 작업별 스킬을 추가할 수 있고 메모리가 활성화되어 경험을 활용하는 기반이 있습니다. 그러나 `배운 점 -> 검토 -> 스킬 승격`과 같은 자가진화 루프가 완전히 자동화되어 있지는 않으므로, 메타데이터 표준 추가, 검토, 스킬 후보 승격 등 운영 규칙이 필요합니다. (관련 사례글: https://www.gpters.org/nocode/post/hermes-agent-kanban-jageob-gwanri-7gaji-tib-aiwa-hyoyuljeog-hyeobeob-mmhNtmJGgUWYzOe)
  • API 토큰 입력 방식:
  • 메시지 창에 직접 입력하는 것은 보안상 권장되지 않습니다.
  • `.env` 파일이나 터미널 `config` 메뉴를 통해 입력하는 방식이 선호됩니다.
  • AI에게 직접 물어봐서 토큰 입력 위치를 파악했다는 경험담도 공유되었습니다.
  • AI 에이전트용 PC 운영:
  • 미니 PC 윈도우 환경에서는 불안정하여 일주일에 한 번씩 재부팅하는 경우가 있습니다.
  • 맥미니 사용자들은 항상 켜두는 경우가 많습니다.
  • OpenClaw나 Hermes를 사용하다가 문제가 발생하면 재부팅하는 경우가 있습니다.
  • LLM 연동 및 요금제:
  • GPT 요금제: Hermes를 GPT Go 요금제로 연동 가능한지 질문이 있었고, 가능하지만 사용량 제한이 커서 실사용은 어렵다는 답변이 있었습니다. 보통 Plus나 Pro 요금제를 사용합니다.
  • API 방식: GPT Plus/Pro 구독 대신 API 잔액으로 사용하는 것도 가능하며, 모델은 OpenAPI Codex를 선택하면 됩니다 (이해 부족으로 혼란이 있었으나, `platform.openai.com/api-keys`에서 발급받은 키를 사용).
  • 클로드(Claude) 활용: 코딩 및 문서 작업에 클로드가 부드럽게 작성해주어 유용하다는 의견이 있습니다.
  • 제미나이(Gemini) 활용: 코덱스를 메인으로 쓰고 제미나이로 노래를 만드는 등 부가적인 작업에 사용한다는 의견이 있습니다. Hermes/OpenClaw에 제미나이 구독제를 바로 연동하는 것은 차단될 수 있으며, API 방식은 가능합니다.
  • 로컬 AI 엔진:
  • Rapid-MLX (Apple Silicon)는 MLX 프레임워크 기반으로 Ollama 대비 최대 4.2배 빠르고, TTFT 0.08초 수준의 추론 속도를 제공합니다.
  • Ollama + EEVE + Docker + n8n 구성으로 보고서 통합 작업을 시도한 사례가 언급되었습니다. Gemini가 추천한 `anpigon/eeve-korean-10.8b:latest` 모델을 사용했습니다.
  • `qwen3.6` 모델이 추천되었습니다.
  • AI 생성 동영상 퀄리티: 퀄리티가 낮을 경우 1080p로 생성하거나 업스케일링을 거치는 방법을 추천합니다.

기술적 논의 (심화)
  • OpenClaw와 Hermes의 차이점: OpenClaw는 사람이 스킬을 만들어서 넣어주는 구조고, Hermes는 작업을 하다 보면 스스로 스킬을 생성하는 차이점이 언급되었습니다.
  • 칸반 에이전트의 자가진화: 칸반 워커들이 배운 것을 skill로 승격시키는 루프에 대한 심도 있는 논의가 있었습니다. 현재는 가능한 기반은 있으나, 운영 규칙으로 완전히 자동화된 것은 아니며, `reusable_lesson` 메타데이터 표준 추가, 검토, 스킬 후보 승격 등 운영 규칙 또는 작은 패치가 필요하다고 합니다. 워커가 직접 스킬을 만들면 중복 스킬, 임시 해결법 영구화 등의 문제가 발생할 수 있어, 큐레이터(관리자) 역할을 하는 것이 안전합니다.
  • GPT 5.5의 컴퓨터 활용 능력: 네이버 블로그 자동화(제목, 링크, 이미지, 카테고리, 태그 설정) 등 컴퓨터 활용 능력이 향상되었다는 언급이 있었습니다.
  • Claude 코드의 `/goal` 기능: Codex에 먼저 들어와 있던 `/goal` 기능(작업 완료까지 멈추지 않고 진행)이 Claude 코드에도 버전업되면서 추가되었습니다.
