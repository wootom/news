Codex 스킬을 결과 중심으로 설계하고 검토·반복으로 품질을 높이는 방법을 설명한다.

결과 정의·작업 분해·검토 반복으로 Codex 스킬 품질을 높이는 설계법.

01핵심 개요

  • 스킬은 Markdown 형식의 작업 레시피로 설명되며, 에이전트가 원하는 작업을 수행하도록 돕는 문서로 제시된다.
  • 설계는 해야 할 행동보다 최종 결과를 먼저 정의하고, 필요한 데이터·출처·형식을 역으로 정하는 방식에 초점을 둔다.
  • 반복 가능한 CRM 처리처럼 결정론적인 작업과 연구·창작처럼 결과가 달라지는 작업을 구분해 지시 수준을 달리해야 한다고 말한다.
  • 첫 버전에서 끝내지 않고 에이전트 검토와 피드백을 여러 번 반복해 시간 낭비를 줄이는 절차를 권한다.
  • 영상 검토 사례에서 Luna, Terra, Sol, Astra, Claude를 비교하며 자막·이미지·기밀 데이터 처리 등 오류를 확인한다.

02핵심 주장 / 논점 구조

  • Codex 스킬은 에이전트가 따를 수 있도록 작업 방식을 문서화한 Markdown 기반의 레시피로 설명된다.
  • 좋은 스킬은 원하는 산출물을 먼저 정하고, 이를 만드는 과정과 검증 기준을 뒤에서부터 구성한다.
  • 작업의 결정론성, 검토 가능성, 반복 피드백을 함께 설계해야 에이전트 활용 품질을 높일 수 있다는 논점이다.

03결과에서 시작하는 스킬 설계

  • 치킨 샌드위치를 예로 들어, 다음번에 요리하는 사람이 무엇을 해야 하는지 알 수 있도록 결과부터 정의하는 방식을 든다.
  • 계산 작업을 만들 때는 어떤 데이터를 고려했는지, 데이터가 어디서 왔는지, 어떻게 형식화했는지를 정해야 한다고 말한다.
  • 스킬 문서는 Markdown으로 작성하며, YAML 프런트매터는 세 개의 하이픈으로 시작하는 구성 요소로 언급된다.

04작업 분해와 결정론성 구분

  • 마케팅 단계 같은 구체적 작업을 분해하고, 이를 체인으로 연결하는 접근을 설명한다.
  • CRM 데이터 처리처럼 입력과 결과가 비교적 명확한 프로세스는 매우 결정론적인 작업으로 제시된다.
  • 연구와 결과물 창작은 매번 달라질 수 있으므로, 결정론적 작업과 같은 수준으로 정확한 지시를 고정하기 어렵다고 설명한다.

05검토 에이전트와 피드백 반복

  • 첫 번째 버전을 그대로 쓰지 말고 검토를 거쳐야 하며, 에이전트를 동료처럼 활용할 수 있다고 말한다.
  • 각 스킬에 대해 에이전트가 피드백을 제공하고 여러 버전을 반복하는 방식이 소개된다.
  • 영상이나 웹사이트가 보기 좋은지 같은 주관적 평가도 검토 절차를 강제해 다룰 수 있다고 설명한다.
  • 피드백으로 왼쪽으로 너무 기울었다는 식의 수정 지시를 주고 계속 개선하는 예시가 언급된다.

06주관적 품질을 확인하는 검증 기준

  • 영상과 웹사이트의 품질 평가는 객관적으로 측정하기 어려운 경우가 많다고 지적한다.
  • 모델 성능과 무관하게, 에이전트가 확인할 수 있는 절차와 기준을 작업에 넣는 것이 중요하다고 말한다.
  • 브라우저를 사용해 결과를 검토하는 방식을 선호한다고 밝히며, 필요한 품질에 도달할 때까지 진행하라고 권한다.

07영상 검토에서 드러난 모델별 결과

  • 영상 검토 화면에서 썸네일, 간격, 스크린샷, 비교 결과 등을 확인하는 과정이 제시된다.
  • 한 결과물에서는 시작 부분이 잘렸고, 다른 결과물에서는 이미지 확대와 제품 선택 등이 관찰됐다고 말한다.
  • 기밀 데이터가 숨겨진 점은 긍정적으로 언급하지만, 반복적으로 발생한 처리 문제는 명확한 문제라고 평가한다.
  • Luna, Terra, Sol, Astra, Claude가 결과 비교 맥락에서 언급되며, Luna는 더 비싸다고 설명된다.
  • 보고서 생성과 스킬의 지속적 개선: 검토 후 'Create report'를 눌러 보고서를 생성하는 흐름이 언급되며, Clay의 도움으로 처리하는 장면이 나온다.
  • 보고서 생성과 스킬의 지속적 개선: 첫 결과가 88이라는 수치를 기록한 뒤 테스트를 한 번 더 실행하고 승인하는 과정이 제시된다.
  • 보고서 생성과 스킬의 지속적 개선: 기사 분석 뒤 이를 X용 글로 바꾸는 역설계 사례에서, 구체적 트리거와 검증·수정 지시를 스킬에 반영한다.
  • 보고서 생성과 스킬의 지속적 개선: 새로운 문제가 계속 나타날 수 있으므로 스킬을 완료된 것으로 보지 않고 계속 업데이트해야 한다고 말한다.

08용어 사전

용어뜻
Codex 스킬에이전트가 특정 작업을 수행하도록 작업 방식과 기준을 적어 둔 Markdown 기반 레시피로 설명된다.
Markdown스킬을 작성하는 문서 형식으로 언급되며, 제목 등을 표시하는 데 사용된다.
YAML 프런트매터세 개의 하이픈으로 시작하는 스킬 문서의 구성 요소로 언급된다.
결정론적 프로세스CRM 데이터 처리처럼 입력과 수행 단계가 명확해 결과를 구체적으로 지시하기 쉬운 작업을 가리킨다.
검토 에이전트초안과 결과물을 확인하고 피드백을 제공해 스킬의 다음 버전 개선을 돕는 에이전트 역할이다.
역설계원하는 결과물에서 출발해 필요한 트리거, 과정, 검증 지시를 거꾸로 구성하는 방식으로 소개된다.
