클라우드 플레어 기반 행동형 AI 에이전트 구조와 피클·뮤즈 설계 비교

클라우드 플레어로 피클·뮤즈급 행동형 AI 에이전트를 구축하는 구조와 보안 설계

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

피클과 메타 뮤즈의 에이전트 구조 분석

  • 피클은 샌프란시스코 소재 한국인 창업팀이 만든 YC 출신 서비스로, 문자 수신 시 식당 전화, 기차표 구매, 메일 정리 등 직접 행동을 수행한다.
  • 메타의 뮤즈는 9월 8일 미국 출시 후 22일 만에 500만 다운로드를 기록했으며, 에이전트마다 전용 컴퓨터를 제공하고 기억을 파일로 저장해 사용자가 직접 수정할 수 있다.
  • 두 서비스 모두 비밀번호와 카드 번호를 암호화된 별도 저장소에 두고 AI 모델이 직접 읽지 못하도록 하며, 대화가 길어지면 일기로 전환해 기억을 관리한다.
  • 피클은 10월 29일 사용자가 지시하지 않은 호텔 전화 건 사고로 인해 업체 연락 전 승인 절차를 추가했으며, 이는 바깥 행동 관문의 필요성을 보여준다.

클라우드 플레어 기반 에이전트 아키텍처 설계

  • 고객 데이터를 단일 데이터베이스에 모으지 않고 클라우드 플레어 듀러블 오브젝트 셀을 고객별로 격리해 데이터 혼선과 장애 전파를 방지한다.
  • 문자 게이트웨이, 에이전트, API, 크레덴셜 브로커, VNC 라우터, 운영 워커 등 6개 워커를 서비스 바인딩으로 분리해 신뢰 경계를 명확히 한다.
  • 로그인 정보는 크레덴셜 브로커가 고객별 키와 마스터 키로 봉투 암호화해 관리하며, 에이전트는 토큰을 직접 받지 않고 브로커를 경유해 요청을 보낸다.
  • API가 없는 사이트 대응을 위해 클라우드 플레어 컨테이너에 크롬을 띄우고, 필요 시에만 켜서 비용을 절감하며 VNC로 화면을 전달한다.

안정성 확보를 위한 큐, 알람 및 기억 규칙

  • 문자는 클라우드 플레어 큐에 먼저 넣고 실패 시 5초부터 30분까지 6회 재시도하며, 최종 실패 시 데드 레터 큐로 이동해 데이터 유실을 방지한다.
  • 듀러블 오브젝트 알람으로 셀이 매시간 스스로 깨어나 반복 작업을 수행하며, 이는 피클의 후속 작업 예약과 뮤즈의 백그라운드 작업에 해당한다.
  • 기억은 사용자가 보낸 문자를 근거로만 생성되며, 웹페이지나 댓글 등 외부 콘텐츠에서 읽은 정보는 기억에 반영되지 않도록 제한한다.

바깥 행동 관문 및 비용 통제 전략

  • 게시, 댓글, DM 등 외부 행동은 직전에 한 번 더 검사하며, AI 판단이 아닌 '1', '올려', '오케이' 등 정해진 단어로만 허락을 받아 실행한다.
  • 작업당 1달러, 고객당 하루 3달러, 서비스 전체 하루 200달러로 비용 상한을 설정하고, 동시 실행 작업은 3개, 브라우저 사용은 1개로 제한한다.
  • 셀별 데이터 격리 방식은 전체 통계 조회가 어렵고, 암호화 값 검색 불가, 대용량 미디어는 R2로 분리해야 하는 등 운영상 단점이 존재한다.
