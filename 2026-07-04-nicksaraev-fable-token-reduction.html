02절감 8대 전략

1. RTK (Rust Token Killer) — 툴 출력 압축

Claude Code의 툴 입출력에서 불필요한 반복(standard out 등)을 미니파이. 세션당 수백~수천 회 발생하는 내부 툴 콜의 중복 제거. 데모: 612줄·36,700자 → 4줄·177자 = 99% 절감(같은 정보). 현실적으로 툴 콜당 30~50% 절감.

2. 의미 압축 (Semantic Compression) — 시스템 프롬프트 다이어트

문장을 의미 손실 없이 최소 단어로 재작성. "Hello, thank you so much…" 같은 정보 가치 0 문구 제거. 데모: 865단어 → 211단어, 1,125토큰 → 274토큰. CLAUDE.md·메모리 파일 전반에 적용.

3. 로그 → SQLite — 대용량 로그 직접 읽기 금지

5,000줄 로그를 통독하는 대신 SQLite DB로 압축, logq.py 같은 검색 함수로 질의. Google Sheet·CSV 등에도 동일 적용 — "텍스트 검색 말고 DB 함수로 필터링."

4. 대용량 읽기 차단 (Block Huge Reads)

618KB·20,000줄 파일을 통독하지 않고, 시작/끝만 샘플링해 구조 파악 → sed로 정확한 인덱스만 조회. 20,000줄 → 20~30줄. 긴 리소스 툴 콜에서 ~99% 절감.

5. 영어로 프롬프트

영어는 정보 밀도가 높고 대부분 모델이 영어로 학습됨. 동일 쿼리 토큰: 영어 51 / 이탈리아어 87 / 독일어 118(2.31x) / 일본어 74(1.45x). 20~80%+ 절감. (예외: 중국어는 표의문자로 토큰 효율 높음.)

6. 컨텍스트 검약 규칙 삽입

시스템 프롬프트에 "명시적으로 지정한 리소스만 조회" 규칙 삽입. 예: "작업과 직접 관련된 파일만 읽고, 3개 파일 넘게 확장 전 물어보라. glob/grep으로 위치 찾고 해당 영역만 읽어라. 생성 파일·픽스처는 명시 요청 전 금지." 주의: 품질을 유의미하게 낮출 수 있는 기법 — 매우 구체적으로 지시해야 원하는 것을 찾음.

7. 주기적 /context 점검

/slashcontext로 무엇이 컨텍스트를 몰래 잡아먹는지 확인. 실사례: Chrome MCP 십수 개가 각각 풀 컨텍스트 로드 → 과다 비용·혼란. 별도 데스크톱에 클로드 인스턴스로 /loop 감시자를 하루 1회 실행 → 24시간 전 대비 새로 낀 항목 알림. 토큰 관리 = 컨텍스트 관리.

8. 사고(Thinking) 상한 — 가장 큰 절감

Claude의 적응형 사고(adaptive thinking)는 필요 이상으로 토큰을 씀. 초고지능 모델은 사고를 많이 안 해도 됨 → 기본을 super low로, 필요할 때만 상향. 데모: low(7턴·1,028토큰·18초·16센트) vs extra-high(9턴·1,363토큰·21초·+3센트) — 같은 버그, extra-high가 ~1.3x(실측 통상 1.5x) 소모. "기본 low, 특정 업무만 high."

03종합 관점

기법 상당수의 공통 원리: "전체를 줄 단위로 통독하지 말고, 지능으로 필터링 메커니즘/스크립트를 만들게 하라." 페이블 등 최신 모델은 이미 어느 정도 잘하나, 이 기법들이 그 방향으로 강하게 편향시킴. 6·8번은 품질 트레이드오프가 있으니 사용 목적에 따라 선택.
