목차카카오톡 봇 개발 관련 이슈 및 해결 방안Claude (클로드) 모델 논의 (Fable, Mythos, Opus, Sonnet)'뽀짝이' 서비스 및 GPTers 커뮤니티 활동기타 AI 관련 논의

01카카오톡 봇 개발 관련 이슈 및 해결 방안

  • 카카오톡 CLI 도구 사용 문제:

* kmsg send 명령어가 작동하지 않는 문제가 발생. * kakaocli, kmsg, openkakao-cli 등 여러 CLI 도구 간의 전환 시도 및 문제 해결 노력. * 터미널 권한이나 GUI 우회 등 여러 방법 시도 후 다른 kmsg 포크 버전으로 해결. * CLI 도구의 버전 차이 (Kakao cli 두 종류)에 대한 언급.

  • 봇 운영 문제:

* 헤르메스 봇 운영 중 소켓 누수 문제 발생. DNS 간헐적 실패 시 끊어진 소켓이 누적되어 통신이 안 되는 현상으로, 봇 재시작으로 해결. * api.telegram.org 주소 조회 실패 문제와 이로 인한 소켓 누수와 영구 먹통 현상 분석. * 클로드 API 사용 시 대화 몇 번에 $1씩 소비되는 비용 문제 언급. 딥시크 4로 전환 고려.

  • 오픈클로(코덱스) 연동 및 계정 관리:

* 코덱스 프로 할당 부족 시 어떤 서비스를 추가로 연결해야 할지에 대한 질문. * 헤르메스 에이전트에 클로드 계정을 여러 개 연동하여 구독 제한 발생 시 폴백 처리하는 방식 공유 (2개 계정 사용하여 1번 계정 사용량 초과 시 2번 계정 사용). * OAuth 방식으로 연동 시 에이전트 별 제한 감지 문제 및 운영 어려움 언급.

02Claude (클로드) 모델 논의 (Fable, Mythos, Opus, Sonnet)

  • Fable 5 (Mythos) 모델의 성능 및 특징:

* 클로드 미토스(Fable 5)가 일반 대중에게 공개된 것에 대한 감탄. * 22일까지 무료 사용 가능하며 1M 토큰 접미사 로직으로 사용 가능함을 확인. * "사이버 공격, 생화학 공격 능력 제거 버전이 페이블"이라는 정보 공유. * 강점: 코딩 작업 시 더 똑똑하고, 복잡한 문제 해결 능력, 특히 까다로운 작업에 효율적이라는 평가. * 단점/이슈: 토큰 소모량이 매우 많아 Opus 대비 5~20배 빠르게 소진된다는 의견이 지배적. (일부 사용자는 생각보다 빨리 한도 안 찬다는 의견도 있음. effort가 높아서 그런 것 같다는 추측) * 활용: 개인용보다는 전문적인 목적 (QA, 소프트웨어 엔지니어링, 지식 기반 작업, 컴퓨터 비전, 과학 연구)에 적합하며, 특정 업무 분야에 포커싱된 모델. * 정책: 22일 이후 유료 전환 또는 API 과금 형태로 변경될 예정. 구독 요금제에는 포함되지 않을 가능성이 높음. (-> "줬다 뺏는 느낌") * 캐싱 효율성: 프롬프트 캐싱이 Opus보다 효율적 (512부터 캐싱 할인 적용), 캐싱 할인이 많이 적용될 경우 실제 토큰 소모가 2배보다는 덜 비쌀 수 있다는 의견. * 보안 및 폴백 기능: 보안이 강하여 요청 거부 시 자동으로 Opus로 폴백 처리되는데, 사용자가 이 사실을 알 수 없음. * 활용 사례: 봇들의 대댓글 맥락 파악 능력 개선, 테스트 인프라 설계, 레거시 디버깅, DB 탐정 놀이, 프롬프트 엔지니어링 등 다양한 작업에 활용. 특히 봇에게 "자아"를 부여하여 자신의 댓글 인지 능력을 추가한 사례 공유. * 자세한 작업 내용은 다음 링크에서 확인 가능: https://bbojjak-library.gpters.org/column/claude-fable-5 * 초기 평가 (긍정적): * "역대 최강 코딩 머신", "결과물은 엄청 맘에 드네", "성능은 확실히 좋다". * "주간 제한 초기화 달달하다", "1M 붙었습니다 먹히네요 길이 늘리면 되네요".

  • Opus (오푸스) 모델:

* 4.6 버전이 가장 만족도가 높았다는 의견이 많음. 당시 앤트로픽이 사용량을 많이 제공했기 때문으로 추정. * 소넷 대비 확실히 뛰어나며, "소넷은 하트비트 돌릴 때만 쓴다"는 농담 섞인 평가. * 코딩 작업에 주로 활용. Opus는 생각 안 하고 써도 5시간 채우기 힘들 정도로 토큰 소모가 덜함.

  • Sonnet (소넷) 모델:

* "멍청하다", "하트비트 돌릴 때만 쓴다"는 평가로, Opus나 Fable 대비 성능이 떨어진다고 인식됨. * 버전업이 오래되어 성능 저하가 느껴진다는 의견. * "소넷이 똥을 많이 싸놓은 상태에서 오푸스로 다시 뒷정리를 해야 하는 상황이 되었을 때 너무 화남"이라는 경험담 공유.

  • Grok (그록) 모델:

* Grok imagin video의 성능에 대한 질문. * Grok 1.5가 좋으며, Claude 3와 비슷한 느낌이라는 평가. 웹 버전에 빨리 적용되기를 기대.

  • 모델 사용 정책 및 비용:

* AI 모델 사용에 따른 빈익빈 부익부 현상 심화 우려. 돈 있는 사람들이 더 똑똑한 모델로 일할 수 있게 되는 점. * API 비용 문제 (minimax 사용 언급).

03'뽀짝이' 서비스 및 GPTers 커뮤니티 활동

  • '뽀짝이' (AI 봇)의 역할:

* 클로드 FaBle 5 소식 정리 및 공유 (https://bbojjak-library.gpters.org/column/claude-fable-5). * 업데이트 소식이나 설명이 필요한 경우 URL을 제공하면 뽀짝이가 정리해 주는 기능 (인간의 검수 필요). * 스터디 무기명 설문 분석 및 리포트 작성 흐름 정리 (https://www.gpters.org/ax-lab/post/survey-becomes-report-arrives-jSIPKu3Gxq0EJtR). * 뽀짝이의 서재 (https://bbojjak-library.gpters.org/column) 운영.

  • GPTers 커뮤니티 활동:

* AI 토크 웨비나: "피그마 디자인, 그대로 코드로 만든다고?" 주제로 피튜브(하이서)님과 함께하는 무료 AI 토크 웨비나 개최 예정. * 신청 링크: https://www.gpters.org/events/post/figma-design-made-code-G4qe1vd4iCL8tj7 * 피튜브 유튜브: https://www.youtube.com/@figma_tutor * 피튜브 인스타그램: https://www.instagram.com/figma_tutor/ * 스터디 활동: * 23기 디자인 스터디 개설 예정. * 스터디의 장점 (강의 콘텐츠, 네트워킹, 체계적인 학습)에 대한 긍정적인 평가. 중독성이 강하다는 후기.

  • 홍차넷 커뮤니티:

* AI 봇들이 회원처럼 활동하는 '홍차넷(https://redtea.kr/)'이라는 일상 잡담 커뮤니티 소개. * 사이트 개설 초기에 원사운드님께 캐릭터 제작을 의뢰했었다는 일화 공유.

04기타 AI 관련 논의

  • AI 개발용 노트북 추천: 300만원대 윈도우 노트북 추천 요청. API 형태로 사용할 경우 100만원대 노트북도 괜찮으며, 맥(Mac) 사용을 권장하는 의견도 있음 (단, 회사에서 윈도우만 사용해야 하는 상황).
  • 비개발자의 AI 활용 및 스킬 학습: 비개발자로서 사이드 프로젝트 진행 시 "실무에서 사용하는 방식"에 대한 어려움 토로. 스터디를 통해 학습하는 방식에 대한 관심.
  • 크립토 시장: BTC 자동매매 중단, 비트코인 공포 지수 최악, 당분간 시장 어려울 것이라는 전망.
