🎯 핵심 요약

  • TDD(테스트 주도 개발): 구현 전에 테스트를 먼저 만들어 AI의 "치팅(속임수)"을 막는다
  • 맥포 스킬은 강제 워크플로우 없이 필요한 스킬만 골라 쓸 수 있는 자유형 가이드북이다
  • Diagnose 스킬: AI가 추측 반복 대신 에러 재현 → 가설 수립 → 검증 순서로 일하게 만든다
1

AI 코딩의 4가지 핵심 문제

①

요구사항-구현 불일치

로그인 폼 만들어 달라 했더니 회원가입까지 싹 만들어버림

②

반복 설명

프로젝트 색깔·폰트·컴포넌트를 매번 다시 알려줘야 함

③

코드 품질 저하

AI가 만든 코드를 그냥 받으면 점점 누더기가 됨

④

아키텍처 붕괴

처음엔 깔끔하다가 기능 2~3개 추가하면 손대기 무서운 코드

2

맥포 핵심 스킬 5개

G
스킬 1 — 기획

Grilme — 디자인 컨셉 대화

문서만 던지는 게 아니라 AI와 함께 "현장에서 직접 맞추는" 과정을 거친다. 인테리어 업자와 현장 돌며 "여기 벽은 이런 느낌으로" 맞추는 것과 같다. 잘 쓴 문서보다 디자인 컨셉을 함께 만드는 과정이 중요하다.

▶ 1:20 영상에서 보기
D
스킬 2 — 기획

도메인 매핑

프로젝트 고유 용어를 AI에게 1회 정의하면 이후 반복 설명이 불필요하다. 토큰·시간 절약. 같은 컨텍스트를 여러 세션에 재사용 가능.

▶ 2:00 영상에서 보기
T
스킬 3 — 구현

TDD(테스트 주도 개발)

AI는 보통 구현 후 테스트를 덮는다 → 버그가 있어도 테스트가 같이 통과. 해결: 구현 전에 테스트를 먼저 만들어 AI가 치팅을 못 하게 한다. 핵심 원리: "피드백 루프 품질이 AI 출력의 천장이다." AI 탓하기 전에 테스트 환경부터 점검하라.

▶ 2:30 영상에서 보기
Dx
스킬 4 — 디버깅

Diagnose — 체계적 디버깅

"이거 왜 안 돼?" 물으면 AI가 추측→틀림→또 추측을 반복해 30분을 낭비한다. 해결: 에러 재현 → 가설 수립 → 가설 검증 순서를 강제한다. 의사가 증상 듣자마자 약 처방하는 게 아니라 검사→진단→처방하는 것과 같다.

▶ 3:40 영상에서 보기
IC
스킬 5 — 유지보수

Improve Code — 점진적 코드 개선

기능 추가 때마다 AI가 만든 코드를 즉시 리팩토링·개선한다. 점진적 개선으로 아키텍처 붕괴를 방지하고, 코드베이스가 장기적으로 건강하게 유지된다.

▶ 4:20 영상에서 보기
3

핵심 인사이트 — 피드백 루프

💡 "피드백 루프 품질이 AI 출력의 천장이다"

야구 타자가 스윙 후 공이 어디 갔는지 봐야 다음 스윙을 고칠 수 있듯, AI도 테스트가 빠르고 정확해야 자기 실수를 스스로 발견하고 고친다. AI 결과물이 별로라면 AI를 탓하기 전에 테스트 환경(피드백 루프)부터 점검하라.
