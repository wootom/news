Opus 5.5 환경에서는 대형 하네스가 토큰·속도·지시 이행을 저해한다고 주장한다.

Opus 5.5에서는 대형 하네스보다 실행 도구와 짧은 프로젝트 규칙을 남기라고 제안한다.

01핵심 개요

  • 메이커 에반은 gstack과 Superpowers 같은 대형 하네스를 Opus 5.5 환경에서 정리해야 한다고 주장했다.
  • 본인 클로드 스킬 폴더에는 162개 폴더와 설명문 5만2,000자가 있었고, gstack 용량은 1.1GB라고 밝혔다.
  • gstack의 배포 스킬 문서는 16만8,000바트, 기획 리뷰 스킬은 13만7,000바, QA 스킬은 7만4,000바라고 제시했다.
  • Superpowers는 적용 가능성이 1%라도 있으면 스킬을 반드시 호출하도록 하며, 단순 작업에도 절차를 강제한다고 설명했다.
  • 실행 기능을 제공하는 도구는 남기되, 모델의 사고 절차를 지시하는 문서는 줄이고 프로젝트 규칙만 약 10줄로 남기라고 제안했다.

02핵심 주장 / 논점 구조

  • 하네스는 클로드 코드 위에 추가로 씌우는 작업 규칙 묶음이며, gstack과 Superpowers가 대표 사례로 제시됐다.
  • 모델이 서툴던 시절에는 계획·리뷰·배포 절차를 문서로 제공하는 하네스가 유용했다고 평가했다.
  • Opus 5.5는 스스로 계획, 파일 탐색, 검증, 작업 분할을 수행하므로 외부 절차가 중복된다고 주장했다.
  • 대형 하네스는 토큰과 시간을 소모하고, 사용자가 처음 요청한 핵심 지시를 문서 사이에 묻게 만들 수 있다고 말했다.

03스킬 폴더와 gstack 문서 규모

  • 본인이 확인한 클로드 스킬 폴더는 162개였으며, 스킬 설명을 합치면 5만2,000자라고 밝혔다.
  • 이 설명 목록은 대화를 열 때마다 먼저 깔리므로, 사용자가 요청하기 전부터 읽고 시작하는 구조라고 설명했다.
  • gstack 하나가 차지하는 용량은 1.1GB이며, 내부 스킬은 53개라고 제시했다.
  • 배포 스킬 문서는 16만8,000바트로 영어 기준 약 4만 토큰, 기획 리뷰 스킬은 13만7,000바라고 말했다.

04강제 호출 규칙과 훅의 지연

  • gstack은 모델이 사용자에게 질문할 때도 앞뒤로 스크립트가 실행되도록 훅을 걸어 놓았다고 설명했다.
  • Superpowers 시작 스킬 문서에는 적용 가능성이 1%라도 있으면 반드시 불러야 한다는 문구가 있다고 소개했다.
  • 질문하기 전에도 스킬부터 확인하도록 되어 있고, 단순 질문이라는 판단을 핑계로 본다는 문구도 있다고 말했다.
  • 오타 하나 수정하는 작업에도 스킬 탐색, 브레인스토밍, 계획, 체크리스트를 거쳐 분 단위가 걸릴 수 있다고 주장했다.

05Opus 5.5에서 절차가 충돌하는 이유

  • 과거 모델은 긴 규칙 중 필요한 부분만 골라 따르는 경향이 있었지만, Opus 5.5는 적힌 규칙을 끝까지 지키려 한다고 설명했다.
  • 체크리스트가 20개면 20개를 모두 수행하고, 문서에 질문하라고 적혀 있으면 불필요한 질문도 할 수 있다고 말했다.
  • 모델 자체의 계획과 하네스 문서의 계획이 동시에 존재해 절차가 두 벌이 된다고 주장했다.
  • 문서에 '반드시'처럼 강한 지시가 있으면 모델은 자체 판단보다 문서 절차를 따르게 된다고 설명했다.

06프로젝트 규칙 누락과 규칙 충돌

  • 하네스 문서는 모든 프로젝트에 맞추려는 일반론이므로, 특정 프로젝트의 규칙과 충돌할 수 있다고 말했다.
  • 사용자 프로젝트에는 특정 폴더를 건드리지 않거나 작업 순서를 지키는 등 별도 규칙이 있다고 예시를 들었다.
  • 하네스 문서가 길어질수록 사용자가 처음 요청한 한 줄 지시가 묻힐 수 있다고 주장했다.
  • 영상 제작 세션에서는 같은 모드 안내문이 시작과 동시에 두 번 들어와 대화 앞부분을 차지한 사례를 언급했다.

07남길 기능과 정리 절차

  • 여러 명이 동일한 방식으로 리뷰와 배포를 해야 하는 팀 환경에서는 하네스 문서가 여전히 유용할 수 있다고 말했다.
  • 처음 시작하는 사람에게 좋은 작업 순서를 보여 주는 교재로도 쓸모가 있다고 평가했다.
  • gstack의 브라우저 도구처럼 실제 실행 기능을 제공하는 것은 프롬프트가 아닌 도구이므로 남겨야 한다고 구분했다.
  • 클로드 데스크탑 앱에서 스킬·플러그인 목록을 확인하고, 외부 대형 묶음과 설정 훅을 점검하라고 제안했다.
  • 바로 삭제하지 말고 백업 폴더로 옮긴 뒤 일주일 사용하고, 프로젝트별 필수 규칙만 약 10줄로 줄이라고 권했다.

용어뜻
