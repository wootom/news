Grok Bot과 Notion의 공통 기억·예약 루틴으로 반복 설명과 업무 위임을 실습한다

Grok Bot의 공통 기억과 Notion 카드 예약 위임을 확인 코드로 검증한다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

01핵심 개요

  • 가상 프로젝트 ‘달빛 카페’의 네 가지 정보를 공통 기억에 저장하고, 새 Bot이 이름표만으로 다시 꺼내는 과정을 시연한다.
  • 저장 요청에는 기존 기억을 수정·삭제하지 말고 저장 후 다시 읽으라는 조건을 넣어, 네 값이 보이는지 확인한다.
  • Notion 보드에 작업 카드 한 장을 만들고, 관리자 Bot의 예약 루틴이 작업자 Bot에게 카드를 전달하도록 설정한다.
  • 실행 탭의 성공 기록, 카드의 완료 상태, 결과 칸의 확인 코드 MOON-1013을 성공 기준으로 삼는다.
  • 프로젝트명·대상·핵심 메시지·확인 코드를 연습용 값으로 바꾸고, 종료 후에는 루틴을 메뉴에서 직접 일시정지한다.

02핵심 주장 / 논점 구조

  • 영상은 Grok Bot과 Notion을 연결해 공통 기억을 공유하는 실습과, Notion 카드 업무를 예약 루틴으로 위임하는 실습을 진행한다.
  • 첫 실습은 새 Bot에게 프로젝트 정보를 주지 않은 채 이름표만으로 저장된 네 값을 불러오는지 확인한다.
  • 두 번째 실습은 보드의 카드 한 장을 관리자 Bot이 작업자 Bot에게 넘기고, 결과를 Notion에 남기는 과정을 보여준다.
  • 두 실습 모두 확인 코드 MOON-1013이 결과에 그대로 있는지를 검증 기준으로 사용한다.

03공통 기억 저장과 이름표 지정

  • Grok 앱 연결 화면에서 Notion 항목을 열고, 계정 옆에 ‘연결됨’ 표시가 있으면 다시 인증하지 않고 진행한다.
  • Notion 문서의 네 값은 프로젝트명 ‘달빛 카페’, 대상 ‘초보 창업자’, 핵심 메시지 ‘주문 누락을 줄인다’, 확인 코드 ‘MOON-1013’이다.
  • Notion이 연결된 Bot에게 사용자 공통 기억에 [Notion 공유기억 데모]라는 이름표와 네 값을 추가하도록 요청한다.
  • 기존 기억을 고치거나 지우지 말고, 저장한 뒤 다시 읽어 보여 달라는 조건을 함께 제시한다.

04새 Bot으로 기억을 교차 확인

  • 같은 대화창에서 ‘공유 기억 확인자’라는 새 Bot을 만들고, 역할을 공통 기억을 찾아 읽고 확인하는 일로 한정한다.
  • 확인 요청에는 프로젝트명·확인 코드·Notion 링크를 넣지 않아, Bot이 요청에서 값을 얻는 상황을 피한다.
  • Bot에게 [Notion 공유기억 데모] 항목만 활용해 영상 제목 3개를 제안하고 네 값을 함께 보여 달라고 요청한다.
  • 응답에는 달빛 카페, 초보 창업자, 주문 누락을 줄인다는 메시지, MOON-1013이 저장된 값 그대로 제시된다.
  • 확인 코드가 빠지면 저장과 질문에 사용한 이름표가 같은지 먼저 확인하라고 안내한다.

05Notion 보드와 Bot 역할 구성

  • 관리자 Bot에게 Notion 보드를 만들도록 요청하며, 속성은 작업·결과·담당 Bot·상태 네 가지로 구성한다.
  • 상태 값은 ‘할 일’, ‘진행 중’, ‘완료’이며, 작업자 Bot의 이름은 ‘Notion 데모 작업자’다.
  • 작업자 Bot 주소 맨 끝의 ID를 확인해 이후 루틴 문구에 넣는다.
  • 예시 카드 ‘자동 데모 A’에는 영상 제목 3개와 주문 누락 예방 체크리스트 3개를 적고, 담당 Bot과 상태를 지정한다.
  • 결과와 카드 본문은 비워 두지만, 카드 이름 자체에 수행할 과제가 들어 있어 작업 기준으로 쓸 수 있다.

06예약 루틴의 조건과 실행 과정

  • 관리자 Bot의 루틴은 지정한 시각에 할 일 상태이고, 담당 Bot이 작업자이며, 이름에 ‘자동 데모 A’가 포함된 카드만 고른다.
  • 루틴은 선택한 카드 상태를 진행 중으로 바꾸고, 카드 주소와 과제를 작업자에게 한 번 보낸 뒤 결과 저장과 완료 처리를 지시한다.
  • 영상의 트리거는 10월 13일 오후 6시 23분과 6시 38분으로, 15분 간격 두 번이며 종료 조건은 지시문에 적었다.
  • 실행 탭에는 성공 1건이 기록됐고, 오후 6시 23분 예약에 대한 실제 실행 기록 시각은 6시 26분이었다.
  • 작업자는 카드 본문이 비어 있어 카드 이름을 기준으로 수행했다고 답했고, 결과를 저장한 뒤 상태를 완료로 바꿨다.

07결과 검증과 실습 적용 시 주의점

  • Notion에서 같은 카드를 직접 열어 완료 상태와 결과를 확인하며, 결과 칸 첫머리에 MOON-1013이 있는지 점검한다.
  • 결과에는 제목 제안과 체크리스트가 기록됐으며, 달빛 카페 사례는 가상 프로젝트에 붙인 제안이지 실제 매장 성과가 아니다.
  • 다른 프로젝트에 적용할 때는 이름표·프로젝트 이름·대상·핵심 메시지·확인 코드를 바꾸고, 자주 맡기는 작업으로 요청을 조정한다.
  • 처음에는 실제 고객 정보 대신 연습용 값을 쓰고, 확인 코드는 MOON-1013처럼 평소 쓰지 않는 짧은 문자열로 정한다.
  • 루틴은 매년 10월 13일로 저장됐으므로 실습이 끝나면 메뉴에서 일시정지하고, 메뉴 표시가 ‘재개’로 바뀌었는지 확인한다.

08용어 사전

용어뜻
사용자 공통 기억Bot 대화에서 저장하고 다시 꺼내 쓰도록 설정한 정보이며, 이번 실습에서는 프로젝트 네 값을 이름표와 함께 저장했다.
이름표공통 기억 항목을 구분하는 표식으로, 새 Bot에게 값 대신 [Notion 공유기억 데모]만 제시해 불러오게 했다.
관리자 Bot공통 기억을 저장한 Bot이자 보드 카드 조건을 확인하고 작업자 Bot에게 과제를 전달하는 역할을 맡는다.
작업자 Bot관리자 Bot에게 전달받은 카드의 이름과 본문을 기준으로 과제를 수행하고 결과와 완료 상태를 Notion에 기록한다.
예약 루틴지정 시각에 조건에 맞는 Notion 카드를 찾아 진행 중으로 바꾸고 작업자 Bot에게 넘기도록 설정한 자동 실행 절차다.
