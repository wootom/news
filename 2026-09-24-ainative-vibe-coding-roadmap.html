비개발자도 개발 도구·설계·실전 토론을 거쳐 바이브코딩 고수로 성장할 수 있다.

도구·설계·AI 토론·실전 트러블슈팅으로 배우는 비개발자 바이브코딩 로드맵.

01핵심 개요

  • 바이브코딩 고수의 목표를 원하는 시스템을 자유자재로 만드는 사람으로 정의하고, 비개발자용 5단계 학습 순서를 제시했다.
  • 첫 단계로 맥북, VS 코드, 터미널 사용에 익숙해지기를 권하며 PWD·CD·LS·RM 등 기본 명령어를 설명했다.
  • 도메인 스토리텔링과 도메인 주도 설계로 현실의 요구사항을 코드 모델로 옮기는 방법을 먼저 익혀야 한다고 말했다.
  • 레이어드 아키텍처와 AI 인터뷰를 통해 SaaS 구독 시스템 같은 기능의 설계 논점과 리스크를 확인하는 방식을 시연했다.
  • 멀티에이전트·하네스보다 실전 트러블슈팅, 개발 이론 학습, AI와의 트레이드오프 토론이 개인에게 더 중요하다고 강조했다.

02핵심 주장 / 논점 구조

  • 영상은 이전 라이브의 개발 프로젝트 진행 순서에 이어, 코드 경험이 전혀 없는 사람을 위한 바이브코딩 학습 순서를 다뤘다.
  • 목표는 바이브코딩 성공 자체가 아니라 원하는 시스템을 자유자재로 만드는 ‘바이브코딩 고수’가 되는 것이라고 정의했다.
  • 학습 순서는 개발 도구 익히기, 도메인 주도 설계, 레이어드 아키텍처, 프롬프팅, 실전 투입과 이론 학습으로 제시됐다.
  • AI가 구현을 맡더라도 설계와 브리핑을 이해하는 인간의 이해도가 병목이 될 수 있으므로 설계 학습이 필요하다고 말했다.

03개발 도구와 터미널 기본기

  • 발표자는 윈도우의 WSL 등 우회 문제를 줄이기 위해 맥북 구매를 첫 단계로 제안했고, 맥북 에어도 괜찮다고 언급했다.
  • VS 코드와 터미널 조작은 투자 대비 효과가 크며, 코덱스 앱이나 오르카를 쓰더라도 직접 터미널을 다룰 일이 있다고 설명했다.
  • VS 코드에서 터미널을 여는 단축키로 커맨드 J를 소개하고, 현재 경로 확인에는 PWD, 폴더 이동에는 CD, 목록 확인에는 LS를 사용했다.
  • 파일 삭제에는 RM을, 비어 있지 않은 폴더 삭제에는 강력한 삭제 명령을 사용할 수 있다고 설명하며 삭제 명령의 위험성도 언급했다.
  • 터미널에서 프로젝트 폴더로 이동한 뒤 code . 명령어로 해당 경로의 VS 코드를 열 수 있다고 시연했다.

04VS 코드 Git 기능과 Oh My Zsh 활용

  • 터미널 환경 개선을 위해 Oh My Zsh 설치를 권했고, 설치 시 클로드에게 ‘공식 문서 기반해서 정확하게 설치’하도록 요청하라고 말했다.
  • VS 코드의 X 버튼은 터미널 패널을 숨기는 기능이고, 휴지통 버튼은 터미널 세션을 종료하는 기능이라고 구분했다.
  • VS 코드에서 수정 파일을 Git add하고 커밋 메시지를 작성해 커밋한 뒤, 푸시하면 원격 저장소에 반영된다고 설명했다.
  • 커밋과 푸시는 보통 AI에 맡기더라도, 사용자가 손으로 처리할 수 있으면 종종 편리하므로 익혀두길 권했다.

05도메인 주도 설계와 서비스 모델링

  • 도메인 주도 설계는 추상적인 현실의 프로세스와 요구사항을 소프트웨어 코드로 모델링하는 설계 기법으로 설명됐다.
  • 도메인 스토리텔링을 도메인 주도 설계의 재료로 활용하며, 코드를 몰라도 설계 기법 자체는 공부할 수 있다고 말했다.
  • 엔티티, 밸류 오브젝트, 애그리거트, 도메인 서비스, 리포지토리를 구분하는 것이 주요 학습 요소로 제시됐다.
  • 연관된 데이터베이스 테이블이 10개 미만인 간단한 서비스는 이 단계까지 학습하면 구현할 수 있다고 봤다.
  • 도메인 주도 설계 학습 기간은 집중하면 1주일, 여유 있게는 약 2주일로 제시했으며 업무 자동화와 개인 사이드 프로젝트 수준을 언급했다.

063계층 아키텍처와 AI 설계 인터뷰

  • 레이어드 아키텍처는 화면, 기능 처리, 데이터 저장 코드를 한 파일에 두지 않고 역할별 파일과 계층으로 나누는 설계 방식이라고 설명했다.
  • 초보자는 프레젠테이션·비즈니스·데이터의 3계층만 나눠도 나쁘지 않은 코드베이스를 만들 수 있다고 말했다.
  • 넥스트.js와 수퍼베이스 기반 SaaS에 레몬스퀴지 구독 시스템을 붙이는 사례로 3계층 관점의 설계 프롬프트를 시연했다.
  • AI에게 모호하거나 위험한 부분을 논의점으로 제시하게 하면 결제사, 개인·워크스페이스 청구, 웹훅, 무료 체험, 환불 같은 쟁점을 먼저 확인할 수 있다고 설명했다.
  • AI 인터뷰에서는 질문을 한 번에 하나씩 하게 하고, 설계 문서는 아티팩트 대신 마크다운으로 작성하도록 지시하는 팁을 제안했다.

07실전 트러블슈팅과 트레이드오프 훈련

  • 프롬프팅은 책만으로 고수가 되기 어렵고, 기본기를 잡는 데는 도움이 되지만 실전 감각은 반복 사용으로 익혀야 한다고 말했다.
  • 추천 도서로 ‘프롬프트 디테일’, ‘로지컬 싱킹’, ‘리팩터링 2판’, ‘엔터프라이즈 소프트웨어 아키텍처 패턴’, ‘클린 아키텍처’, ‘클린 코드’를 언급했다.
  • 실전에서는 정답 하나보다 트레이드오프가 중요하며, 여러 설계 중 현재 상황에서 가장 적합한 선택을 찾는 경험이 필요하다고 설명했다.
  • 레몬스퀴지 웹훅 처리의 동기·비동기 방식, 수퍼베이스 장애, 레디스 추가 여부, DB 트랜잭션과 동시성 대응을 토론 사례로 들었다.
  • 개인 바이브코더에게는 하네스 엔지니어링, 스킬, 멀티에이전트보다 실전 구현·트러블슈팅·개발 이론 학습의 투자 대비 효과가 더 크다고 주장했다.

08용어 사전

용어뜻
도메인 스토리텔링서비스가 다루는 사람·행동·규칙·용어를 서술해 도메인 주도 설계의 재료로 쓰는 방식이다.
도메인 주도 설계현실의 추상적인 프로세스와 요구사항을 엔티티·밸류 오브젝트·리포지토리 등으로 코드 모델링하는 설계 기법이다.
레이어드 아키텍처UI, 비즈니스 로직, 데이터·DB처럼 역할별로 코드를 계층화해 적절한 위치에 배분하는 방식이다.
3계층 아키텍처프레젠테이션·비즈니스·데이터의 세 계층으로 기능 코드를 나누는 레이어드 아키텍처의 기본 형태다.
트레이드오프레디스 추가, 동기·비동기 처리처럼 장단점이 공존하는 선택지에서 현재 상황에 맞는 결정을 내리는 과정이다.
Oh My Zsh발표자가 맥북 터미널 환경을 개선하고 점점점 같은 이동 기능을 쓰기 위해 설치를 권한 Zsh 플러그인이다.
