Anthropic Fable 5.2 프롬프팅 10가지 규칙: 고효율 사용법과 주의사항

Fable 5.2를 효율적으로 쓰려면 High effort, 작업 검증, 기존 규칙 정리, 코드 소유권 부여가 필수입니다.

영상 발화자의 견해·경험을 원문에 근거해 정리한 요약입니다.

Effort Level 설정과 비용 효율성

  • Fable 5.2는 API에서 High가 기본값이지만 Claude Code에서는 Medium이 기본으로 설정되어 있어 High로 수동 변경을 권장한다.
  • Frontier Code 2.0 벤치마크에서 High 설정은 45.3% 점수를 기록하며 Opus 5.5 Max와 유사한 성능을 절반의 비용으로 제공한다.
  • Medium 설정은 37.6%로 성능이 현저히 낮아지므로, 기술적으로 도전적인 장기 에이전틱 작업에는 High 또는 Extra High를 사용해야 한다.

환각 방지와 작업 완결성 확보

  • Fable 5.2는 이전 모델보다 추론을 사실로 서술하거나 존재하지 않는 파일을 지어내는 환각률이 높아 출력 전 테스트 실행을 지시해야 한다.
  • 시스템 카드에 따르면 파일 누락 시 2% 확률로 가짜 파일을 생성하며, 이러한 단축 경로를 방지하기 위해 검증 프롬프트를 사용해야 한다.
  • 장기 에이전틱 작업 중 중간에 작업을 중단하는 빈도가 높아 '작업을 끝까지 마무리하라'는 명시적 지시를 통해 중단 확률을 절반으로 줄일 수 있다.

기존 규칙 파일(Claude.md) 재점검

  • Fable 5.2는 주어진 규칙을 매우 엄격하게 따르기 때문에, 이전 모델용으로 작성된 과도하게 엄격한 스타일 가이드나 규칙은 오히려 성능을 저해한다.
  • 불필요한 엄격한 지침을 제거하여 모델이 설계된 대로 자유롭게 작동할 수 있는 공간을 확보하는 것이 새로운 프롬프팅 전략의 핵심이다.

사고 과정 제어와 디스틸레이션 차단

  • Fable 5.2는 '생각하지 마라'는 지시를 무시하고 항상 토큰을 소모하며 사고하므로, 비용 절감을 위해 Low나 Medium effort level을 사용해야 한다.
  • 단계별 추론 과정을 설명해 달라는 요청은 내부 분류기에 의해 디스틸레이션 공격으로 오인되어 차단될 수 있어 주의가 필요하다.

코드 소유권과 서브에이전트 위임

  • 모델에게 코드베이스 소유권을 명시적으로 부여하면 코드 중복을 줄이고 최적화된 결과를 얻지만, 최소한의 변경만 원한다면 소유권을 주지 말고 구체적으로 지시해야 한다.
  • 서브에이전트 사용에 대한 기존 규칙을 삭제해야 하며, Fable 5.2는 필요 시 스스로 서브에이전트를 생성하여 작업을 검증하므로 강제 지시는 토큰 소모만 증가시킨다.

긴 작업 업데이트와 응답 톤 제어

  • 긴 도구 호출 작업 중 침묵하는 것을 방지하려면 업데이트를 요청해야 하지만, 매 도구 호출마다 응답을 지시하면 토큰 사용량이 20% 증가할 수 있다.
  • 응답의 톤과 길이는 effort level에 영향을 받지 않으며, 원하는 형식을 얻으려면 프롬프트나 Claude.md 파일에 명시적으로 기록해야 한다.
