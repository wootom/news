Fable 5.1은 짧은 작업에서 한도와 비용이 Opus 5보다 더 빨리 소진될 수 있다.

짧은 작업의 Fable 5.1은 캐시 쓰기 비용과 한도 차감 때문에 Opus 5보다 비쌀 수 있다.

01핵심 개요

  • Fable 5.1의 입력·출력 가격은 100만 토큰당 10달러·50달러로 Opus 5의 정확히 2배이며, 캐시 읽기만 75% 인하됐다.
  • Max 요금제에서는 Fable 사용량이 주간 한도의 50%까지만 포함되고, 같은 세션도 Opus보다 약 2배 무겁게 차감된다.
  • 실측에서 동일 저장소·프롬프트 작업은 Fable 5.1이 80초로 더 빨랐지만, 평균 비용은 2.98달러로 Opus의 1.53달러보다 1.94배였다.
  • Fable 5.1 비용 2.98달러 중 캐시 쓰기가 2.48달러, 83%를 차지해 캐시 읽기 할인 효과가 짧은 작업에서는 작았다.
  • 영상은 기본 모델을 Opus 5로 두고, Fable 5.1은 긴 세션·대형 컨텍스트·고난도 추론에만 쓰라고 제안한다.

02핵심 주장 / 논점 구조

  • Fable 5.1은 장시간 에이전트 작업을 겨냥한 모델이지만, 짧은 작업에 기본값으로 쓰면 Max 한도와 비용 소진이 빨라질 수 있다는 것이 영상의 주장이다.
  • Max에서 Fable은 같은 세션이 Opus보다 약 2배 차감되고, Fable 5.1의 긴 출력 특성까지 겹치면 한도가 최대 4배 속도로 빠질 수 있다고 설명한다.
  • Anthropic 문서는 대부분의 작업을 Claude Opus 5로 시작하고, Fable 5.1은 까다로운 추론과 긴 에이전트 작업에 쓰라고 안내한다고 소개한다.
  • 영상 제작자는 실측과 문서 내용을 근거로 기본값을 Opus 5로 바꾸고, Fable은 조건부로 사용하는 방식을 택했다.

03Fable 5.1의 가격·사양과 개선 영역

  • Fable 5.1은 Fable 5의 후속 모델이며 입력은 100만 토큰당 10달러, 출력은 50달러로 Fable 5와 가격이 같다.
  • Opus 5의 가격은 입력 100만 토큰당 5달러, 출력 25달러로 Fable 5.1 가격의 절반이다.
  • Fable 5.1의 캐시 읽기 가격은 100만 토큰당 1달러에서 25센트로 75% 내려갔다.
  • 컨텍스트 창은 100만 토큰, 최대 출력은 12만8천 토큰이며 생각하기 기능은 항상 켜져 있고 끌 수 없다.
  • Anthropic이 밝힌 개선 영역은 긴 코딩 세션, 문서·스프레드시트, 리서치, 차트 읽기, 긴 컨텍스트, 컴퓨터 조작이다.

04Max·Pro 요금제에서 달라지는 한도 처리

  • Max 요금제에는 Fable이 기본 포함되지만, 주간 한도의 50%까지만 Fable에 사용할 수 있다.
  • Fable용 50% 한도를 모두 쓰면 Fable만 막히고 Opus는 계속 사용할 수 있다고 설명한다.
  • 문서상 Fable은 같은 세션이라도 Opus보다 대략 2배 무겁게 한도에서 차감된다.
  • Pro 요금제에서는 Fable이 한도에 포함되지 않으며, 별도 크레딧을 충전해 API 가격 그대로 결제한다.
  • 영상은 Pro 사용자가 모델 목록에서 Fable을 선택하는 순간 카드 결제가 시작된다고 표현하며, Fable 5.1에는 7월 Fable 5 때와 같은 100달러 제공이 없었다고 말한다.

05동일 작업 실측에서 나타난 비용 차이

  • 제작자는 같은 저장소·프롬프트·권한으로 컴포넌트 폴더 전체를 읽고 각 파일의 입력값을 표로 정리하게 했으며, 파일 수정은 막았다.
  • 캐시 상태에 따른 편향을 줄이기 위해 모델 순서를 바꿔 총 두 차례 비교했다고 설명한다.
  • Opus 5는 100초 이내에 끝났고 출력은 8,500~9,400토큰, 비용은 1.32달러와 1.75달러였다.
  • Fable 5.1은 같은 프롬프트에서 80초에 끝났고 출력도 더 적었지만, 두 번 모두 비용이 2.98달러였다.
  • 평균 비용은 Opus 5가 1.53달러, Fable 5.1이 2.98달러로 Fable이 약 1.94배였다고 집계했다.

06캐시 쓰기 비용이 짧은 작업에서 불리한 이유

  • Fable 5.1 실측 비용 2.98달러 가운데 캐시 쓰기는 2.48달러로 전체의 83%였고, 출력은 43센트, 캐시 읽기는 7센트였다.
  • Fable의 캐시 읽기 가격 인하는 이 작업에서 전체 비용의 2%에 해당하는 항목에만 적용된 셈이라고 설명한다.
  • 캐시 쓰기는 Fable이 100만 토큰당 20달러, Opus가 10달러여서 이 항목에서 2배 차이가 난다.
  • 실측에서 캐시 읽기는 Opus가 약 58만 토큰, Fable이 약 26만 토큰으로 Opus가 더 많았지만 총비용은 Fable이 더 높았다.
  • 저장소 내용을 서버에 처음 저장하는 것은 캐시 쓰기이고 이후 다시 활용하는 것은 캐시 읽기이므로, 짧은 작업은 쓰기 비용을 나눌 기회가 적다고 설명한다.

07Fable 5.1 사용 특성과 권장 운용법

  • Anthropic 문서에는 Fable 5.1이 작은 수정에도 파일 전체를 다시 쓰고, 도구를 한 번에 하나씩 호출하는 경향이 있다고 적혀 있다고 소개한다.
  • 긴 작업에서 중간 보고가 적고, Claude Code·API의 기본 에포트는 High이며 웹 기본값은 Medium이라고 설명한다.
  • 문서는 Medium 에포트의 Fable 5.1이 Fable 5의 High와 비슷하다고 안내하며, 문장 밀도·목록 사용·요약 방식은 프롬프트로 조정할 수 있다고 한다.
  • 캐시가 약 14만~20만 토큰 이상 쌓이는 긴 세션에서는 Fable의 캐시 읽기 25센트가 Opus의 50센트보다 낮아 턴당 비용이 유리해질 수 있다.
  • 제작자는 큰 리팩터링, 100만 토큰 컨텍스트, Opus를 High로 써도 틀리는 작업에만 Fable을 켜고 Medium 에포트·부분 수정·병렬 읽기 지시를 사용한다.

Opus 5영상에서 기본 모델로 권장한 Claude 모델로, Fable 5.1보다 입력·출력 가격과 Max 차감 무게가 낮다고 비교된다.

캐시 읽기저장된 캐시를 다시 활용하는 비용으로, Fable 5.1은 100만 토큰당 25센트로 인하됐다.
