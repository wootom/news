클로드를 상위 1%처럼 쓰는 법 — 모델 선택부터 코워크·코드까지

01핵심 개요

항목내용
출연·형식Futurepedia 채널의 튜토리얼 영상. 화자는 수백 시간 클로드를 사용하고 공식 문서를 전부 읽었다고 밝히며, 초보자용 원샷 질문부터 실제 업무를 맡기는 숙련자 수준까지 단계별로 안내한다.
핵심 문제의식클로드는 사용설명서가 따로 없어 대부분의 사용자가 기능의 일부만 쓰고 있으며 그마저도 잘못 쓰는 경우가 많다는 것이 출발점이다.
구조메모리 이전 → 모델·이펏 레벨 선택 → 프롬프트 습관 → 커넥터 → 프로젝트 → 스킬 → 코워크(Co-work) → 클로드 코드(Claude Code) 순으로 난이도가 올라가는 구성이다.
모델 전략화자는 하이쿠는 거의 쓰지 않고, 프로 플랜은 소넷을 기본값으로 어려운 문제만 오퍼스로 전환하라고 권한다. 맥스 플랜에서는 오퍼스를 주로 쓰고 창작 작업에서만 소넷을 선호한다고 밝힌다.
이펏(effort) 레벨미디엄은 일상 작업, 하이는 코딩·분석, 익스트라 하이는 에이전틱·멀티스텝 코딩 작업에 쓰라고 권한다. 불필요하게 높이면 시간만 오래 걸리고 결과가 나빠질 수 있다고 경고한다.
최종 메시지채팅 → 모델/이펏 선택 → 도구 연결 → 프로젝트 설정 → 스킬 제작 → 코워크로 위임 → 코드로 실제 제작, 이 순서로 옮겨가라는 것이 화자의 결론이다.

02핵심 기능/내용 구조

영상은 크게 세 층위로 구성된다. 첫째 층위는 채팅(Chat) 안에서의 기초 설정이다. 다른 AI에서 쌓아온 기억을 클로드로 이전하는 방법, 무료 플랜과 유료 플랜의 화면 차이(코워크·코드 탭 유무), 모델 드롭다운에서 모델과 이펏 레벨을 고르는 법, 그리고 프롬프트를 잘 쓰는 두 가지 습관(맥락 덤핑, 비판적으로 되묻기)을 다룬다. 둘째 층위는 맥락을 지속적으로 공급하는 장치들이다. 커넥터(Connectors)로 Gmail·캘린더·구글드라이브·이미지 생성 도구(Higsfield 등)를 연결하는 법, 프로젝트(Projects)로 대화·지식베이스·커스텀 지침을 격리된 작업공간에 묶어두는 법, 스킬(Skills)로 반복되는 워크플로를 레시피 카드처럼 저장해 다음부터 한 번에 실행하는 법을 설명한다. 셋째 층위는 위임형 에이전트다. 코워크는 목표만 던지면 스스로 계획을 세우고 체크리스트를 수행하는 비서 역할이며, 클로드 코드는 코드를 몰라도 원하는 앱·자동화·크롬 확장 프로그램을 자연어로 설명하면 만들어주는 엔지니어 역할이라고 구분한다.

03기술적 맥락

영상에서 언급되는 클로드 관련 개념은 다음과 같다. 모델 라인업은 하이쿠(가장 빠르지만 화자는 거의 안 씀), 소넷(빠르면서 추론력 좋은 일상용 모델), 오퍼스(멀티스텝 작업에 강하고 작업 중 스스로 점검), 페이블(오퍼스보다 토큰 소모가 커서 오퍼스가 막힐 때만 전환)이다. 이펏 레벨은 모델이 답을 내기 전에 쓰는 사고 시간(토큰량)을 조절하는 별도 설정으로, 모델 선택과는 독립적인 축이다. 커넥터는 외부 서비스와 클로드를 연결하는 기능으로, 목록에 없는 서비스는 URL만 입력하면 붙는 커스텀 커넥터도 지원한다. 프로젝트는 서로 참조하지 않는 격리된 메모리 공간이며 하루 한 번 자동으로 메모리가 갱신된다. 스킬은 대화에서 다듬어진 프로세스를 통째로 패키징한 것으로, 슬래시(/)로 이름을 불러 명시적으로 실행할 수도 있다. 코워크는 세션마다 클라우드상의 별도 컴퓨터를 할당받아 작업하며, 데스크톱 앱에서는 로컬 컴퓨터의 지정 폴더에서 동작한다는 차이가 있다. 클로드 코드는 데스크톱 앱에서는 로컬 폴더를, 웹에서는 깃허브 저장소를 지정해야 하며, 플랜 모드로 전환하면 실행 전에 계획을 먼저 검토할 수 있다.

04전략적 의미

화자가 강조하는 것은 도구를 층위별로 옮겨 타는 전략이다. 채팅은 사고를 도와주는 파트너, 코워크는 목표를 맡기는 비서, 코드는 실제로 결과물을 만드는 엔지니어로 역할이 뚜렷이 나뉘므로, 사용자가 자기 작업의 성격에 맞춰 세 계층을 오가야 한다는 것이다. 특히 모델·이펏 레벨을 잘못 고르면 사용량 토큰을 낭비하고 리셋을 기다려야 하므로, 이 설정을 가장 먼저 익혀야 한다고 반복해서 강조한다. 또한 개발자가 아니어도 클로드 코드로 실사용 가능한 도구(프리미어 프로 플러그인, 모바일 앱 등)를 만들 수 있다는 점을 자신의 사례로 들며, 비개발자에게도 에이전틱 도구 진입을 권한다. 프로젝트를 업무·개인·창작 등으로 분리해 서로 참조되지 않게 하는 것도 전략적 선택으로 제시되는데, 이는 맥락 오염을 막아 각 프로젝트의 응답 품질을 유지하기 위해서다.

05핵심 워크플로우·방법론

  1. 다른 AI에서 메모리 이전하기: 설정 → Capabilities → "Import memory from other AI providers"에서 Start import를 누른다. 안내된 프롬프트를 복사해 ChatGPT·Gemini 등 기존에 쓰던 AI에 붙여넣고, 그 응답을 다시 복사해 클로드에 붙여넣은 뒤 "Add to memory"를 누르면 끝난다. 같은 설정 화면에서 "search and reference chats"와 "generate memory from chat history" 토글도 켜 두어야 클로드가 시간이 지날수록 사용자를 더 잘 이해한다.
  2. 모델과 이펏 레벨 정하기: 모델 드롭다운에서 모델(하이쿠/소넷/오퍼스/페이블)과 이펏 레벨(로우~익스트라 하이)을 각각 고른다. 프로 플랜이면 소넷을 기본으로 쓰다 어려운 문제에서 오퍼스로 전환하고, 맥스 플랜이면 오퍼스를 기본으로 쓰다 막히면 페이블로 바꾼다. 이펏은 일상 작업엔 미디엄, 코딩·분석엔 하이, 에이전틱·멀티스텝 코딩엔 익스트라 하이를 쓴다.
  3. 맥락 덤핑과 비판적 되묻기로 프롬프트하기: 프롬프트 엔지니어링을 정교하게 다듬을 필요 없이, 관련 있어 보이는 맥락을 정리되지 않은 채로 그냥 다 넣는다. 어떤 맥락이 필요한지 모를 때는 클로드에게 필요한 정보를 먼저 질문하게 시키는 "맥락 인터뷰"를 활용한다. 첫 응답을 곧이곧대로 믿지 말고 매번 허점과 개선점을 되묻으며 협업자처럼 다룬다.
  4. 커넥터로 도구 연결하기: Customize → Connectors → Add에서 목록의 커넥터를 고르고 플러스 버튼을 눌러 계정 로그인으로 연결한다. 목록에 없는 서비스는 "Add custom connector"에서 이름과 URL을 넣어 직접 추가한다(예: 이미지 생성용 Higsfield).
  5. 프로젝트로 작업 공간 분리하기: 사이드 패널에서 새 프로젝트를 만들고, 커스텀 지침(맥락·톤·프로세스·요구사항)과 프로젝트 파일(브랜드 가이드·SOP·참고자료)을 등록한다. 프로젝트는 서로 격리되어 참조되지 않으며, 하루 한 번 자동으로 메모리가 갱신되어 매번 맥락을 재설명할 필요가 없어진다.
  6. 스킬로 반복 워크플로 패키징하기: 대화에서 원하는 결과가 나올 때까지 되묻고 다듬은 뒤, "이 과정을 스킬로 패키징해줘(예: weekly special)"라고 요청한다. 이후에는 해당 스킬을 이름으로 부르거나 문맥상 자동으로 호출해 같은 프로세스를 한 번에 재현할 수 있다.
  7. 코워크로 실제 업무 위임하기: 채팅과 달리 목표만 던지면 클로드가 스스로 계획과 체크리스트를 세우고, 필요하면 하위 에이전트에 작업을 나눠 맡긴 뒤 완성된 결과를 가져온다. 예약 작업(scheduled task) 기능으로 매주 특정 요일에 자동 실행되게 설정할 수도 있다.
  8. 클로드 코드로 실제 제품 만들기: 데스크톱 앱에서 폴더를 지정하고 원하는 것을 자연어로 설명한다. 처음이라면 플랜 모드로 전환해 실행 전에 계획을 먼저 검토받는 것을 권장한다.

06활용 시나리오

  1. 1인 마케터의 주간 프로모션 자동화: 프로젝트에 브랜드 문서·톤 가이드·판매 이력을 올려두고, 판매 데이터 분석 → 프로모션 문구 작성 → 이미지 생성(Higsfield 커넥터)까지 이어지는 과정을 "weekly special" 스킬로 만들어 매주 반복 실행한다.
  2. 비개발자의 사이드 프로젝트 제작: 코딩을 모르는 사람도 클로드 코드로 프리미어 프로 플러그인이나 모바일 앱 같은 실사용 도구를 직접 만들 수 있다. 화자 본인이 비개발자로서 여러 도구를 만든 사례를 든다.
  3. 업무별 프로젝트 분리 운영: 사업, 유튜브, 건강, 가족처럼 서로 무관한 영역을 별도 프로젝트로 나눠, 한 영역의 맥락이 다른 영역 답변에 섞이지 않게 관리한다.
  4. 커넥터 기반 자동 맥락 수집: Gmail로 고객 응대 톤과 진행 중인 프로젝트를 파악하고, 캘린더로 최신 일정을, 구글드라이브로 관련 파일을 자동으로 끌어와 별도 설명 없이 바로 작업을 시킨다.
  5. 예약 작업으로 정기 리포트 자동화: 코워크의 scheduled task 기능으로 매주 금요일 아침에 프로모션 문구와 이미지가 자동으로 준비되게 설정해, 출근 즉시 소셜 업로드만 하면 되게 만든다.

07현황 및 전망

화자는 지난 1년 사이 에이전틱 도구들이 비개발자도 쓸 수 있을 만큼 강력해지고 쉬워졌다고 평가하며, 지금 소개한 채팅 단계 기능만 제대로 써도 이미 사용자의 상위 90%에 든다고 말한다. 다만 이는 클로드가 할 수 있는 일의 일부에 불과하며, 다음 단계는 코워크와 클로드 코드로 넘어가는 것이라고 강조한다. 오퍼스 최신 버전이 워낙 강력해져 페이블을 거의 안 쓰게 됐다는 언급에서 보듯, 모델 세대가 바뀔 때마다 화자의 기본 선택도 달라지고 있어 이런 가이드는 주기적으로 갱신될 필요가 있다는 점이 시사된다. 화자는 영상 설명란에 프롬프트 100개 이상과 설치 가능한 스킬 12개를 담은 무료 자료도 제공한다고 밝힌다.
