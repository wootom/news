바이브코딩은 스캐폴딩과 도메인 스토리텔링으로 AI와 설계·구현을 나눠야 한다.

바이브코딩은 스캐폴딩을 먼저 정하고, AI에 도메인 맥락을 전달해 설계·구현을 맡기는 과정이다.

01핵심 개요

  • 발표자는 바이브코딩의 성공을 수익화가 아니라 개발적으로 흠없는 결과물을 만드는 일로 정의했다.
  • 첫 단계인 스캐폴딩에서 구현 방식, 기술 스택, 배포 인프라를 먼저 결정해야 한다고 설명했다.
  • 대부분 프로젝트는 배포와 업데이트가 간편한 웹이 적합하며, 명확한 앱 목적이 있을 때만 앱을 권했다.
  • 앱·웹·서버 코드를 TypeScript로 통일하고 Expo·Next.js·NestJS·PostgreSQL 조합을 제안했다.
  • AI에는 기획서를 직접 맡기기보다 사용자의 문제 상황을 인터뷰처럼 전달하는 도메인 스토리텔링을 권했다.

02핵심 주장 / 논점 구조

  • 바이브코딩의 목적은 업무 자동화, 포트폴리오, 수익화 등 사람마다 다르지만 이번 방송은 개발적 완성도에 집중했다.
  • 노베이스 사용자도 AI에게 코드 작성을 맡길 수 있지만, 무엇을 모르고 있는지 파악하는 일이 우선이라고 말했다.
  • 개발 과정은 코드베이스 뼈대를 만드는 스캐폴딩, 도메인을 설명하는 스토리텔링, 이후 구현으로 이어진다고 제시했다.
  • 코드 문법을 직접 알 필요는 적어졌지만, AI가 제안한 아키텍처와 인프라를 평가·토론할 수준의 이해는 필요하다고 봤다.

03스캐폴딩에서 먼저 정할 세 가지

  • 스캐폴딩은 코딩과 시스템 구축 전에 기본 뼈대와 디렉터리 구조를 만드는 작업으로 설명됐다.
  • 이 단계에서 구현 방식, 기술 스택, 대략적 인프라를 정하며, 잘못 정하면 이후 개발 단계가 어려워진다고 말했다.
  • 앱·웹·데스크톱 중 구현 방식을 먼저 판단해야 하며, 제품 특성상 SaaS인데 앱으로 만들었다가 엎는 사례를 언급했다.
  • 스캐폴딩 설계가 끝난 뒤 AI에게 모노레포 구성을 요청하고, 생성된 구조에 피드백하는 방식이 제시됐다.

04웹·앱·데스크톱 구현 방식의 선택 기준

  • 대부분의 프로젝트는 웹으로 만들어도 되며, 웹은 스토어 심사 없이 배포할 수 있어 앱보다 업데이트가 쉽다고 설명했다.
  • 사용자가 자주 접속하는 서비스는 앱이 의미 있을 수 있으나, 데스크톱에서도 써야 한다면 웹이 더 적합하다고 말했다.
  • 앱은 재배포, 스토어 심사, 사용자 업데이트를 고려해야 하고 API 스키마 변경도 까다로워진다고 언급했다.
  • 데스크톱 프로그램은 배포와 개발자 서명, 운영체제별 차이를 고려해야 해 추천하지 않는다고 밝혔다.

05TypeScript 중심의 권장 기술 스택

  • 발표자는 앱·웹·서버의 코드를 TypeScript로 통일하면 범용성이 높고 선택이 크게 어긋나지 않는다고 주장했다.
  • 앱에는 Expo를, 웹과 어드민에는 Next.js를, 서버에는 NestJS를 제안하며 Flutter·Spring·FastAPI는 기본 조합에서 제외했다.
  • 데이터베이스는 PostgreSQL을 권했고, 이미지·영상 등 자산을 위한 스토리지도 별도로 필요하다고 설명했다.
  • 메인 웹·어드민·서버는 분리하고 모노레포로 관리하는 구성을 선호했으며, Next.js 단일 풀스택 구조는 코드베이스가 커질 수 있다고 봤다.

06인프라 비용과 Supabase 결합도 관리

  • 어드민 배포에는 Vercel, 서버에는 월 5달러부터인 Railway, 데이터베이스에는 Supabase를 권장했다.
  • Neon은 데이터베이스 활성 시간 단위로 과금돼 사용 시간이 집중된 서비스에는 가능하지만, 고르게 쓰면 과금이 커질 수 있다고 말했다.
  • Supabase는 데이터베이스 컨테이너로만 쓰고 Storage·Auth·RLS 등에 강하게 의존하지 않는 편을 권했다.
  • 스토리지는 Cloudflare R2를 제안했으며, Supabase Storage에 결합하면 다른 서비스로 이전할 때 코드 변경이 커질 수 있다고 설명했다.
  • Vercel은 월 100달러 수준까지 편의성 측면에서 쓸 만하지만, Supabase가 유료 전환되면 AWS나 GCP 이전을 고려하라고 말했다.

07도메인 스토리텔링으로 AI에 맥락 전달하기

  • 스캐폴딩 후 구현을 시작할 때 AI는 사용자가 해결하려는 문제와 맥락을 모르기 때문에 추가 설명이 필요하다고 했다.
  • 비전문가가 완성된 PRD나 기획서를 직접 쓰려 하기보다, AI가 인터뷰하도록 만들어 현재 상황과 페인 포인트를 설명하는 방식을 제시했다.
  • 사용자는 왜 기능이 필요한지, 일상에서 어떤 문제가 있었는지를 전달하고 기획 문서 작성은 AI가 맡는 구조를 권했다.
  • 도메인 스토리텔링을 잘하면 AI가 사용자의 상황을 정확히 이해하고 큰 모듈·객체 설계도 러프하게 완성될 수 있다고 설명했다.
  • 서버와 클라이언트를 분리하고 외부 제공자를 서버 뒤에 두는 스캐폴딩 구조가 보안 문제를 줄이는 기본이라고 덧붙였다.

08용어 사전

용어뜻
스캐폴딩구현 전에 코드베이스의 기본 뼈대, 디렉터리 구조, 기술 스택과 인프라를 정하는 단계다.
도메인 스토리텔링AI가 사용자의 문제 상황과 페인 포인트를 인터뷰처럼 이해하도록 맥락을 전달하는 방식이다.
모노레포메인 웹·어드민·서버처럼 분리된 애플리케이션을 하나의 저장소에서 관리하는 구성이다.
Supabase영상에서는 PostgreSQL 데이터베이스 컨테이너로 활용하되 Storage·Auth·RLS 의존은 줄이라고 제안한 서비스다.
RLSSupabase에 강하게 결합될 수 있어, 다른 인프라로 이전하기 어려워질 수 있다고 언급된 설정 방식이다.
